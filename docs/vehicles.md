# 通用载具

`VehicleModule` 将展示实体组保存为模型蓝图；实例的物理状态独立于展示实体，不使用矿车物理。支持汽车、动力船和固定翼飞机。由 `Mik` 启停，停服时先保存实例，再移除临时模型、座位和点击实体。

## 命令结构

`/vehicle` 使用 Paper 的 `LifecycleEvents.COMMANDS` 注册 Brigadier 子命令树，由 `VehicleCommands` 和 `VehicleModelCommands` 分别管理驾驶/实例操作与模型编辑；不再把整条输入交给 `greedyString` 手动分发。已有命令路径保留。

| 权限 | 命令 |
| --- | --- |
| `mik.vehicle.use` | `list`、`ride`、`passenger`、`leave`、`inspect`、`engine`、`mode`、`gear`、`throttle`、`hud`、`dashboard`、`fuel`、`repair`、`access`、`remove` |
| `mik.vehicle.admin` | `origin`、`select`、`capture`、`spawn`、`reload`、`model` 及其全部子命令 |

`/vehicle help` 按权限显示驾驶与管理帮助，`/vehicle model help` 显示模型编辑帮助。Tab 按当前层级补全子命令、模式、类型、属性、模型 ID 和可访问的载具 UUID；展示实体 UUID 只建议附近可选择的实体。权限在节点和执行入口均检查；模型编辑仍检查当前草稿和会话，载具操作仍检查访问权、所有权与驾驶位。

UUID、整数、数值、布尔值、生成位置和方块状态使用类型化参数；缺少参数、多余参数或超出参数范围会由命令树拒绝，不执行操作。选区半径满足 `0 < radius ≤ 16`，组件编号从 0 开始。只有展示文字和可变长度的齿比列表使用剩余字符串参数，不用于分发子命令。生成坐标支持 Paper 原生的绝对、`~` 相对和 `^` 局部坐标；模型内部位置/旋转/尺寸仍是局部数值，不解析 `~` 或 `^`。控制台执行玩家操作会收到明确提示，失败返回 0 而非成功。

## 制作和生成

需要 `mik.vehicle.admin`，默认 OP。

1. 搭好 BlockDisplay、ItemDisplay、TextDisplay 模型。
2. 站在希望使用的模型原点，水平面向车头，执行 `/vehicle origin`。局部 +Z 是前方、+Y 是上方；原点不是重心。
3. `/vehicle select radius 8` 将周围展示实体加入选择。也可以 `/vehicle select <实体 UUID>` 逐个切换选择。`/vehicle select clear` 清空选择和原点。
4. `/vehicle capture sedan car` 保存汽车蓝图；船使用 `boat`，固定翼飞机使用 `plane`。捕获只复制数据，不移除原模型。原始矩阵、物品显示模式、文字、背景、亮度等被保存。
5. `/vehicle spawn sedan` 在前方生成实例，或者 `/vehicle spawn sedan x y z` 指定模型原点的世界坐标。实体 UUID 与载具实例 UUID 不同；生成成功返回实例 UUID。
6. 右击载具上车，或 `/vehicle ride [载具 UUID]` 进入驾驶位；`/vehicle passenger [载具 UUID]` 进入乘客位。

捕获要求 1–128 个展示实体，至少一个方块或物品展示实体。不能选择已经由载具模块管理的实体或编辑器预览。自动包围盒只是制作起点：方块按单位方块、物品按保守的单位盒估计，文字不参与估计。用游戏内编辑器校正物理碰撞体和座位。

## 游戏内模型管理

执行 `/vehicle model` 打开空间模型库，选择模型后可以编辑、复制或删除；新建表单输入模型 ID 和 `car`、`boat`、`plane` 类型。编辑器分为展示组件、座位与出口、碰撞盒、支撑点、物理/发动机参数和现场工具六页。组件列表点击后进入独立操作页，位置和出口有专门的现场取点与轴向微调页；旋转、缩放、动画和属性仍可通过原生输入表单配置，不需要编辑 YAML。操作名称和参数字段使用下面的稳定标识符。

### 现场取点与微调

开始草稿时固定模型原点及车头方向，并自动开启个人预览。走动或转头不会改变坐标系；`here` 读取的是**玩家脚下位置**，不是眼睛位置，自动换算为模型局部坐标；`look` 则读取视线命中的世界方块或个人预览表面。如果需要把整个预览移到新的制作位置，在「现场编辑工具」页选择「将预览原点放在脚下」，或执行 `/vehicle model anchor`；此时玩家的水平朝向作为车头，草稿内部坐标不变，不移动原始展示实体或已生成的载具。

- **座位**：走到希望的驾驶位或乘客位，在座位页选择「在脚下添加驾驶/乘客座位」。已有座位进入「位置 / 轴向微调」后可使用当前位置；「出口位置 / 轴向微调」单独设置下车点，不会随座位修改被覆盖。
- **展示组件、支撑点和碰撞盒中心**：组件操作页进入位置微调页，选择「使用我当前的脚下位置」。碰撞盒只移动中心，保留原有尺寸。支撑点页也可以直接在脚下新增采样点；现场工具页可以将重心设置在脚下或视线命中处。
- **先选中，再走动**：选中组件或进入出口微调页，关闭菜单，走到目标位置，执行 `/vehicle model here` 将目标设置在那里。重新打开 `/vehicle model` 会恢复所在编辑页。目标只能处于同一世界、距离固定原点不超过 32 格；组件自身仍受 24 格范围限制。删除以及改变组件数量的撤销/重做会取消快捷取点目标，须重新选择，避免编号移位后误改其他组件；普通位置撤销/重做保持所在编辑页。
- **不用走过去的视线取点**：位置页选择「视线放置」会先关闭菜单，再瞄准目标表面、用主手右击确认，成功后回到原编辑页；潜行右击取消。这样不会误取点击菜单按钮时的瞄准方向，待放置的表面有黄色光标。工具 30 秒后过期，草稿修改、撤销/重做、保存、传送或重新打开菜单也会取消；首个开启工具的点击不计为确认。没有命中则保留工具供重新瞄准，不猜一个空中坐标。也可以在关闭菜单后直接执行 `/vehicle model look`，以及 `seat exit 0 look`、`part position 0 look`、`support add look`、`collider position 0 look`，这些命令立即取当前视线。现场工具页的视线重心和碰撞盒页的视线角点按钮使用相同的右击确认流程。射线只考虑世界方块和自己的预览，并遵守遮挡；表面位置不是安全下车点保证，出口仍须自行放在可站立区域。
- **局部网格吸附**：默认关闭，位置页按钮或 `/vehicle model snap [on|off]` 切换。开启后，脚下/视线采样按当前微调步长吸附到模型局部 X/Y/Z 网格，旋转模型也能对齐。手动输入、相对移动不强制吸附；界面只简化显示至三位小数，保存坐标不截断。
- **微调**：位置页提供局部 X/Y/Z 正负方向按钮，步长在 `0.1`、`0.25`、`1` 格之间切换；也可以手动输入绝对局部坐标。修改立即同步预览，支持撤销；位置编辑保留组件旋转、缩放和其他展示属性。
- **两点建碰撞盒**：在盒子的第一角执行 `/vehicle model collider corner1`，走到空间对角（包括高度）后执行 `/vehicle model collider corner2`；也可用两个命令的 `look` 版本远程取表面点。菜单有对应按钮。标记第一角后，橙色草图随脚下位置更新；第一角使用 `look` 时，草图跟随当前视线命中处，尚未写入模型。无厚度或越界时不显示合法草图，并在脚下采样模式以红点提示无效对角；提交失败保留第一角供重试。`collider cancel` 单独取消草图。盒子按模型局部轴向建立，不是世界轴向；改变预览原点或结束草稿会清除第一角。
- **看向组件选中**：开启预览后，看向方块或物品组件，执行 `/vehicle model pick` 打开该组件操作页。不会选中墙后的组件或其他玩家的预览；文字组件仍通过列表选择。
- **旋转、缩放与尺寸**：组件旋转／缩放页提供局部三轴正负调整、步长切换和手动输入；旋转步长为 `1°/5°/15°`，缩放因子为 `1.01/1.05/1.25`，减小使用倒数，也可统一缩放。碰撞盒尺寸页按完整宽高长编辑，以固定中心向两侧调整；命令为 `/vehicle model collider size <索引> <宽> <高> <长>`。
- **复制和移除**：部件、座位、碰撞盒、支撑点操作页可复制并自动选中副本；命令为 `/vehicle model <part|seat|collider|support> copy <索引>`。复制驾驶位会转为乘客位，避免出现两个驾驶位。菜单移除需确认，并检查编辑版本未变化；复制、移除均可撤销。工具页的视线选择也先关闭菜单，再右击确认，避免取到点击按钮时的视线。

预览标记：原点轴为红 X、绿 Y、蓝 Z；绿色为驾驶位、蓝色为乘客位、橙色为出口/第一角、黄色为支撑点、紫色为重心。白色线框显示当前碰撞盒（未选择时显示第一个），白色点标出当前编辑的位置。标记只发给编辑者，不创建可乘坐实体。

例如，不需要计算坐标就可以设置座位与下车点：

```text
/vehicle model edit sedan
# 走到座位位置
/vehicle model seat position 0 here
# 走到安全的下车位置
/vehicle model seat exit 0 here
/vehicle model save
```

### 导入 Axiom 展示实体 Group

支持的是 **Axiom 展示实体编辑界面的 Grouping → Group with nearby in range 创建的 Group**，不是要求你另行用原版命令把展示挂载起来。已核对本机 Axiom 6.0.5 for MC26.2：`EditDisplayEntityScreen` 的分组操作通过 `PassengerManipulation.ADD_LIST` 建立父子关系，并把成员的位置偏移及原 yaw/pitch 写入展示变换。分组后多个展示可能共享同一个实体位置，但视觉内容仍有各自偏移。导入会读取这一已落到服务器世界中的完整 Group，包含根展示以及嵌套子组，保留各成员当前可见的变换，不再次乘父展示矩阵。

因此，导入前只需要在 Axiom 中正常完成 Group 操作；**不需要拆组、不需要转换标签，也不需要重新挂载**。导入后 Axiom 原 Group 保持不变，载具使用独立模型快照。这个实现也兼容相同结构的普通展示实体树；读取已存在的结构本身不依赖 AxiomPaper 的 Java API。仅临时多选、尚未执行 Group 的实体不是一个 Group，可用显式或半径选择后 `part add selected`。

推荐先看向分组中的方块或物品展示，再执行：

```text
/vehicle select clear
/vehicle select group
/vehicle select info
/vehicle model import sedan car
/vehicle model preview
/vehicle model save
/vehicle spawn sedan
```

`select group [实体UUID]` 从任意成员追溯根实体，再遍历整个连接树；这一步**替换**之前的选择，不把周围其他模型混进来。选择命令未指定 UUID 时重新按视线查找方块/物品展示；导入命令未指定 UUID 时先使用当前已选分组，没有选组才按视线查找。瞄准检测使用展示变换后的实际几何范围，不依赖经常为零的原版实体点击框，并受方块遮挡限制。文字展示、特殊 billboard 和不容易瞄准的载体建议指定 UUID。所有导入都是只读快照：不删除源实体、不拆散源组，不修改 Axiom 的原始模型。

`model import <新id> <car|boat|plane> [实体UUID]` 创建完整但尚未保存的草稿，导入展示变换、方块状态、物品数据、文字与展示属性，并按几何范围生成默认碰撞盒、座位及支撑点。没有设置 `/vehicle origin` 时，以根实体的位置和 yaw 为原点；显式原点优先。每个展示按当前世界位姿扁平化，不能再次叠加父展示矩阵。复制后的草稿独立于源组，源组后续移动或拆分不会自动改写已导入模型。

模型库提供「导入 Axiom 展示组」表单，输入模型 ID、类型及可选 UUID。建议先用 `select group` 选好源组，再打开菜单，避免输入表单期间视线变化。已有草稿必须先保存或放弃，不会被导入覆盖。现有草稿的「展示组件」页可以「添加 Axiom 展示组」，也可用 `part add group [实体UUID]`；追加组件以当前草稿预览原点定位，不擅自重置碰撞盒或驾驶位，需要时再执行 `collider auto` 并调整物理参数。

允许忽略真正的不可见载体：Marker、Interaction、不可见 ArmorStand；可见 ArmorStand、玩家、动物等不是展示组件，出现时拒绝整组，而不是悄悄丢弃。最多 128 个展示实体、256 个总成员，所有成员须在当前世界且距离操作者不超过 32 格。选定分组后，如果增删、重新挂载或更换根实体，后续捕获会要求重新选择；不导入不完整分组。运行中的载具和私有预览不能作为源组，捕获原点及各展示实体都经过载具使用事件检查。手动逐个选择或半径选择会转为普通选择，清除分组结构绑定；`select clear` 同时清除显式原点。

运行中的载具实体与私有预览通过独立 Axiom gizmo scope 隐藏编辑控制柄，与菜单、AFK 等模块的排除集合合并，不互相覆盖。安装兼容的 AxiomPaper 时，另外接入其公开的可取消实体修改/删除事件，拒绝直接修改受管实体；兼容 API 不存在时记录警告并退回 gizmo 排除，导入功能仍可使用。这是编辑防误操作，不替代服务器权限或区域保护。实例卸载、预览结束、玩家退出与模块关闭时清理各自排除集合。

模型编辑采用独立草稿。新建模型提供对应类型的物理预设，但没有展示组件；可以在游戏内添加方块、主手物品、文字，或者导入已选择的展示实体。支持暂时不完整的配置，例如先删除驾驶位再添加新驾驶位；只有保存时才要求完整有效的模型。

示例：从现有展示实体制作并配置汽车，不修改配置文件。

```text
/vehicle origin
/vehicle select radius 8
/vehicle model create sedan car
/vehicle model part add selected
/vehicle model collider auto
/vehicle model seat position 0 0 0.8 0
/vehicle model seat exit 0 2 0.5 0
/vehicle model set mass 1500
/vehicle model set engine.ratios 3.8 2.4 1.6 1.1 0.8
/vehicle model preview
/vehicle model save
/vehicle spawn sedan
```

也可以 `/vehicle model part add block minecraft:stone` 从空模型开始。保存后的模型通过 `/vehicle model edit sedan` 再次编辑；`/vehicle model clone sedan sedan_sport` 创建副本草稿，不立即保存。

| 命令（省略 `/vehicle model`） | 用途 |
| --- | --- |
| `list`, `info [id]` | 模型列表；查看草稿或已有模型各组件的编号与配置 |
| `create <id> <car\|boat\|plane>`, `edit <id>`, `clone <id> <newid>` | 新建、编辑、复制草稿 |
| `import <newid> <car\|boat\|plane> [实体UUID]` | 将真实连接的展示分组复制为新模型草稿；省略 UUID 时优先使用已选分组 |
| `set <field> <value...>` | 修改下方表格中的物理、发动机、向量参数；`kind` 修改类型，`engine.ratios` 输入递减档比 |
| `part add selected\|block <blockdata>\|item\|text <text...>` | 导入选择；添加方块、主手物品或纯文本展示组件 |
| `part add group [实体UUID]` | 追加整个展示分组，保留当前草稿的原点与物理配置 |
| `part position <index> <x y z>` | 设置组件绝对局部位置，保留原旋转和缩放 |
| `part rotate <index> <pitch yaw roll>`, `part scale <index> <x y z>` | 相对旋转（度）或相对缩放（正数），不是覆盖已有变换 |
| `part animation <index> <BODY\|WHEEL\|FRONT_WHEEL\|PROPELLER\|RUDDER>` | 指定组件动画 |
| `part block <index> <blockdata>`, `part item <index>`, `part text <index> <text...>` | 替换展示类型和内容，保留变换；`item` 取当前主手物品 |
| `part option <index> <property> <value>` | 配置展示属性，见下文 |
| `seat add <x y z> <driver\|passenger>` | 添加座位；设置为驾驶位时自动取消其他驾驶位标志 |
| `seat position\|exit <index> <x y z>`, `seat driver <index>` | 配置座位、退出点和唯一驾驶位 |
| `seat add here <driver\|passenger>`, `seat position\|exit <index> here` | 从当前脚下位置添加座位、设置座位或出口 |
| `collider add <x y z halfX halfY halfZ>`, `collider set <index> <x y z halfX halfY halfZ>` | 添加、替换碰撞盒；尺寸均为半尺寸 |
| `collider auto` | 从当前方块/物品组件重建一个包围盒，替换原复合碰撞体，可撤销 |
| `collider corner1`, `collider corner2` | 在脚下取两个空间对角，添加局部轴向碰撞盒 |
| `collider position <index> <x y z\|here>` | 移动碰撞盒中心，保持半尺寸不变 |
| `support add <x y z>`, `support set <index> <x y z>` | 添加、移动接地/浮力采样点 |
| `support add here`, `support set <index> here`, `part position <index> here` | 使用当前脚下位置 |
| `part\|seat\|collider\|support move <index> <dx dy dz>` | 按局部轴向相对移动组件，座位移动不改出口 |
| `set center-of-mass here`, `anchor`, `pick`, `here` | 现场设置重心、移动预览原点、视线选中组件、设置已选位置 |
| `look`, `part position\|seat position\|seat exit\|collider position\|support set <index> look` | 以视线命中的表面设置已选位置或指定组件位置 |
| `seat add look <driver\|passenger>`, `support add look`, `set center-of-mass look` | 从视线表面添加座位、支撑点或设置重心 |
| `snap [on\|off]` | 开关局部网格吸附，无参数则切换；网格大小使用当前微调步长 |
| `collider corner1\|corner2 look`, `collider cancel` | 视线取碰撞盒对角，或取消未提交草图 |
| `redo`, `check`, `apply` | 重做、结构参数检查、保存并继续编辑 |
| `part\|seat\|collider\|support remove <index>` | 删除组件，其后编号顺次前移，可撤销 |
| `preview [off]`, `undo`, `save`, `cancel`, `delete <id>` | 私有预览、撤销、校验保存、放弃草稿、删除已有模型 |

所有编号从 **0** 开始。坐标均相对于模型原点，局部 +Z 向前；`rotate` 的正 yaw 与游戏朝向约定一致。向量参数如 `center-of-mass` 和 `inertia` 输入三个数字。`engine.ratios` 可用空格或逗号分隔，须正数、严格递减，最多 12 档。

`/vehicle capture` 与 `model import` 都只创建新 ID，不覆盖已有模型；更新已有模型请用 `model edit <id>` 修改并 `model save`。

`part option` 支持 `billboard`（`FIXED`/`VERTICAL`/`HORIZONTAL`/`CENTER`）、`item-transform`（原版物品展示模式）、`alignment`（`LEFT`/`CENTER`/`RIGHT`）、`block-light`/`sky-light`（-1 或 0–15；要覆盖亮度需同时设置两个值）、`background`（有符号 ARGB 整数，如黑色 `-16777216`）、`line-width`（1–2048）、`opacity`（0–255，亦接受原版有符号 byte）、`shadow`/`see-through`（`true`/`false`）。捕获组件保留原始富文本；用 `part text` 替换后是纯文本。

保存先验证结构、数值、展示数据以及现有实例兼容性，再更新文件和受影响的实例，不全局重载。不相关模型的载具可以继续驾驶；使用当前模型的载具必须停止移动/旋转、关闭发动机且无人乘坐。不能把燃料容量或档数缩小到现有实例无法容纳的值，也不能使新碰撞体与已加载世界中的方块或其他载具重叠。保存失败保留原配置与草稿。`save` 成功后结束草稿；主页「保存并继续编辑」或 `apply` 使用同样的完整保存检查，但保留草稿、固定原点、选中位置、个人预览和历史，同时更新版本基准，方便连续调整。保存后的撤销修改仍需再次保存才会落盘。

现场工具页的「检查结构与参数」或 `check` 只做模型结构与数值校验，不落盘、不替代保存时的展示数据检查、实例兼容性与世界碰撞检查。

多人编辑使用版本检查：其他管理员保存、删除或重载后，旧草稿不能覆盖新模型；检测到文件被外部修改时，先 `/vehicle reload`，再放弃旧草稿并重新编辑。输入表单绑定当前会话及草稿修订号；修改、撤销、退出服务器或重启模块后，旧表单不能误改新的配置。删除模型、放弃未保存草稿均需确认；仍有实例引用的模型不能删除，包括未激活的实例。ID 不直接重命名，采用复制新 ID、移除旧实例、删除旧模型的流程。

预览只有自己可见，不运行驾驶动画或物理，不生成座位和点击实体，不自动加载区块；模型尚未添加展示组件时也能查看物理位置标记。所有草稿的原点均在开始时固定：分组导入使用导入原点，其他草稿优先使用当时的 `/vehicle origin`，其次使用已选分组根实体，再次使用当时的玩家位置；只有显式 `model anchor` 才会移动预览原点。已选展示实体与分组追加都使用这个固定原点转换，避免走动后组件错位。编辑和撤销会同步预览并刷新五分钟有效期；纯位置变换原位更新，不反复生成实体。停止编辑五分钟后、传送、离开 32 格、区块/世界卸载、保存/放弃草稿、退出服务器或关闭模块时清除。预览失败不丢弃草稿，可使用 `model preview` 重试或 `model preview off` 关闭。每个模型最多 128 个组件，全服预览最多 512 个展示实体。

每位管理员同时只有一份草稿，全服最多 32 份；撤销与重做共享最多 20 个历史快照和 8 MiB 总预算，单份模型也限制 8 MiB。撤销后做新的有效修改会清空重做分支；失败或无变化的操作不会清空它。位置页也有撤销/重做按钮，没有对应历史时禁用。个人取点与微调只重绘自己的编辑菜单，不刷新其他编辑者；展示组件快照按草稿修订缓存，避免持续预览时反复解码。关闭菜单不丢弃草稿，但**退出服务器或关闭模块会丢弃未保存草稿**，请先保存。

## 驾驶与 HUD

所有驾驶操作需要 `mik.vehicle.use`，默认所有玩家。乘客不接管快捷栏、换手或动力输入；驾驶位接管滚轮和換手动作，下车恢复。

| 输入 | 汽车 | 动力船 | 固定翼飞机 |
| --- | --- | --- | --- |
| W | 油门，包括挂 R 后的倒车油门 | 提高推进指令 | 压低机头 |
| S | 制动，不自动挂倒档 | 降低推进指令，停稳后可进入倒推 | 抬高机头 |
| A/D | 转向 | 船舵 | 滚转；地面滑跑时也控制偏航 |
| 跳跃 | 手刹并切断油门 | 无附加动作 | 地面轮刹 |
| 滚轮向上/下 | 手动模式升/降档 | 推进指令增/减 5% | 油门增/减 5% |
| 换手 | 自动/手动辅助档切换 | 航行稳定辅助切换 | 自动回平辅助切换 |
| 潜行 | 退出 | 退出 | 离机，不提供降落伞 |

`/vehicle engine` 开关发动机。进入驾驶位时，有燃料且未完全损坏的载具自动启动；汽车从 P 请求切入 D。退出驾驶位、死亡、断线或传送会断开驾驶控制并关闭发动机。车仍然受惯性、重力及接触力影响；船保留漂移，飞机继续滑翔/下落。

HUD 分为持续显示的屏幕读数和可点击的驾驶控制台。两条独立 BossBar 分别显示驾驶数据、燃料/车况/告警；汽车第一条的进度表示 RPM，接近限转时变红，船和飞机表示推进/油门。不持续占用 ActionBar。告警采用当前语言显示，包含燃料耗尽、低燃料、严重损坏、碰撞、失速、禁止方向切换、换挡中和超转速降挡等。

汽车进入驾驶位时自动打开控制台；也可以 `/vehicle dashboard` 打开。控制台只由当前驾驶员操作，以虚拟实体呈现，不创建世界内的真实仪表实体。面板随玩家/载具平移，保留打开时的水平方向，不追随鼠标转动，因此可以瞄准按钮；转弯后需要调整布局时点击「重新定位面板」或重新执行打开命令。W/S、A/D、空格、滚轮及换手驾驶输入保持原有行为。

控制台会同时避让方块和当前玩家可见的方块／物品展示模型，不依赖展示实体的空碰撞盒。检测覆盖按钮的整块区域和图标深度；模型遮挡时，整页沿眼睛方向收近并同比缩小，保持屏幕上的布局与角度大小，点击区域同步更新。行驶时当 tick 重算，静止时每四 tick 检查移动的模型，空出空间后逐步恢复。不会移动原模型、隐藏车辆或把其他玩家的私有预览当作障碍。座位应保证眼睛不在不透明模型内部；资源包物品模型使用保守包络，仍需实际客户端验证。

| 页面 | 读数和操作 |
| --- | --- |
| 驾驶 | 速度与安全上限、转速与限转、实际档位/目标档位、驾驶模式、油门、制动、转向、驻车/手刹、燃料、车况、乘员数量和告警；P/R/N/D、升降挡、模式切换、发动机开关 |
| 变速箱 | 未换挡时只显示当前档位，换挡时改为实际→目标档位、进度与剩余时间；P/R/N/D 与模式由按钮选中状态表示，前进档数由档位按钮展示；手动模式直接选择各前进档 |
| 车辆详情 | 燃料量/容量、当前消耗率、估算续航时间与里程、车况、乘员/座位数、模型原点坐标、航向、接地/浮力支撑和告警 |

瞄准按钮后左击操作。不满足条件的按钮显示禁用原因；例如自动挡下禁用手动档位按钮，换挡中禁用重复换挡，行驶中禁用 P/R。所有操作仍会在服务端重新检查当前驾驶位、载具访问权限、档数、换挡延迟和降挡超转速，旧面板不能控制新乘坐的另一辆车。模式切换保留 P/R/N/D、实际档位及正在进行的换挡，不会因为切换自动挡而释放驻车。

模式切换按钮标注切换后的模式。成功操作直接更新读数与按钮，不重复弹出通用成功提示；失败仍显示具体原因。发动机状态由开关按钮表示，面板只额外显示告警，换挡页不再重复“正在换挡”。估算说明见下文，不常驻占用仪表空间。

```text
/vehicle dashboard drive
/vehicle dashboard gearbox
/vehicle dashboard details
/vehicle dashboard off
/vehicle hud off
/vehicle hud on
```

`dashboard off` 或控制台关闭按钮只关闭交互面板，BossBar 继续显示。`hud [on|off]` 控制读数与控制台，无参数切换显示；关闭 HUD 后不会在同次设置下自动打开控制台。下车、死亡、断线、载具卸载或模块关闭时清理自己的面板及 BossBar，不影响其他模块的显示。

船和飞机可手动打开控制台；显示相应状态、垂直运动数据，并提供推进/油门增减、稳定辅助与发动机操作，不显示汽车选档杆和档位按钮。控制台必须使用空间交互呈现，不能降级为会占用驾驶输入的原生表单。

燃料单位是本模块定义的游戏单位，不声称是现实升数。消耗率与物理更新使用同一公式；续航仅按当前速度、油门和消耗率估算，不预测路线、坡度或未来操作。发动机关闭时不报告虚假的无限续航，静止时不报告可行驶里程，无法估算时显示 `—`。没有模拟水温、油温、胎压等参数，因此不编造这些仪表读数。

内部单位为方块、秒及游戏尺度质量。显示约定一方块相当于一米，汽车/飞机转为 km/h，船转为节；飞机高度为世界 Y，不是距地高度。当前无风，因此空速与地速相同。`VehicleHud.Frame` 是只读快照，后续资源包 HUD 可以替换呈现层，不需要访问可变物理状态。

船的航向使用罗盘约定：北 0°、东 90°、南 180°、西 270°。

## 变速箱

汽车提供自动档和手动辅助档；手动模式由玩家决定档位，系统自动完成离合，不要求额外客户端按键。

- `/vehicle mode` 切换模式，也可以 `mode automatic`、`mode manual` 明确选择；不重置选档杆、实际档位或正在进行的换挡。
- `/vehicle gear P|R|N|D` 选择档位。
- `/vehicle gear up|down` 或滚轮在手动模式逐档换档。
- `/vehicle gear 1` 等数字直接请求手动档，`0` 是空档，`-1` 是倒档。
- 换档有动力中断和接合延迟，HUD 显示实际档位与目标档位。
- 速度超过 0.5 方块/秒时不能挂 P 或切换前后行驶方向。
- 预计降档转速超过限转保护范围时拒绝换档，并显示本地化超转速提示。
- 自动升降档具有阈值滞回和最短档位保持时间；手动模式不自动升档。

W 与 S 同按时相互抵消，不给油。手刹优先于油门。腾空的汽车不能产生地面牵引或轮胎转向力。

## 所有权与维护

实例默认私有，所有者和管理员可以使用。`/vehicle access public` 开放驾驶和乘坐，`private` 收回开放；只有所有者或管理员可以更改开放状态、维修、加油或移除。

- `/vehicle list` 查看模型及可访问实例。
- `/vehicle inspect [uuid]` 查看速度、档位、RPM、燃料、车况及激活状态。
- 关闭发动机并停稳后，手持煤/木炭执行 `/vehicle fuel`，消耗一个物品，补充最多 10 燃料单位。
- 同样手持铁锭执行 `/vehicle repair`，补充最多 10 车况。
- `/vehicle remove [uuid]` 移除停稳、无乘客的实例，不删除模型蓝图。

无 UUID 的命令优先使用当前乘坐载具，否则使用 32 方块内最近的可访问实例。移除和服务操作保存失败时回滚状态，不消耗物品。

## 配置与模型编辑

`plugins/mik/vehicles.yml` 管理总预算：

```yaml
maximum-active: 16
maximum-instances: 256
maximum-per-owner: 16
activation-distance: 80
disabled-worlds: []
```

设置在启动时读取。实例上限最多 512，激活上限最多 64；模型最多 256。大量模型零件会增加实体同步和客户端渲染开销，应先测量再增加预算。

蓝图保存在 `plugins/mik/vehicles/definitions/<id>.yml`。可通过游戏内参数/组件表单或 `model set` 修改以下字段；也支持停机后维护文件并执行重载：

| 字段 | 用途 |
| --- | --- |
| `mass`, `center-of-mass`, `inertia` | 质量、相对模型原点的重心、局部三个轴的惯量 |
| `colliders.<编号>.center/half-size` | 复合盒碰撞体；尺寸是半尺寸，不是全尺寸 |
| `seats.<编号>.position/exit/driver` | 座位位置、退出点、是否驾驶位；必须恰好一个驾驶位 |
| `supports.<编号>` | 车轮/起落架接地点，船的浮力采样点 |
| `support-length`, `grip` | 悬挂支撑长度、地面抓地系数 |
| `engine.*` | 扭矩、怠速、限转、惯量、轮径、主减速比、倒档及前进档比、换档时间 |
| `buoyancy` | 船体采样点的浸水浮力系数 |
| `wing-area`, `lift` | 固定翼面积与升力系数限值 |
| `fuel.capacity/consumption` | 容量与工作消耗率；怠速也消耗燃料 |
| `maximum-speed` | 游戏尺度安全速度上限 |
| `parts.<编号>.matrix` | 列主序的 4×4 仿射局部矩阵，保留缩放和旋转 |
| `parts.<编号>.animation` | `BODY`, `FRONT_WHEEL`, `WHEEL`, `PROPELLER`, `RUDDER` |

零件动画绕零件自身的局部原点旋转；轮胎、舵和螺旋桨需要在模型制作时设置合适的旋转中心。预设只提供车身，不自动猜测机械零件。

飞机可用机身、左右机翼等多个盒体；船的浮力点与实体碰撞体分别配置。定义支持最多 16 个碰撞盒、16 个座位和 16 个支撑点。所有尺寸、矩阵及物理参数经过有限数值和大小限制校验。

停稳全部载具，关闭全部发动机，让所有乘客下车后执行 `/vehicle reload`。重载先读取并校验全部蓝图和现有实例，再整体替换。失败保留原运行配置。不能删除仍有实例引用的定义，也不能使实例当前燃料/档位超过新定义限制。

## 碰撞、区块和保存

使用旋转盒的分离轴扫掠检测，世界障碍来自方块的真实碰撞形状；复合盒可检测机翼而不仅是载具原点。速度与角速度影响内部子步数，最终位姿每服务器 tick 同步一次。载具之间按复合盒阻挡；当前不处理乘客之外的生物撞击伤害。

座位使用隐藏的标记盔甲架，`VehicleSeatMover` 将 Paper 26.3 的原生位置同步隔离在一个适配器内。持续移动不调用 Bukkit 玩家传送，不改变玩家自由观察的朝向，也不会把载具运动记为玩家主动传送。升级服务器基线时应重新验证此适配器。

不会主动加载区块。未加载区块、世界边界和高度边界作为障碍处理。附近玩家触发实例激活，远离玩家且已静止、关闭发动机的地面载具休眠。空中实例在区块仍加载时继续计算；区块卸载时保存逻辑状态并撤掉实体，再加载时保留动量恢复，发动机不自动重启。无观察者载具受同一激活预算约束，不无限加载世界。

实例统一保存在 `plugins/mik/vehicles/instances.yml`，每 30 秒检查点保存，生成、维护、权限更改和删除立即保存。文件通过同目录临时文件和原子替换写入；不支持原子移动的文件系统使用替换移动。YAML 损坏、未知版本或缺失定义会阻止模块启动，不用空集合覆盖现有数据。

展示、点击和座位实体不持久化。重新启动及区块载入时清理遗留的带标记实体，再按实例状态生成，避免重复载具。

## 保护插件接入

`VehicleUseEvent` 是可取消事件，提供玩家、操作、实例 UUID（捕获时为空）和位置，包含捕获、生成、进入、维护及移除。

`VehicleMoveEvent` 提供实例 UUID、所有者 UUID、可空的驾驶员和本 tick 的起止位置。取消后恢复原位姿并阻止本次移动。两个事件是区域保护接入点，不代表模块自动接入了全部地段或第三方保护规则；生产服应按自己的策略注册监听器。

## 验证与范围

执行 `gradle test --tests 'org.encinet.mik.module.vehicle.*' --tests 'org.encinet.mik.module.menu.*' --tests 'org.encinet.mik.module.i18n.LanguageResourcesTest'` 验证动力、传动、碰撞、矩阵、持久化、HUD 快照、界面控制、安全换挡、随车锚点及语言键。

客户端验收应覆盖多人驾驶/乘坐、第一/第三人称、控制台在高速行驶时的按钮命中与随车显示、UI 切换自动/手动挡、换挡进行中的重复点击、乘客/下车后的旧界面、HUD 开关、飞机俯仰/滚转、潜行退出、跨区块、断线重连以及基岩桥接输入。单元测试不能代替实际客户端的骑乘和插值体验测试。

当前范围是游戏尺度车辆，不是完整机械仿真。没有直升机、帆船、自由行走甲板、完整手动离合、飞机相机滚转、降落伞、资源包图形仪表或真实发动机声采样。基础 HUD 无资源包即可使用；真实座位按模型的三维位置移动，玩家外观和相机仍遵守原版骑乘表现。
