# 空间菜单

Java 菜单使用玩家专属的虚拟展示实体，Bedrock 从同一菜单定义生成原生表单。菜单、世界文字和选区粒子不注册世界实体、不放方块、不写区块。菜单与命令提交同一操作时，均由服务端重新校验权限和状态。

## 操作

- 对准按钮点击，禁用项显示原因；返回恢复上一级页面。
- 名称、玩家名和说明通过原生输入框填写，取消后返回原页。
- 同页状态更新保留当前位置，子页使用统一返回层级。
- 世界对象的提示贴近对象显示，离开范围或关闭功能后清理。

## 菜单大小与文字

「界面与文字」分别设置菜单整体大小和额外文字倍率，默认均为 100%，相互叠加：

| 设置 | 档位 |
| --- | --- |
| 菜单大小 | 70%、80%、90%、100%、110%、120%、130% |
| 文字大小 | 70%、80%、90%、100%、110%、125%、140%、160%、180% |

指向对应一侧滚轮只改变该项，端点停止；可一次恢复两项为 100%。Java 即时更新当前页，Bedrock 表单字号由客户端控制。

偏好按玩家保存在 `plugins/mik/menu-settings.yml` 的 `.scale`、`.text-scale`。世界锚定文字和固定世界尺寸的交互保持原有大小。墙体、地板、天花板或阅读角度限制可能使场景进一步缩小。

## FOV 适配

Java 的独立 FOV 页面须手动匹配客户端常规视野。提供 30°–110°、每 10° 一个预设，可用滚轮或按钮每次调整 5°，也可输入范围内的整数；默认 70°。

服务端只据此调整菜单位置，不读取或修改客户端摄像机。冲刺、飞行、效果、望远镜、模组变焦及窗口比例变化不会自动同步。高 FOV 会拉近菜单，字号和菜单大小仍独立控制；左右区域仍可能需要转头。

FOV 保存在 `.field-of-view`，无效值回退 70°，恢复菜单和文字 100% 不重置它。世界锚定标记和 Bedrock 原生表单不使用此适配。

## 布局与避障

| 场景 | 布局 |
| --- | --- |
| 主菜单、治理、地段 | 玩家正面宽弧，列表与操作分区 |
| 语言 | 完整圆环，滚轮逐项转动；正文、自动语言和返回留在正面 |
| Home | 地点列表与当前地点双栏 |
| 公告 | 固定平面阅读墙，滚轮翻页，首尾不循环 |
| 地段编辑 | 中央沙盘，周围为选点、形状、保存和历史操作 |
| 音乐 | 曲库列表与详情；唱片机按用途分控制、队列和声音设置 |

布局按实际文字、图标和立体装饰尺寸测量，长译文可换行。普通文字带深色阅读底，颜色之外保留名称、状态和禁用原因。

前方菜单整体避让已加载区块中的方块碰撞形状，以及当前玩家可见的方块／物品展示模型。空间不足时调整高度、朝向或整体缩小，渲染、悬停和点击共用最终位置；真实遮挡或尚未显现的按钮不可命中。环绕语言菜单优先保证正文和必要控件可读。

随车 HUD 在移动时重新拟合，静止时每四 tick 检查移动模型；遮挡时收近，空间恢复后逐步回退。菜单不会移动或隐藏原模型。眼睛位于不透明模型内部时无法保证可见，应调整座位或离开模型；资源包自定义模型使用保守包络。

公告每屏最多十四行正文，日期与分页另占两行，长公告完整接续到后页。默认字体估算与自定义资源包字体可能有差异。Bedrock 显示同一完整阅读页及翻页按钮，不逐帧刷新表单。

## 开发约定

共享框架位于 `shared/menu`，业务功能维护自己的菜单内容、会话和操作，跨功能导航位于 `shell/menu`。同一页面使用稳定 `screenId` 就地更新。

`frontArc()` 用于正面宽弧，`aroundViewer()` 用于环绕场景，`workbench()` 为立体预览预留中央空间；`spatialOnly()` 标记仅空间呈现的控件。具体功能通过共享定义适配平台，不直接依赖 Geyser API。空间检查只读取已加载区块，耗时几何与世界采样遵循主线程边界及有界任务预算。

具体操作见[地段](plot-board.md)、[选区与子地段](plot-subplots.md)、[音乐与音游](music.md)、[载具](vehicles.md)。
