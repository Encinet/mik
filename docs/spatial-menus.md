# 空间菜单交互设计

## 目标与边界

玩家应在一次进入后看清当前位置、可做的事及操作结果。菜单承载选择，世界承载位置和状态。建造、圈地、唱片机等有具体世界对象的功能给出贴着对象的反馈；语言、聊天、界面尺寸等纯设置保持简洁菜单，不添加无意义的世界特效。

所有世界提示必须只发送给相关玩家：空间菜单与唱片机侧面文字是客户端虚拟实体，plot 选区用指定玩家的粒子包。二者均不向世界注册实体，不放置方块，也不写入区块。

所有关键操作都留在游戏内。命令可作为快速入口和兼容入口；网站只承载可分享的完整公示记录。普通建造无需提交告知或走审批。管理操作按现有权限执行，同一动作从菜单和命令进入时由同一服务端检查裁定。

## 空间边界与过渡

主菜单、治理、地段和公告使用 `frontArc()`，只在玩家正面展开宽弧；语言的完整圆环继续使用 `aroundViewer()`。两者不共用「只保证正文和返回可见」的避障策略：前方宽弧需要让整页的侧栏、文字、图标和按钮边缘一起适应房间，圆环则优先保持正文与必要控件可读，其他卡片遵守真实遮挡。

布局先按实际文字与图标尺寸测量，再检查地板、天花板、墙面和未加载区块。按钮不只检测中心和四角：完整旋转面板与方块碰撞形状一起参与检查，半砖、细柱等按实际形状处理。空间不足时，前方宽弧先使用有限的高度调整与转向候选，再整体缩小；不会把单个按钮随意挪到另一侧。普通页面的尺寸偏好也不能突破最终空间与阅读角度约束。

大弧形保持水平曲面，不添加垂直俯仰；高页面通过扩大布局半径限制上下阅读角度。最终前方页面的垂直半角不超过约 35°，横向宽弧不再连带扩大垂直交互范围。通用间距缩紧，但按钮之间保留独立命中间隙。地段列表和多数操作区按实测宽高选择行列，短窄卡片可以多列，长标签不会强行横排。语义分组、删除确认、选区预览与隐藏菜单后的圈地流程保持不变。

环绕菜单从最终卡位显示，不再从玩家眼睛的位置放大移出；打开和关闭以文字淡入淡出、图标轻微缩放为主。切页或切换卡片需要大幅移动时直接替换到目标卡位并局部淡入，仅很小的邻近变化沿短弧过渡。弹性进度限制在 0–1，避免动画超调把文字推到拟合边界外。尚未可见或被真实方块遮挡的按钮不会命中，也不会把菜单点击变成挖掘背后的方块。

语言菜单不分页，所有语言卡片始终保留同一身份，并按实测标签宽度确定整圈半径，防止卡片重叠。布局显式选择 `continuousOrbit()`：滚轮每次转动一个语言位置，使用未取模的累计角度驱动位置与朝向同步插值，连续滚动、跨首尾与转过半圈不会反向或穿过玩家。滚动不重置卡片显现进度，不以淡出／淡入冒充移动；正文、自动语言和返回控件留在正面。其他环绕菜单继续采用原有的大幅切换替换策略。Bedrock 同样一次列出全部语言，不提供分页控件。

场景测量结果随页面保存，平衡布局按节点尺寸缓存，同次拟合复用碰撞形状。稳定的前方页面在普通数据刷新时不重复搜索房间；附近放置、破坏、活塞移动、爆炸或实体改变方块会标记重新拟合，并合并到最多每四 tick 一次。所有空间检查只读取已加载区块，不向世界注册菜单实体。

正面菜单与载具仪表还会避让玩家可见的方块／物品展示实体。检测使用实体朝向、平移、左右旋转与缩放后的几何体，而不是展示实体通常为空的碰撞盒；先按变换后的包络筛除远处实体，再裁剪展示几何与整块按钮的视锥，避免只检查中心或角点时漏掉细杆和边缘遮挡。按钮正文、图标深度及悬停／按压余量一起参与拟合。遇到遮挡时，以眼睛为中心同比缩短距离和尺寸，保持屏幕上的角度大小和布局，不移动、删除或隐藏模型实体，也不纳入其他玩家不可见的预览。物品模型按保守的单位包络处理；相机朝向的展示实体使用保守旋转包络，资源包的自定义模型不在精确几何保证范围内。

跟随玩家的 HUD 在移动当 tick 重新拟合，静止时每四 tick 检查移动的展示实体；遇到障碍立即收近，空间恢复时逐步回退，稳定结果不重复发送整页元数据。渲染、悬停和点击使用同一轮拟合后的坐标及尺度；客户端不再单独插值尺寸，避免避让时仍显示上一帧的大按钮。服务端继续负责开关、悬停等动画。玩家眼睛已进入不透明模型内部或与表面几乎重合时没有可保证可见的空间，应调整座位／模型或移到模型外；算法只保留退化尺度以避免非法元数据，不把这种情况视为可见性保证。环绕语言菜单仍保持原来的必要控件优先策略。

地段编辑器使用通用 `workbench()` 布局，在中央为立体模型预留空间，把实测控件放在后方浅弧的左右、上方与下方。`BlockVolume` 装饰保存完整 `BlockData` 及独立三轴尺寸，只发送私有显示包，不产生交互盒。房间拟合将这些体积的旋转角点合并成保守三维包络，并检测整个包络的深度，不能只按平面宽高检查；立体装饰从最终位置出现，避免从眼前放大飞入。`spatialOnly()` 控件在原生表单中隐藏，具体业务模块不依赖 Geyser API。

公告使用一整块正面平面阅读墙，不再分成弧形卡片。每屏一页，顶部标题、背景和下方控件固定，阅读区最多十四行正文，另留日期与分页归属两行。短公告保留相同尺寸，长公告完整接续到后面的阅读页，不截断正文，也不需要点击展开。正文为被动内容，没有点击命中盒。背景是仅当前玩家可见的虚拟方块薄板，不在真实世界放置方块。

滚轮向下进入右侧的下一页：当前正文向左滑出，下一页从右侧进入；向上反向浏览，首尾不循环。滑动使用 260 毫秒缓出，快速滚动累积目标页，反向输入从当前插值位置继续。边缘按完整字素裁切，避免露出阅读区外的文字；这不是客户端像素级剪裁，宽度以默认字体估算，自定义资源包字体可能偏离。两枚浏览按钮只有多页时出现，重载和返回留在独立下方。分页仅随公告快照变化重建；重载保留当前公告与页内位置，并终止旧滑动、约束新边界。动画借用菜单生命周期刷新，不新增独立定时任务。Bedrock 直接显示同一完整阅读页和浏览按钮，不生成空间背景、逐行片段或逐帧表单刷新。

## 统一交互语法

| 层次 | 内容 | 交互 |
| --- | --- | --- |
| 总览 | 当前地点和少量主要目的地 | 一次点击进入对象；返回回到原菜单 |
| 对象 | 名称、状态、直接相关操作 | 先显示可见的结果与限制；动作在当前页更新 |
| 设置 | 可改变的权限与成员 | 显示当前选中状态；点击切换，失败保留原状态 |
| 输入 | 名称、玩家名、说明 | 使用原生对话框；Esc 返回；提交后回到原页 |
| 世界反馈 | 仅与地点或物件直接相关 | 私有、短距离、按需更新；离开后移除 |

按钮使用物品图标加文字；颜色辅助区分状态，但不单独承载含义。禁用项要显示原因。相同菜单页用 `screenId` 就地更新，子页沿统一 Back 返回。Java 版由虚拟展示实体构成空间场景，Bedrock 由同一菜单定义投影成原生表单。输入使用 Paper 原生对话框。每位玩家独立生成自己的文本，因此世界状态与说明按阅读者语言呈现。

方块图标按立体模型而非平面物品处理：下方标签根据实际文字高度留出间距，文字平面位于方块最大展示深度之前。方块与标签共同轻微浮动；悬停放大、多行文字和阅读尺寸设置都参与布局包络，墙体拟合同时检查方块与前置标签的深度。普通物品图标沿用原有位置与文字间距。

普通空间菜单的标题、按钮及禁用文字带半透明深色底，避免草地、雪地、火光和建筑纹理吞掉字形。默认字形尺寸为 `0.92`，暗灰字和暗紫标题在 Java 世界文字中提亮；玩家可在「界面与文字」中独立调节菜单和文字大小。常规页面使用相同的视觉缩放，切换页面或翻页不会因为内容多少改变字和图标的大小。较宽的页面可轻微转头阅读；只有场景超出最大阅读角度或前方有遮挡时才缩小。排版仍要先减少同屏内容，不能依赖自动缩小容纳十几项操作。透明文字背景用于贴在世界物体上的短提示，以及已有整块深色背景的公告墙；后者不为每行重复叠加小卡片。

## 独立菜单与文字大小

设置页左侧为菜单大小，右侧为文字大小，中间保留说明和实时文字预览，所有档位在同一页直接选择，不分页。

- 菜单大小提供 `70%、80%、90%、100%、110%、120%、130%` 七档，控制包含文字、图标、布局和沙盘在内的整体视觉缩放；调大不会反向缩小文字。
- 文字大小提供 `70%、80%、90%、100%、110%、125%、140%、160%、180%` 九档，作为当前菜单缩放之上的额外文字倍率，影响文字、禁用原因和非世界锚定文字装饰。
- 默认两项均为 `100%`，可单独改动，也可一键恢复两项。指向左侧档位滚轮只调整菜单，指向右侧档位只调整文字；达到端点后停止，不循环。
- 文本的局部比例直接使用文字倍率，不再除以菜单倍率。宽弧和环绕场景的观看距离同时按菜单倍率补偿，避免图形和距离同比缩放抵消屏幕大小变化。字形尺寸、图标下方留白、交互热区、障碍物包络和布局测量共用真实文字倍率。两项保存值仍独立；例如菜单 120%、文字 125% 会叠加放大文字，不会把其中一项抵消。
- 墙体、地板、天花板和最大阅读角度仍是安全边界；空间不足时允许整体拟合缩小，设置百分比不承诺在任何狭窄位置都能完整呈现。世界锚定的文字与固定世界尺寸交互保持原有大小。

两项偏好按玩家分别保存到 `plugins/mik/menu-settings.yml` 的 `.scale` 和 `.text-scale`，修改一项不会覆盖另一项。主菜单入口同时显示当前两项百分比。Java 菜单即时更新同一页面，不重新建立导航层级；Bedrock 仍提供清晰分组的直接选项，但原生表单字号由客户端控制，页面明确说明此限制，不为滚轮额外生成操作对话框。

## FOV 适配

Java 设置页提供独立的「视野适配（FOV）」入口，不把第三组档位挤进菜单大小与文字大小两栏。适配页提供 `30°、40°、50°、60°、70°、80°、90°、100°、110°` 九个预设；滚轮或 `−5°／+5°` 每次调整五度，也可输入 `30–110` 之间的任意整数。自定义值不被预设取整，未知时保持默认 `70°`。

该值由玩家手动匹配客户端的常规 FOV；实现不读取或修改客户端视野，也不拿视距、GUI 缩放、客户端品牌或运行速度推测 FOV。它是服务端空间排布使用的保守参考，不是客户端摄像机控制；冲刺、飞行、速度效果、望远镜、模组动态变焦以及窗口宽高比变化均不会自动更新这个值。

纵向阅读边界使用 `FOV / 2`，不再把 70° 以上的设置全部截成 35°。投影补偿系数为 `tan(FOV / 2) / tan(35°)`：普通前方面板在高 FOV 下拉近锚点，同时保留正常控件比例；宽弧和环绕菜单保持横向位置、纵向位置与控件尺寸，将局部前后距离除以「FOV 补偿系数 × 菜单倍率」，并重新计算朝向、控件包络和墙体拟合。菜单 100% 时，110° 的补偿系数约为 2.04；无遮挡的正前方控件会比 70° 更近，而不是把位置、字形一起等比例缩小后抵消变化。局部沙盘、标签与按钮使用同一投影；世界锚定标记不移动。

FOV 与菜单大小、文字大小独立保存。调整 FOV 不改写字号或菜单比例；目标是避免高 FOV 下正前方控件明显缩小，密集页面、侧面控件和近墙拟合仍可能影响屏幕大小。左右分区及环绕场景仍需转头浏览，不保证全部按钮同时进入屏幕；需要更大文字时仍可独立调整字号。FOV 单独保存在 `.field-of-view`，无效存储值只回退此项为 `70°`；「两项恢复 100%」不重置 FOV。适配后即时更新同一页面，返回设置页显示最新值。原生 Bedrock 表单不使用该空间适配入口。

## 形式与视觉层次

菜单按任务选形态，玩家无需选择样式。主菜单是围绕玩家正前方展开的大弧面：个人资料和地段在左侧，常用目的地与快捷状态在正前方，投票、公示结果与站外链接在右侧，不再把投票区堆到主菜单下面；治理和 Plot 页面也沿宽弧按任务分区，详情与说明居中，列表和操作分列左右；Home 是“地点列表＋当前地点”双栏；唱片机分播放、队列和声音设置三页；曲库左侧列歌，右侧常显操作提示和曲目资料；公告用平面阅读墙，社区记录用阅读卡片。危险确认只呈现目标、后果和返回操作。布局都按文字和物品实际尺寸计算间距，长译文可以换行，不能靠固定坐标堆放。

这几类分别使用冷蓝、青绿、草木色、深紫、暖灰褐和暗红的深色阅读面。颜色提示所处功能，但名称、图标、状态字和禁用原因始终保留；同一屏的选中、指向和按下反馈沿用同一交互语法。阅读卡片比短操作面更不透明，浅色方块背景下的红字、蓝字与暗色提示在 Java 空间文字中提亮。Bedrock 从同一菜单定义读取标题、内容、顺序和操作，样式差异不携带额外功能信息。

常规页面的曲面只用于少量目的地或操作区，深度保持很浅；列表和长文仍以直列或卡片呈现。主菜单、治理和 Plot 共用最多约 160° 的正面圆柱弧，各面板朝向玩家，可转头在左右查看不同任务区。半径按文字和图标的实际宽度计算，中心始终对准主要阅读或操作区，长译文、投票加载及地段公告出现时仍保留面板间距。需要更多横向空间的 Home 双栏和唱片机控制台允许小幅转头阅读，且与单栏菜单共用阅读尺寸。附近墙体可能迫使菜单变近并缩小，主要入口和关闭按钮参与遮挡检查。所有样式仍是玩家专属的客户端显示实体；装饰物、粒子和真实世界状态的边界不变。

宽弧几何由菜单基础设施的 `panoramicPanels` 统一计算，功能模块只声明中心面板、区域顺序和任务分组。每份菜单定义持有独立布局缓存，测量尺寸变化时重新计算，不在模块之间共享可变布局状态。Plot 的页面框架集中在 `PlotMenuLayouts`，控制器保留刷新、预览和操作回调；治理布局集中在 `GovernanceArcLayouts`。权限判断和数据库写入仍由原有服务处理，Java 与 Bedrock 继续使用同一份语义菜单定义。

公告正文使用固定尺寸的正面平面阅读区，只让日期与正文在区内水平滑动。音乐曲库每页 16 首，需要密集列表和常显详情；地段权限需要并列比较；社区记录还要呈现公示与异议的关系，因此这些页面保留列表或双栏。能对应到附近方块的位置继续用私有世界标记或粒子提示，不用轮盘代替真实位置。

## 常用菜单

- 主菜单沿玩家正面的宽弧从左到右显示个人资料、地段区、常用操作、投票区和公示结果与站外链接。地段入口固定在左侧，玩家站在保护范围内时，同一侧增加当前地段的私有菜单公告板：地段名和所有者始终显示，有告示正文时一起显示；点击直接打开当前位置的地段详情。家、音乐、公告及 AFK、PvP 快速状态留在正前方，设置与关闭在中央操作区下沿。治理入口、进行中的投票、分页及投票按钮固定在右侧，最近结果与官网、地图、Wiki 在更右侧，不再另设底部公示区。进出地段，或告示、地段名、所有者变更时，已打开的主菜单自动刷新。公告板只使用对查看者可见的菜单实体，不在真实世界放置方块或实体。每次展示一项投票，滚轮切换其他议题；合资格玩家可在主菜单直接选赞成、反对或弃权，选票状态在提交后刷新。更多个人资格与历史记录仍从治理入口查看。语言、聊天、传送偏好与界面尺寸仍在同一设置页。
- 主菜单右侧的当前投票与最近结果合成连续投票区：治理入口在组上方，两列标题按实测顶部对齐，组内间距小于其他任务区之间的间距。站外链接独立置于更外侧，不穿插在投票或结果卡片之间。不同文字长度、结果数量和阅读尺寸不会把同组内容推到不相关的排位。
- 治理首页采用大弧形：资格在最左侧，最近结果与进行中的议题相邻组成投票浏览区，进行中的议题贴近正前方详情；两列标题顶部对齐，各列卡片按顺序连续排列。详情、本人选票及投票按钮在正前方，治理操作在右。刷新与返回保留在中央；滚轮切换更多议题。历史、联署和玩家档案页也使用相同宽弧，历史页只用于查看较早的完整记录。
- Home 每页四个家，保留所选家的位置详情。选中同世界、已加载且距玩家约 2–18 格的家时，在保存点上方显示一个与菜单图标相同的小型客户端虚拟物品；切换选择或关闭菜单即移除。创建家在菜单内输入名字，保存位置固定为打开输入框时的站位；更新位置、换图标和删除都可直接点按。修改位置与删除继续确认。跨世界的家不做远处世界预览，也不为看菜单加载区块。
- 音乐浏览每页 16 首，左侧两列各八首；每项第一行尽量显示歌名，第二行显示序号和歌手。右侧常显当前指向歌曲的较完整资料、左右键说明与曲库操作，减少列表上方控件对阅读空间的挤占。左键直接拿取唱片或加入队列，右键直接播放；移动到侧栏时资料可以变化，但不会改变点击所作用的曲目。队列也用两列各八首，选中歌曲及播放、移除、调整顺序留在右侧。搜索、歌单导入、排序、分区和翻页都可在游戏内完成。
- 公告按发布时间从新到旧排列，不按月份筛选，也不因超过一年而隐藏。每条完整分成阅读页，在正面平面墙中左右浏览，不旋转整面墙、不首尾循环。场景包络通过 `framingDecorations("wall")` 只测量固定背景与控件，避免移动片段触发重新定位；正文片段使用精确坐标跟踪，不叠加布局缓动或从中心冒出的入场位移。重载和返回在固定阅读区下方；短公告、长公告与空列表共用稳定背景尺寸。空间实体仅查看者可见，仍遵守真实方块遮挡；Bedrock 使用完整正文页和按钮。
- 语言选择每页八种语言，选项围绕玩家排成一圈；滚轮逐种切换，跨页时自动接续，点击卡片立即应用。自动识别会把当前实际使用的语言转到正面；“自动识别”和返回始终在正面下方。被方块挡住的语言卡片不会透墙显示或响应点击，滚轮仍可继续切换。Bedrock 表单按固定语言顺序列出本页选项。聊天、PvP 及传送偏好等纯设置保留简洁切换页，不在世界中叠加无意义的实体或粒子。

## 地段流程

地段菜单围绕固定范围管理，不混入施工预留、施工证据、自动扩张或到期配额。

地段主界面只保留当前数据、操作与异常状态。当前位置卡片已显示地段名称时，不再额外复述「这里属于某地段」；详情不常驻显示边界颜色说明，范围编辑也不重复同名分区标题。帮助仅保留选点、沙盘图例、矩形调整和返回编辑器所需的操作信息；删除采样参数、重复菜单导航、角色规则和环境作用的独立帮助页。权限页没有底部切换顺序说明，成员草案只显示「尚未提交」状态。正常沙盘没有空说明卡，剖切高度、加载进度、未加载区域、简化预览和校验问题仍明确显示。删除、转让、移除成员与保存范围继续保留确认及后果说明。没有地段时只显示当前位置无地段，不再要求先建造建筑。

1. `/plot` 首页：左侧列出自己的和共享的地段，中央显示当前位置，右侧是创建和公开到访入口；社区历史和指引不再挤在首页。
2. 「建立地段」先打开选区面板，选两个角点后创建并填写名称。无需先放置建筑方块或等待 Prism 查询。
3. 详情页：资料与告示在中央，范围编辑在左侧，权限、改名与告示设置在右侧，到访点另成一栏；删除独立放置并需要确认。已有子地段显示在左侧，划分操作收进高级编辑页。
4. 普通范围编辑：选点、边框预览、保存、撤销／重做。先载入已有范围，重新选两点时明确显示「替换范围并保存」。高级页单独提供累加、扣除、替换和划分子地段，不与普通选点同屏堆放。

新范围向外对齐 4×4×4 网格，不附加隐藏余量，面板显示最终尺寸与坐标。保存前复检当前权限、重叠、子地段和到访点；旧确认不能覆盖确认期间已改变的边界。普通建造和批量编辑都只检查保护权限，不改变范围。

菜单收起后保留世界坐标选区和边框，玩家可自由走动。仅预览状态不拦截建造；潜行加右键／F 或 `/plot edit` 返回面板。实地选点时才拦截无参数 `//pos1`、`//pos2`，不注册或覆盖 WorldEdit 命令。

粒子只发送给当前玩家：金色两点笔刷、紫色组合轮廓、青色已保存的单元。每 10 tick 最多 256 粒子，裁剪 24 格外边缘并复用几何缓存；菜单和会话不会重复绘制同一份预览。旧地段保留原有保护余量，旧预留不再提供保护，历史记录不删除。完整操作与兼容说明见 `docs/plot-board.md`、`docs/plot-subplots.md`。

## 唱片机

正在播放或载入的最近一台可见唱片机，在朝向玩家的一侧显示曲名、歌手等资料、播放状态、时间和底部进度条。音乐模式用冷蓝色，音游模式用粉色与不同的状态符号；曲名仍保持白色以便阅读。侧面牌的文字缩放、行宽和最多七行共同限制在方块侧面内，遮挡检测按同一范围取样。长曲名在两行窗口中逐行滚动；过长的资料、状态和时间在各自行内缓慢滚动，歌手常显，其余资料轮换。时长未知或尚在载入时，进度条显示移动光段，不显示虚假的完成比例。音游等待玩家或曲目没有可用节拍时显示空进度条和准确的状态文字。播放牌贴在方块侧面；玩家视线与文字范围之间有方块遮挡时隐藏，斜向观看可选另一处无遮挡的侧面。每位靠近者看到自己的语言；仅扫描玩家周围已加载的区块，不加载新区块。显示不带交互热区，控制入口仍是潜行空手右击实体唱片机。切换侧面时复用同一个虚拟展示实体；距离超过控制范围、播放结束、方块或玩家离开世界时移除。完整曲目资料、队列和控制保留在已有控制菜单中，避免侧面文字盖满建筑。

控制首页顶部显示当前曲名、播放状态和进度，下面只放当前模式常用操作。队列与声音设置各有独立一页，音量和范围用明确的加减按钮。音乐控制页用冷蓝色，音游入口、玩法选择、延迟测试和结算页用粉色；文字和图标仍明确标示模式。曲目的专辑和音频参数直接显示在曲库右侧。打开控制页时，唱片仍以仅向玩家发包的虚拟物品在真实唱片机上方旋转。

调整音量成功时，从真实唱片机位置向操作玩家发送少量音符粒子；调整传播范围成功时，在方块周围显示四个短暂粒子点。效果只表示操作已作用于这台唱片机，实际数值仍以菜单文字为准；到达上限而数值未变化时不播放反馈。粒子均为玩家专属包，不写入世界。

## 校验重点

- Java 与 Bedrock 的入口、顺序、禁用原因一致；鼠标和手柄表单都能完成 plot 常用动作。
- 世界提示不挡住实体、墙面或其他玩家；远离、切换世界和插件关闭后没有残留。
- 16 份语言资源键及参数一致；名称和玩家输入由服务端再校验。
- 高密度区域内每名玩家最多看到一台唱片机侧面状态；plot 预览裁剪到视点 24 格内，单次最多 256 个粒子，不对世界产生实体或方块修改。
