# 公告（更新日志）

公告只展示服务器最近的更新，不记录已读进度，也不向游戏聊天、网页聊天、QQ 或 Matrix 推送。Paper 主菜单预览最新一条；从主菜单或 `/announcements` 打开后，按日期从新到旧阅读，长文本沿用菜单的正文分页。网页通过 `GET /api/announcements` 读取同一份日志，不依赖 Paper 在线。

## 编辑与生效

将日志写入 `mikd` 的 `/var/lib/mikd/announcements/catalog.json`。内容是 JSON 数组：

```json
[
  {"timestamp": "2026-11-19T12:00:00+08:00", "content": "主城新增公共传送点。"},
  {"timestamp": "2026-11-18T18:00:00+08:00", "content": "修复唱片机切歌后不更新标题的问题。"}
]
```

时间戳使用带时区的 RFC 3339。正文不能为空，每条至多 8 KiB；整份文件最多 256 条和 128 KiB。用同目录临时文件替换原文件，清空时写入 `[]`。

`mikd` 在启动后立即尝试加载，此后每 5 秒检查文件。有效快照自动生效，无需执行游戏命令或重启。Paper 启动时请求快照，此后每 30 秒同步一次；在连接正常时，更新通常在替换文件后 35 秒内可见。

| 目录状态 | 网页 API | 游戏更新日志 |
| --- | --- | --- |
| 已加载有效文件（包括 `[]`） | `200`，返回 JSON 数组 | 显示公告或「暂无公告」 |
| 尚未加载过有效文件 | `503` | 提示暂时不可用 |
| 已加载过有效文件，当前文件无法读入 | `200`，保留上次有效快照 | 显示上次取得的快照并标明状态 |

API 使用 `X-Mik-Announcements-State` 标注 `ready`、`unavailable`、`stale` 或 `disabled`。Paper 到后台断线时也会保留并标明上次加载的日志。文件缺失或损坏不会阻止后台其他功能启动；持续失败只记录一次错误，修复后自动恢复。
