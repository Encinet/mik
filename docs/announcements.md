# 公告

从主菜单进入「公告」，或执行 `/announcements`。目录和正文使用同一空间工作区；关闭后再次打开会恢复本次在线期间的阅读位置。

主菜单左侧显示最近一条公告的日期与正文。优先按当前字号和实际宽度完整展开，整页放不下时才显示最多八行摘要，保留悬浮全文并显示「查看全部公告」；点击从最新公告的第一页开始阅读。没有公告或最新公告正文为空时，组件收起。预览不改变已读记录，公告重载后自动刷新，包括日期未变的正文修订。

## 阅读

- 左侧目录每组显示四条公告，按日期从新到旧排列，条目包含日期与短摘要。点击直接阅读，当前公告保留选中标记。
- 指向目录区域滚轮翻组，包括标题、条目和空白处；翻组时保留正在阅读的正文。目录也有「较新一组」「较早一组」按钮。目录到首末组后停止，滚轮不转交给正文。
- 右侧以稳定阅读面显示日期和正文。每页容量由实际字号、FOV 和菜单大小决定，长段落自动拆分；短末页保留同篇正文的阅读范围，正文左缘和底部工具位置保持稳定。
- 在正文区域使用滚轮或翻页按钮连续阅读。跨越公告边界时，翻页按钮提示「较新公告」或「较早公告」；首尾停止，不循环。页码表示当前公告内的页数。
- 切换公告后再选回来，会恢复该篇的正文位置；字号或 FOV 改变后重新分页，保留正在阅读的位置。「最新公告」直接回到最新一篇的第一页，返回恢复实际来源菜单。

## 文件与重载

公告位于 `plugins/mik/announcements.txt`，每段以服务器本地时区的 `yyyy-MM-dd HH:mm:ss` 日期开头，下一行开始是正文，段落之间用 `---` 分隔。例如：

```text
2026-10-29 12:00:00
周末活动安排

本周六 20:00 在主城集合。
---
2026-10-28 18:00:00
服务器已完成维护。
```

拥有 `mik.command.reloadannouncements` 权限的玩家可使用菜单中的「重新加载公告」或 `/reloadannouncements`。执行菜单操作时再次检查权限。加载失败时保留原有公告；新增或修改公告后，已打开的工作区尽量保留当前公告与正文位置，内容缩短时收回到有效范围。

上线推送及新增公告聊天通知使用已读记录，保存在 `announcements-state.yml`。HTTP API 读取同一公告快照。目录摘要只用于查找，完整正文不会因摘要截断而丢失。

## 新公告同步

执行 `/reloadannouncements` 或菜单中的重载操作后，新增时间戳的非空公告会同时通知在线游戏玩家、WebChat，以及已启用并就绪的全部 Social 平台。目前支持 QQ 和 Matrix；Social 发送到各平台 `chat-bridge.routes` 配置的全部群或房间，不需要账号绑定。

公告是独立的服务端通知，不受普通聊天的 `inbound` / `outbound` 前缀限制。Social 通知包含公告时间与正文，标题跟随平台的 `default-language`，使用平台自身的 Markdown 或 HTML 渲染，并沿用内容安全与出站长度限制。平台未配置投递路由时不发送；审核拦截时取消该平台的通知，发送失败记入日志与 `/social status` 的失败计数，其他平台和其他目的地继续发送。

首次启动只加载历史公告；重复重载、仅修订相同时间戳的正文、玩家上线补看未读公告，都不会重新向群聊广播。只有新增公告触发本次同步，离线平台不保存待补发历史。Social 的网络请求和审核在现有有界后台队列执行，重载与停用会取消旧平台运行周期的排队通知。
