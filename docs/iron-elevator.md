# 铁块电梯

在同一世界的不同高度放置铁块即可使用，无需命令或登记。同一高度侧面相连的铁块组成物理平台，斜角不相连；不同平台有重叠的 X/Z 列即可连接成井道，共享楼层列表。同一井道在一个高度可以包含多片分离的平台，它们属于同一楼层；出发范围始终是玩家脚下那片连通平台，冷热缓存保持一致。

## 使用

- 站在平台上跳跃到上一安全层，按下潜行到下一安全层；保持潜行不连续下行。
- Action Bar 显示“↑ 跳 / ↓ 蹲”，日常提示使用跳跃、潜行的动作名称，均按玩家选择的语言显示。Action Bar 中绿色方向可用，灰色不可用；没有安全目标的孤立平台不显示提示。
- 传送只修改 Y，保留 X、Z 和视角，不吸附平台中心。当前垂直落点无铁块或有障碍时，上下行继续寻找下一层；直接选层则不可用。
- 按实际碰撞形状与玩家空间检查落点，排除液体、火等危险位置。可跨楼板，楼层间距不设限制，扫描限于世界建筑高度。
- 成功后清除速度与摔落距离，全部随行玩家冷却 0.5 秒。飞行、滑翔、游泳和旁观模式不触发；其他插件可取消传送。

徒步跳跃在已有安全上行结果且当前站位重新验证通过时转为电梯操作；平台内移动和提示刷新期间可复用该结果。刚进入平台或缓存过期尚未确认时，保留普通跳跃，发现过程仍按 tick 分批执行。

查询中只保留玩家最新一次操作，最长 1.5 秒。重复输入复用扫描进度；同一支撑列内移动或同行组变化时，重新评估已发现的候选楼层，包括此前不可用的楼层；支撑列变化时重新查找路线。离开平台、相关方块变化、卸载或离线会取消待执行请求。没有可用目标时仍可普通跳跃或下马。

电梯布置与操作也会出现在[日常随机提示](guidance.md#日常随机提示)中。

## 拴绳与骑乘

玩家、坐骑、全部乘客及拴绳相连生物作为同行组，支持串联、分支与多层乘坐。非乘客成员须站在同一出发平台，附近无连接的实体不随行。

目标须容纳每名成员，底层成员各自在原 X/Z 下有铁块。整组沿 Y 平移并保留骑乘与拴绳关系，上下行跳过不能容纳整组的楼层。骑乘时只响应新按下的跳跃或潜行；已接受下行请求时阻止本次自动下马。

候选实体只查平台外扩 16 格的已加载范围，最多 1024 个候选、64 名同行成员，超限拒绝。传送前复核关系与落点；中途失败会尝试恢复原位与连接。其他插件可能拒绝恢复，相关失败记录日志。整组执行期间保留成员占用，传送事件引起的观察在执行或恢复结束后刷新；同组玩家不能重入发起另一趟传送。

## 选层面板

井道至少有 2 个可站立楼层时，在平台附近合适的平整墙面显示私有按钮。优先相邻墙，最远搜索 4 格；找不到合适墙面时，在铁块平台的外露边缘悬空显示面板，朝向平台内部。悬空位置固定，不随玩家视角或站位移动，宽度限制在连续的直边内，避开障碍和未加载区块。

对准数字左键或右键选层。当前层为绿色下划线，不可用层为黄色删除线，尚在检查的楼层附省略号；只有确认可用的目标附带操作，容量不足时分页。楼层数字在各列居中，末行不足一行时水平居中，末页不足一页时在正文区域垂直居中。数字和翻页控件均无背景，悬浮与按压保持原平面，贴墙面板的挂点位于方块表面。贴墙与悬空面板保持相同的可操作高度，不改方块、不生成持久实体。面板整体拦截挖掘和物品使用，点击再次校验墙面或边缘空间、遮挡与落点。

面板读取楼层状态快照，布局、翻页和字号重排不读取世界。共享菜单发布当前窗口后，电梯按预算检查可见楼层；方向查询与面板目录独立推进。面板每秒更新状态，挂点分步搜索并缓存两秒；相关方块变化或卸载使缓存失效，离开电梯即移除。挂点范围不随楼层数改变，字号变化在原范围内重新分页，刷新保留正在浏览的楼层。显示、组件与点击共用[空间菜单运行时](spatial-menu-design.md#世界固定面板)；普通菜单打开时暂时隐藏选层面板并停止可见楼层检查，关闭后按当前窗口恢复。挂点失效或消失只撤下面板，方向传送继续按自己的查询结果工作。

## 楼层编号

普通世界根据周围已加载地表估计入口层，优先稳定的低处地面证据，减少屋顶与孤立深坑影响。确认后的基准在井道内共享，不因换站相邻铁块或加盖屋顶而改变。证据不足时暂用最低可用层并继续重试；下界、末地或无有效地表时也使用最低层。

1 层向上为 2、3……，向下为 −1、−2……，没有 0 层。自动估计无法保证复杂坡地、大屋顶、多入口或悬空建筑准确，可在 `plugins/mik/iron-elevators.yml` 手工指定，重启生效：

```yaml
ground-floors:
  '世界 UUID':
    '铁块 X,铁块 Z': 64
```

值为 1 层铁块的 Y，不是玩家脚部高度。同一井道配置任意一列即可；多列应使用相同高度，冲突时按 X、Z 升序采用第一项。人工值优先，须对应实际可用层；损坏配置会报错。配置在后台读取并校验，成功后才启用事件和调度；失败时电梯功能保持停用并记录错误。人工高度必须精确对应可用楼层，不会自动选取附近高度。

## 扫描限制

世界读取在主线程分批执行，不加载区块；每 tick 最多 256 步并协作检查 1 ms 预算。输入、方向提示、完整目录按 4:2:1 步数轮转，同类任务轮流执行，进度跨 tick 保留；空闲份额可复用。多个玩家共享进行中的井道发现及完成的目录。后台任务保留交互接纳空间，面板安放与可见楼层检查也使用同一预算。未加载或超限的井道不缓存完整目录；路线仅发布已确认的安全目标。

每片平台最多 64 块铁块，完整目录最多 128 列、4096 块铁块。完整目录超限不发布，但独立验证通过的局部上下行仍可用；超大连通平台不视为可用平台。

几何缓存有效两秒，最多 64 座井道。到期重新验证出发平台，保留已接受输入的原始截止时间；平台几何未变时，未完成的路线扫描和共享井道发现继续推进。相关放置、破坏、爆炸、活塞和区块卸载使缓存失效并取消相关请求；活塞包含源与目标位置，依赖范围包含探测过的空白区域。缓存不替代落点、实体碰撞和传送前的实时检查。

性能测量单独运行 `./gradlew benchmark --tests org.encinet.mik.feature.world.elevator.IronElevatorBenchmark`，结果记录耗时与分配量，不代表实服 TPS。
