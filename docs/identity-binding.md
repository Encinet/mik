# 外部身份绑定

身份绑定连接 Minecraft UUID 与平台认证的外部身份，并统一管理服务器准入。玩家至少有一条绑定，且该账号仍在任意一个已接入社区中，才可新登录。社交平台的命令和适配边界见 [社交平台适配架构](social-platforms.md)。

## 身份、绑定与会话

| 概念 | 标识 | 职责 |
| --- | --- | --- |
| 外部身份 | `platform + issuer + scope + subject` | 识别平台认证出的账号，决定是否为同一个身份 |
| 绑定记录 | 随机 UUID `binding_id` | 记录外部身份属于哪个 Minecraft UUID，提供稳定的单条解绑目标 |
| 会话与成员上下文 | 平台会话及其成员记录 | 决定消息发往哪里、是否能够原生 @，不自动产生绑定 |

四段身份键的含义如下：

| 字段 | 含义 | QQ 群消息适配 | Matrix 适配 |
| --- | --- | --- | --- |
| `platform` | 平台类型 | `qq` | `matrix` |
| `issuer` | 签发标识的应用或身份提供方 | 机器人 AppID | MXID 的 homeserver |
| `scope` | 用户标识真正生效的命名空间；账号级标识为空 | 空 | 空 |
| `subject` | 平台认证出的用户标识 | `member_openid` | 完整 MXID |

`scope` 由平台标识的语义决定，不能直接使用消息所在的群 ID。QQ 同一 AppID 下，相同 `member_openid` 在多个群出现时共用一条绑定；群 ID 留在会话与成员目录中。若将来某个平台的用户 ID 确实只在群内有效，适配器必须把群标识写入 `scope`，各群身份分别绑定、分别解绑。

除 `platform` 会转为小写外，其他三段都是不透明标识，不裁剪、不改写大小写、不做 Unicode 归一化。适配器可提供 `scopeDisplayName`（例如群名）用于列表展示；名称不参与唯一性或鉴权。真正按社区隔离的身份显示社区名，没有名称时显示带短指纹的社区标签。

## 绑定不变量

- 一个完整外部身份键最多绑定一个 Minecraft UUID，不能用另一个验证码抢绑。
- 同一 Minecraft UUID 在同一个 `platform + issuer + scope` 内最多绑定一个外部账号。
- 同一身份再次验证，只更新展示名称和验证时间，保留 `binding_id` 与首次绑定时间，不新增记录。
- 不同 AppID 或真实作用域保持独立。不能按昵称、相同裸 ID 或同一玩家名推断跨作用域身份相同；不同标识需分别验证。
- Minecraft UUID 是关联不同平台身份的依据，玩家改名只更新展示名称。
- 解绑后重新绑定会生成新的 `binding_id`，旧列表按钮不会删除新绑定。

这意味着一个玩家可以有多条有效绑定，例如 QQ、Matrix 和某个按群隔离的平台的两个群身份。这些记录可以分别撤销；相同外部身份的重复验证不会增加记录。

## 绑定白名单与成员退出

MIK 直接检查绑定与平台成员资格，原版 `whitelist.json` 和 OP 不能绕过，插件不会把绑定同步成另一份原版名单。`white-list` 开关不影响绑定准入；原版名单可以清空。封禁、维护和密码验证继续各自生效。

| 账号状态 | 新登录 | 已在线玩家 | 绑定记录 |
| --- | --- | --- | --- |
| 任一绑定账号仍在任一接入社区 | 允许继续其他登录检查 | 保留连接 | 保留 |
| 没有绑定 | 拒绝并提供绑定指令 | 最迟下一次 1 秒检查时移出 | 无 |
| 所有绑定账号确认离开各自平台的全部接入社区 | 拒绝 | 最迟下一次 1 秒检查时移出 | 自动逐条撤销 |
| 因启动、断线或接口错误暂时无法核验，且没有其他已确认的绑定 | 暂停新登录 | 保留连接 | 保留，等待核验 |

同一 QQ／Matrix 账号在多个接入群或房间出现时共用一条绑定。退出其中一个仍保留，只有退出该平台最后一个接入社区才自动解绑；另一个平台或真实独立作用域的绑定不受影响。重新加入社区不会恢复已撤销的绑定，需要再次验证 Minecraft 账号。

QQ 的 `allowed-group-openids`、Matrix 的 `membership.room-ids` 必须显式配置非空列表，确定哪些社区授予入服资格。Matrix 命令房间由 `commands.room-ids` 单独指定，子房间不会继承或授予 Space 的成员资格。聊天桥接路由只决定消息投递，不决定成员资格；不桥接聊天的接入社区仍参与核验。机器人离开社区、无权限读取或名单请求失败表示无法核验，不能推断全体成员离开。

平台通过 `IdentityMemberships` 提供三种状态：`JOINED`、`ABSENT`、`UNKNOWN`。完整名单或覆盖每个接入社区的明确退出记录可证明缺席，未知社区不能当成已退出；新平台若提供绑定入口，必须同时提供成员监测能力，否则 Host 拒绝注册。`IdentityMembershipCoordinator` 合并当前有效提供方的证据，通过 Identity 的有界后台写队列精确撤销绑定。成员状态由平台会话拥有，关闭会话释放订阅，旧会话结果不能影响新会话。

兑换验证码时，`ABSENT` 提示先加入接入社区，`UNKNOWN` 提示成员资格暂时无法核验；这两种结果不消费验证码，也不计入无效验证码次数。身份服务或数据库故障仍单独报告绑定服务不可用。

QQ 根据可信群消息作者及 `GROUP_MEMBER_ADD`、`GROUP_MEMBER_REMOVE` 保存各接入群的成员事实。任一群有在群记录即为 `JOINED`；所有配置群都明确记录为已退出才为 `ABSENT`；其余情况为 `UNKNOWN`，保留绑定并暂停新登录。首次绑定消息先建立发送者的在群记录，再兑换验证码。

QQ 成员事实保存到 `social/qq-memberships.json`，重连或重启后沿用最后收到的记录。当前没有完整成员列表补查，停机期间遗漏的退出无法自动发现，未观测群的真实状态也无法推断；因此离线退群可能继续保有准入资格。没有成员记录的已绑定玩家，可在任意接入群向机器人发送一次消息恢复证明。完整范围和故障处理见 [QQ 成员资格](qq-bot.md#成员资格)。

Matrix 为资格来源建立与 `/sync` 游标对齐的完整成员快照，再按 `m.room.member` 更新；命令与聊天房间的名单仅用于消息上下文和提及，不参与准入。首次同步不执行历史命令，重启可补查离线期间的退出，具体流程见 [Matrix 成员资格](matrix-bot.md#成员资格)。

## 首次登录

1. 尚未加入社区时，先到 [加入社区](https://mcmik.top/join) 选择并加入。登录拒绝界面和游戏内 `/bind` 提示也提供此入口。
2. 尝试连接 Minecraft 服务器。正版／代理身份认证和已有密码验证完成后的拒绝界面列出各可用平台的完整绑定指令；QQ 使用 `/bind`，Matrix 使用 `!bind`，说明文字跟随界面语言。
3. 在已加入的对应 QQ 群或 Matrix 房间向机器人发送任意一条指令。验证码同时证明 Minecraft 账号控制权和可信平台账号身份，不能凭昵称自报绑定。
4. 机器人确认绑定成功后重新连接。验证码过期也可重连获取新码。在连接配置阶段、已有密码验证之后核验绑定，防止密码验证等待期间绑定失效后继续进入世界。

已有绑定暂时无法核验时，登录界面仍提供其他可用平台的指令，允许改用其他平台恢复准入。

拒绝界面中的验证码在有效期内复用；已消费、取消、过期或被其他命令替换的验证码会重新生成。最多缓存 512 个登录挑战，原始验证码只在内存中展示，数据库仍只存摘要。原版白名单校验允许连接进入配置阶段，绑定门槛在进入世界之前统一执行。登录挑战在后台配置线程处理，不读写 Bukkit 玩家状态；不会在已有密码验证之前签发。

## 玩家流程与单条解绑

```text
/bind <平台>               生成新的单次验证码
/bind qq                   生成 QQ 绑定指令
/bind list                 查看绑定，每行有「解绑」按钮
/bind unlink               打开同一绑定列表，选择一条解绑
/bind unlink <绑定ID>      精确解除自己的某一条绑定；支持自己的绑定补全
/bind cancel <平台>        作废尚未使用的验证码
```

通常只需 `/bind list` 后点击对应行的「解绑」，不必输入绑定 ID。每行展示平台、账号名与解绑按钮；按社区独立绑定的身份另显示社区名称。绑定日期和编号可悬停查看，显示名称重复的记录补充短编号以便区分；命令补全复用相同标签。解绑只处理选中的记录，随后显示剩余绑定。即使手动填写其他人的绑定 ID，也不能解除他人的绑定。

QQ 这类账号级身份在多个群共用一条绑定，解除这一条后，这些群都会失去该账号的绑定权限。真正按群隔离的平台有多条绑定，解除其中一条会保留其他群的绑定。绑定撤销与关闭某个群的聊天路由是不同操作；后者由 Social 路由配置控制。

验证码由密码学安全随机源生成，为 6 位数字（`000000`–`999999`），保留前导零，5 分钟后过期，只能成功兑换一次。有效验证码全局唯一，随机重复时重新生成；只接受完整 6 位数字，两侧空白可省略。同一玩家重新生成同一平台验证码时，旧码失效。数据库只保存验证码的 SHA-256 摘要。

拥有 `group.custodian` 权限的管理员可以使用：

```text
/bindadmin lookup <玩家或UUID>
/bindadmin unlink <绑定ID> confirm
```

查询结果同样提供逐条解绑按钮，控制台额外显示可执行的完整解绑命令。管理员撤销也精确到绑定记录；受影响的在线玩家会收到通知。列表和命令补全不会展示完整外部用户 ID、应用 ID 或群 ID，短指纹仅供辨认来源，不能代替绑定 ID 执行操作。

## QQ 流程与依据

1. 首次连接时从拒绝界面取得 QQ 指令；已在游戏内可执行 `/bind qq` 复制指令。
2. 在机器人接受的 QQ 群内发送 `/绑定 123456`。
3. 同一 AppID、同一 `member_openid` 的其他群消息可以使用已有绑定，无需逐群重复绑定。
4. QQ 侧用 `/我的`、游戏内用 `/bind list` 复查。
5. QQ 侧 `/解绑 确认` 解除当前认证账号的绑定；游戏内可从列表精确选择。

[QQ 官方唯一身份机制](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/api-call-guide.html#唯一身份机制)明确了 AppID 隔离：不同机器人得到的用户、群、频道 openid 不能直接互用。同一 AppID 下，相同 `member_openid` 在多个群共用账号键；不同值仍保持独立，不通过昵称合并，也不自动关联 C2C、频道或可选的跨应用字段。

`/我的` 的 @ 与回复查询，只从当前可信事件的成员标识构造账号键，再查询绑定。正文中的昵称或手写标签不作为身份。语言偏好由绑定的 Minecraft UUID 决定；未绑定时使用命令别名的语言，最后回退到简体中文。

QQ 出站原生 @ 与定向提醒使用与绑定准入相同的成员记录，并按确切目标群核验；提及与历史引用不会自行生成群成员关系。目标在群状态未知、已记录退出或连接尚未就绪时，普通聊天显示文本提及，定向提醒跳过该群。

## 存储与运行

数据位于 `plugins/mik/identity-bindings.db`，使用 SQLite WAL。绑定表以 `binding_id` 为主键，并分别对完整外部身份键和玩家侧命名空间建立唯一约束，保存账号名、作用域展示名及创建／验证时间。

游戏命令和玩家名称刷新通过功能拥有的有界单线程队列写入数据库；玩家对象在主线程读取，反馈回到主线程。身份查询读取原子发布的不可变快照，不等待数据库写锁。功能关闭时停止排队写入并关闭存储。Social 后台调用通过同一绑定服务串行维护事务与快照。

连续 5 次无效验证码会对完整外部身份锁定 15 分钟；失败窗口为 10 分钟。绑定冲突不覆盖既有记录，也不消耗仍可用的验证码。日志不记录验证码、外部标识或消息原文；数据库应随服务器资料限制访问并备份。

## 接入新平台

`IdentityBindingManager` 通过 Bukkit `ServicesManager` 发布。平台注册同时提交入口元数据和权威成员监测能力，身份作用域仍由适配器确定：

```java
IdentityPlatformRegistration registration = bindings.registerPlatform(
        new IdentityPlatform("example", "Example", "/bind {code}"), memberships);

ExternalIdentity identity = new ExternalIdentity(
        new ExternalIdentityKey("example", issuer, verifiedScope, authenticatedUserId),
        displayName, scopeDisplayName);
IdentityLinkResult result = bindings.redeem(code, identity);

// memberships 实现 IdentityMemberships；只有完整核验后才可返回 ABSENT。
// 适配器停用时释放注册租约与订阅；未知状态保留绑定，暂停新登录。
registration.close();
```

`authenticatedUserId` 与 `verifiedScope` 必须来自可信的平台事件，不能由聊天正文自报。平台描述的兑换模板必须包含 `{code}`。平台注册采用租约：相同描述可被多个适配器注册，最后一个租约关闭才隐藏入口；同一平台 ID 的冲突描述会被拒绝。
