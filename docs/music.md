# MIK 音乐模块

`music` 模块统一提供本地音频、NBS 红石音乐、LX Music 自定义音源聚合搜索、
在线音频缓存、音乐唱片和唱片机播放队列。在线功能只包含歌曲搜索、歌词和播放，
不提供歌单导入、发现或详情功能。

## 运行要求

- Paper 26.2
- Plasmo Voice 2.1.13
- PacketEvents
- Java 25

普通音频由 MIK 自己加载 Lavaplayer 并通过 Plasmo Voice 从唱片机位置发送空间
音频。NBS 不经过 Lavaplayer，直接使用 Minecraft 音符盒声音。MIK 自己声明并
加载所需运行时库，不要求安装额外的唱片或 Lavaplayer 附加插件。

## 目录结构

```text
plugins/mik/
├── music/                         # 管理员维护的本地音频和 NBS，递归扫描
│   ├── album/example.mp3
│   └── redstone/example.nbs
├── lxmusic/
│   ├── local/                     # 管理员手工维护的 LX 自定义音源脚本
│   │   ├── 10-primary.js
│   │   └── 20-fallback.js
│   └── remote/                    # MIK 管理的 URL 导入快照
│       ├── sources.json
│       └── remote-<URL 摘要>.js
├── cache/music/                   # 在线音乐完整文件的持久缓存
│   ├── <播放目标摘要>.audio
│   └── <播放目标摘要>.track.json  # 已验证在线曲目的随机候选元数据
├── cache/lyrics/                  # 在线歌词的独立持久缓存
│   └── <播放目标摘要>.json
└── state/
    ├── music-disc.key             # 在线唱片快照的签名密钥
    └── music-playback.json        # 服务器播放次数与最近播放时间
```

各目录职责固定：

- `music/`：本地普通音频和 `.nbs` 文件。可以任意分子目录，MIK 会递归扫描。
- `lxmusic/local/`：管理员手工放置的可信 `.js` 音源。按相对路径排序，文件名前缀
  `10-`、`20-` 等可用于明确聚合和回退顺序。
- `lxmusic/remote/`：通过命令导入的 URL 音源快照。MIK 独占管理，不能手工放脚本。
- `cache/music/`：在线歌曲下载完成后的持久缓存及其曲目元数据。本地文件和 NBS 不会
  重复复制到这里。
- `cache/lyrics/`：在线歌词的独立缓存。歌词不会写入曲目元数据、唱片快照或音乐配置。
  总量固定限制为 256 MiB，超过后按文件最近使用时间淘汰旧歌词。
- `state/music-disc.key`：MIK 自动生成，应随服务器数据备份，不应编辑。
- `state/music-playback.json`：MIK 原子维护的服务器级播放统计，用于榜单和缓存策略。

`lxmusic` 根目录中的脚本不会加载。不存在特殊的 `music/lx` 目录，也没有音乐模块
配置文件。`lxmusic/remote/sources.json` 是 MIK 的内部订阅登记，不是配置文件。

支持的本地扩展名：`mp3`、`m4a`、`mp4`、`wav`、`flac`、`ogg`、`oga`、
`aac`、`opus`、`mka`、`webm`、`nbs`。

## 本地元数据

普通音频按以下顺序读取信息：

1. 文件内嵌标签中的歌曲名、歌手和专辑。
2. Lavaplayer 解析到的播放信息和技术参数。
3. 轻量格式解析器读取文件大小、采样率和时长。
4. 仍然缺失的字段逐个回退，不会因为一个字段缺失而丢弃其他已解析字段。

歌曲名最终回退到格式化后的相对文件名。没有可靠内嵌信息时，歌手和专辑保持为空，
不会猜测 `歌手 - 歌曲名.ext` 这类文件名的字段边界。无法被实际播放后端识别的普通
音频不会进入音乐库。

NBS 支持旧版格式及现代 v1-v6。v6 中索引 16-19 的四种 Minecraft 26 小号音色会按
原版音色播放，自定义音色从文件声明的原版音色数量之后开始。NBS 读取文件头中的
歌曲名、作者和原作者，并在唱片信息和播放提示中分别显示作者与
原作者；歌曲名缺失时才回退到文件名。NBS 文件大小和按速度计算的时长也会显示在
唱片信息中。

普通本地音频还会尝试读取容器标签中的歌词字段（MP3、FLAC、Ogg、M4A/MP4、WAV）。
带标准 LRC 时间戳的内嵌歌词会按播放位置同步；没有时间戳的纯文本歌词会按照已知曲目
时长均匀排布。标签不可读、文件被删除或路径在读取前不再通过安全校验时只会跳过歌词，
不会影响歌曲播放。

添加、删除或替换本地文件后执行 `/music reload`。

## LX 自定义音源

把可信的 LX 自定义音源 `.js` 放到 `plugins/mik/lxmusic/local/`，然后执行
`/music reload`。常见 LX V4 音源只要声明官方 `musicUrl` action，就可以参与
在线搜索和播放；MIK 会先查询其声明的 `kw`、`kg`、`tx`、`wy`、`mg` 平台目录，
再把歌曲信息交回对应脚本解析播放 URL。

脚本也可以声明 MIK 扩展 action `musicSearch`。如果它返回有效歌曲，MIK 优先使用
脚本结果；失败、空结果或畸形结果会回退平台目录。多个脚本和多个通道会并行聚合，
按稳定歌曲 ID 去重。一个音源失败不会丢弃其他音源的结果。

支持歌词的音源可额外声明 `lyric` action。MIK 通过完整的 LX `musicInfo` 请求歌词，
接受原文 LRC、翻译和罗马音；若音源没有该 action 或未返回歌词，会回退到搜索结果中的
安全 HTTP(S) `lrcUrl`，并在可用时读取 `trcUrl` 翻译。歌词加载、网络请求和缓存 I/O
都在后台进行，不阻塞 Bukkit 主线程。

播放期间，当前歌词会显示在与唱片机同世界、65 格范围内听众的 Action Bar 中；翻译
优先显示，缺少翻译时显示罗马音。LRC 的空时间戳行会清空显示，避免间奏继续停留上一句。

`/music search <关键词>` 始终同时搜索本地曲目和在线音源。每个在线渠道保留其返回顺序，
不会因为全局排序而把同一渠道后面的曲目提前。结果采用保序的多路归并：每次只比较各个
渠道当前队首的匹配质量，标题精确匹配优先于标题前缀、标题短语、多词元数据覆盖以及
歌手、专辑等弱匹配；取出一首后才推进该渠道。因此渠道之间的交叉由额外匹配精度决定，
不是固定轮询，也不会破坏渠道内部顺序。匹配信号完全相同时保留渠道首次出现顺序，
缓存状态不参与交叉排序；GUI 只为已缓存曲目标记“已缓存，可直接播放”。

音乐库、搜索结果和唱片机选歌界面都可以在“全部音乐”和“NBS 专区”之间切换。
专区选择会在这些界面之间保留；NBS 专区中的翻页、排序和随机操作只使用 NBS 曲目。

自定义音源连续失败 3 次后会暂停 60 秒，再自动进行可用性检查；单次超时只记为一次
失败，不会立即摘除整个音源，只有连续超时达到同一阈值时才会关闭并重建 runtime。
初始化、搜索和播放 URL 解析的单次等待上限为 20 秒。`/music sources` 会显示每个 runtime 的
通道、action、健康状态、连续失败次数、恢复时间和最近错误。

运行时提供常见 LX 脚本使用的 HTTP、Buffer、MD5、AES/RSA、随机字节、zlib 以及
全局、`window` 和 `lx` 上的 `setTimeout`、`setInterval`、`clearTimeout`、
`clearInterval`。脚本不能访问 JVM host class、本地文件或 native API，但可以发起
外部 HTTP 请求，因此只能安装可信脚本。

完整扩展格式见 [lx-custom-source-extension.md](lx-custom-source-extension.md)。

## URL 音源导入

管理员可以导入 HTTP(S) URL 或绝对 `file://` URL：

```text
/music sources import https://example.invalid/lx-source.js
/music sources import file:///srv/mik-sources/lx-source.js
```

`file://` 后必须是绝对路径。MIK 会先在隔离 runtime 中初始化并检查脚本，再复制为
`lxmusic/remote/remote-<id>.js` 快照；不会直接执行原路径中的文件。在线 URL 也只
执行本地快照，因此更新失败时仍可继续使用最后一次成功版本。

订阅会在以下时机检查更新：

- 服务器启动。
- `/music reload`。
- `/music sources update`。
- 每 6 小时自动检查。

HTTP(S) 使用 `ETag` 和 `Last-Modified` 条件请求。只有脚本内容变化且新版本通过
初始化检查后，MIK 才原子替换快照并重建 LX runtime。下载失败或新版本无效时保留
旧快照，并在 `/music sources` 中显示错误。

使用 `/music sources remove <remote-id>` 删除订阅和它的受管理快照。命令参数会
补全当前订阅 ID，不会删除 `local/` 中的脚本，也不会删除 `file://` 指向的原文件。

## NBS 红石音乐

支持 legacy v0 和版本 1-5，包括：

- 速度和完整歌曲时序。
- 图层音量、单音力度、声像和微调音高。
- 有限循环和无限循环。
- 16 种既有音符盒乐器。
- 普通、斑驳、锈蚀和氧化四种 Minecraft 新小号音色。

播放音量由图层音量和单音力度线性相乘。任一分量为 `0%` 时静音；很低但非零的
音量不会被截断或人为抬高。ID 16-19 分别映射四种小号。声明 16 种原版乐器的文件
也可以通过自定义乐器名称或采样路径中的英文、简体中文或繁体中文小号名称识别。
自定义采样文件本身不会加载，未知自定义乐器回退为竖琴。

详细格式和边界见 [nbs-music.md](nbs-music.md)。

## 在线音乐缓存

在线歌曲会把同一条 HTTP 响应渐进写入 `plugins/mik/cache/music/`，并在格式探测所需
的首批数据到达后开始解码，不再等待整首下载完成。缓存具有以下性质：

- 相同播放目标可跨服务器重启复用。
- 同一目标的并发播放共享一次下载。
- 播放读到当前下载末尾时会等待后续字节，不会把临时 EOF 当作歌曲结束。
- 临时文件下载成功后才原子替换正式缓存。
- HTTP 错误、超时、空响应、超限响应和中断会停止等待中的解码并清理半文件。
- 正在加载或播放的文件持有租约，不会被清理或配额淘汰。
- Lavaplayer 无法识别的缓存会失效，下次播放重新下载。
- Lavaplayer 成功识别后会原子登记曲目元数据，使完整缓存可在重启后参与随机选择。

旧版本创建且尚无曲目元数据的 `.audio` 仍可照常命中播放；对应曲目下一次成功播放后
会自动补齐元数据并加入随机候选。

单首上限固定为 512 MiB，总配额固定为 8 GiB，最多同时下载 4 首，单次下载超时
10 分钟。达到配额后会为每个非活跃缓存计算保留分：播放次数采用对数权重，最近播放
或缓存访问时间按 30 天尺度衰减，并对大文件增加存储成本。低分条目优先淘汰，因此
高频、近期使用且较小的歌曲更容易保留，长期未用、低频或较大的歌曲更早清理。没有
曲目元数据或历史统计的旧缓存仍以文件访问时间参与排序。如果活跃文件占用导致无法
释放足够空间，新下载会失败而不会突破配额。

服务器播放次数在一次有效播放结束时结算：自然播放完成一定计数；手动停止、唱片替换、
区块卸载或服务器关闭等非失败终止，只有实际进度达到已知曲目时长的 70% 才计数；时长
未知时至少播放 30 秒。下载、搜索、拿取唱片、加入队列、加载失败和短暂试听不计数，
每次播放最多计一次。统计在后台原子写入，并在服务器关闭时刷新。

## 命令

玩家命令：

- `/music`：打开本地曲目和已完整缓存在线曲目的音乐库。
- `/music search <关键词>`：同时搜索本地曲目和所有可用在线音源。
- `/music page <页码>`：切换当前音乐视图页码。
- `/music random`：从本地曲目和已完整缓存的在线曲目中获得一张随机唱片。
- `/music randomplay`：在 50 格内最近的已加载唱片机播放随机本地或缓存在线曲目。

管理员命令：

- `/music reload`：异步重载本地目录、URL 订阅和所有 LX runtime。
- `/music sources`：查看本地脚本、远程订阅、能力和健康状态。
- `/music sources import <url>`：导入 HTTP(S) 或绝对 `file://` 音源。
- `/music sources update`：立即检查全部远程订阅。
- `/music sources remove <remote-id>`：删除一个远程订阅和受管理快照。
- `/music cache`：查看在线缓存文件数、占用和配额。
- `/music cache clear`：清理在线缓存；正在播放的文件会在释放后删除。

命令中的文件 I/O、网络请求和脚本初始化不会阻塞 Bukkit 主线程。
`/music reload` 会分别发布本地音乐库、URL 订阅和 LX runtime 的结果：全部成功时
显示成功，至少一部分成功时显示保留旧状态的部分成功，三部分全部失败时显示失败及
各自原因。一个损坏的本地文件或失效订阅不会撤销其他部分已经成功发布的状态。

## GUI 和唱片机

音乐浏览悬浮列表每页显示 18 首：

- 曲目名称优先使用元数据歌曲名。
- 选中曲目时，独立详情浮窗直接显示格式、歌手、专辑、文件大小、采样率、时长、
  在线缓存状态、服务器播放次数和最近播放时间，不使用遮挡场景的悬浮 Lore。
- 排序按钮依次切换默认顺序、播放排行榜和最近播放；排序对当前音乐库或搜索视图生效，
  切换后回到第一页。播放排行榜按服务器播放次数降序，同次数时按最近播放时间排序。
- 左键获得实体音乐唱片，右键直接在最近唱片机播放。
- 搜索期间显示加载状态；空结果、全部失败和部分失败均有独立状态。
- 旧异步搜索结果不能覆盖玩家后发起的新搜索或新页面。

空手潜行右键唱片机打开控制场景。场景不生成固定标题：唱片作为仅该玩家可见的虚拟
实体悬浮在实际唱片机上方，播放时旋转、加载时浮动、停止时静止；曲名、播放状态、
MIK 曲目的当前播放进度（进度条、已播放时间和总时长）及有限的曲目元数据
显示在靠近玩家一侧的透明信息层；进度按整秒更新，未知总时长的曲目仍显示已播放时间。
每台唱片机使用独立的
运行期播放列表，每页最多 12 首；列表在所有播放模式下都可见、可排序和编辑：

- 左键立即播放并保留在列表中。
- 右键只从队列移除。
- Shift+左键前移，Shift+右键后移。
- “选择音乐”可搜索本地或在线曲目；左键加入列表，右键立即播放。
- “清空队列”不影响当前正在播放的曲目。

每台唱片机的播放范围默认保持为 64 格，可在控制场景中调节到最多 256 格。左右键每次
粗调 32 格，滚轮每次细调 4 格；修改会立即应用到正在播放的普通音频、NBS 音乐和歌词
范围，并持久保存在该唱片机上。

播放模式按钮依次切换“列表循环”“单曲循环”“列表随机”“音乐库随机”。列表循环按当前
顺序播放并在末尾回到第一首；单曲循环在自然结束后重复当前歌曲，但手动点击“下一首”
仍会切到列表下一首；列表随机只从当前列表选择，并在列表超过一首时避免连续重复；音乐
库随机从当前动态音乐库（本地曲目和已缓存在线曲目）选择，并排除当前歌曲。失败、手工
停止和取消不会错误触发后续播放。“停止并弹出”会停止播放、取消后续任务并弹出唱片，
也适用于控制面板中显示的 Minecraft 原版唱片。

实体 MIK 唱片和 Minecraft 原版唱片都可以通过漏斗、投掷器等原版容器机制装入唱片机；
正对唱片机的发射器也可以装入两类唱片。MIK 唱片只有在曲目验证并成功启动后才从来源
容器扣除，失败时唱片保留在来源中。服务器内部生成的临时唱片不能被自动化设备转移；
原版唱片继续使用 Minecraft 原生的容器装载行为。

控制场景仅允许同世界且距离唱片机不超过 8 格的玩家操作，并遵循所有悬浮菜单统一的
离开打开位置 3 格即关闭规则。唱片机被拆除、区块卸载
或玩家离开范围后，已打开的场景不能远程修改状态。区块卸载时播放停止；区块重新加载或
服务器重启后，仍在唱片机内的当前格式唱片会恢复播放。

播放列表和循环/随机顺序是运行期状态，服务器重启后清空。唱片机另有持久化到区块实体
的“用途模式”：音乐模式在音频达到可解码条件后尽快开播；音游模式在没有实际参赛玩家前保持
等待，不创建声音后端。点击“开始游戏”以及浏览玩法、难度都不会开播；首位玩家确认难度并
进入游戏场景后，才等待整首歌曲缓存、离线节奏分析并从歌曲起点同步开始声音、播放时钟和
完整谱面。切换用途模式会立即重建当前 MIK 唱片的播放状态：切到音游后马上停止声音并等待
参赛玩家，切回音乐后才正常开播。两种模式使用独立的控制区：音乐模式显示播放队列、播放顺序、下一首和清空
队列；音游模式隐藏这些听歌功能，改为“选择音游歌曲”“开始游戏”和“完整延迟测试”。
原来的“添加所有歌曲”入口及其控制
动作已经删除。在线实体唱片保存经过签名的受限播放快照，避免同 ID 歌曲被另一个音源目标覆盖。

两种用途不是两套播放器：持久化的用途模式只选择播放生命周期和控制界面，唱片解析、完整缓存、
音频/NBS 后端及节奏提取仍由共享服务负责。音乐模式立即取得听众并播放；音游模式只登记等待中
的曲目，直到首位玩家真正进入游戏才取得参赛租约并启动后端，最后一位玩家退出后又回到等待。
这样既不会让菜单浏览误触发播放，也避免音乐和音游状态各自维护一份互相漂移的歌曲时钟。

### 自动节奏游戏

唱片机播放 MIK 曲目时，控制场景中的“开始游戏”会先选择玩法，再选择难度并进入
独立的空间操作场景。下落式的四轨从左到右为 `1 · 2 · 3 · 4`，读取客户端实际绑定的
热栏第 1-4 格动作。入场时服务器会把选中槽切到第 9 格；每次收到第 1-4 格输入后都会在
同一个事件中取消槽位变化并立即切回第 9 格，因此同一轨可以连续输入且不会真的切换
手持物品。第 5-8 格同样会被切回但不参与判定，退出玩法后恢复入场前的选中槽。
环向来袭不接管热栏，玩家转动视角对准从四周飞来的方块，左键或右键均可命中。
星域点击同样使用左右键，但目标固定在以入场眼睛为中心的三维球域中，除水平 360° 外还会
进入高处、低处以及近、中、远深度层；四点接近笼收拢到命中核的时刻就是点击时机。
部分相邻拍点会形成弧形视角轨迹链：跟随移动星体转动准星，并在每个发光检查点到拍时点击。
Minecraft 对空瞄准没有可靠的通用鼠标松开事件，因此轨迹链不要求长按；连续跟随只作视觉引导，
实际得分和 Miss 仍只由这些离散检查点决定。
若玩家修改了 Minecraft 键位，则界面显示并使用这些动作的新绑定键。按下玩家实际绑定的
下蹲键约 600 ms 才会退出，ActionBar 会显示进度，短按不会误丢失整局；下蹲不参与谱面判定。
进入游戏后玩家的位置会暂时锁定，但仍可
转动视角；传送、受伤、死亡、退出、歌曲停止或唱片被替换都会安全结束本局。

四档难度从同一份共享节奏提取结果按玩家独立投影，不会重复解码或分析歌曲：

| 难度 | 最大音符密度 | Perfect | Great | Good | 得分倍率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 轻松 | 约 2.0/s | ±120 ms | ±200 ms | ±300 ms | ×0.80 |
| 标准 | 约 4.0/s | ±90 ms | ±150 ms | ±220 ms | ×1.00 |
| 困难 | 约 5.9/s | ±70 ms | ±120 ms | ±165 ms | ×1.15 |
| 专家 | 约 7.7/s | ±55 ms | ±90 ms | ±125 ms | ×1.35 |

普通音频不会边播放边提取节奏：本地文件可立即进入分析，在线歌曲则先等待整首缓存
完成，再由独立后台解码器快速读取完整音频。第一阶段使用近似对数间隔的八频带滤波器组、
对数能量通量、动态中位数/MAD 阈值、局部峰值和最小触发间隔，同时生成高召回候选与可靠
重音锚点。相邻频带的前帧轨迹最大值会压低人声、弦乐颤音造成的伪起音，瞬时通量与较慢的
宽带包络则共同覆盖鼓点、钢琴以及柔和渐起的有调声音。候选和锚点只共享一次 PCM 滤波，
再应用两套阈值策略，不会为高召回率重复执行最重的 DSP。
第二阶段先由真实候选间隔投票生成少量速度假设，再精评周期、相位、候选覆盖率和强弱结构，
不再遍历整个 BPM 范围。可跟踪周期为 110-2000 ms，并在最佳粗略周期附近细化到 0.5 ms，
因此 40 BPM 的慢拍、125 ms 的 DJ/十六分细分以及 200-250 ms 电子鼓点都不会仅因速度先验
折叠成半速。跟拍器同时比较直拍与两步摇摆；短时区间会在实际速度/密度变化处重新分段，
固定网格证据不足但相邻间隔呈连续渐快、渐慢或稳定长短拍时，只保留真实起音而不强制量化
或补拍。只有周期、相位、网格覆盖率和摇摆强弱支持都达到阈值时才采用拟合结果；证据不足
时保留可靠锚点和独立强瞬态，只有低强度非周期噪声仍保持为空。该流程不先猜测“动漫、
古典、流行、打击乐或 DJ”等曲风，而是统一使用声学瞬态、周期与局部连续性证据。方块并非由
一个固定频率的计时器生成：稀疏主歌只保留实际稀疏重音，密集高潮和
变速段会随候选密度及重新估计的速度增加或改变；若原曲本身稳定，则保持稳定而不随机
制造变化。缓存与加载使用异步 Future；整曲分析最多同时运行两个任务，并让虚拟线程承担
等待解码帧的阻塞部分，CPU 密集的解码/DSP 仍受固定并发上限约束，不会占用 Bukkit 主线程。
完整谱面生成成功后才一次性发布，期间不会暴露半成品。NBS 则按音符、和弦重音、
速度变化和循环元数据生成精确时间轴。难度投影只让小于最小音符间隔的相邻瞬态互相竞争，
同时为 20 ms 检测窗口保留小幅量化容差；因此标准难度下稳定的 250 ms 节奏即使被检测成
240/260 ms 交替，也不会每隔一个方块被误删成半速。观察到完整稳定范围后保留其中较强者，
不再因为“窗口末端强拍”额外制造接近双倍的空档。
每位玩家拥有独立的判定、连击、得分和难度偏好，多名
玩家可以同时游玩同一台唱片机而互不覆盖状态。

音游模式的唱片机控制页只提供一个“延迟校准”入口，无需放入唱片或播放歌曲；玩法选择页
不再重复提供校准或歌曲精调。完整测试需要玩家已连接并启用 Plasmo Voice，并自动连续执行
四个阶段：第一阶段使用 Minecraft `playsound`，第二阶段使用 Plasmo Voice 连续音频流，第三阶段
完全静音并按任意 1-4 键，第四阶段使用同一静音画面改为左键或右键点击。完整测试始终使用两小节 4/4 的
恒定节拍：75 BPM、每 800 ms 一拍、每轮 6.4 秒。所有阶段使用完全相同的节拍，不再随机选择
律动或插入变长间隔，避免节奏变化影响玩家跟拍和不同通道延迟的比较。
进入测试先用 2 秒显示说明，各阶段切换保留 1.5 秒，全部完成后保留结果 3 秒再自动返回。

Minecraft 和画面阶段先示范第一小节恒定节拍（3.2 秒）；声音阶段提示先听，静音画面阶段提示
先完整观察一次方块过线，并明确要求暂不操作。此时
所有按键都被明确排除在估计器之外；后续节拍保持相同间隔，因此无需重复等待。示范结束后
从短句第一拍重新开始，且边界只发出一次鼓点，界面切换为“现在跟打”后才累计样本。Plasmo
Voice 阶段会先跑完一轮连续音频以确认传输和循环边界稳定；若发送器意外中断，该阶段会回到
试听并重新对齐整段短句，不会拿已经错相的鼓点继续计算延迟。

输入只会匹配网络补偿后相距不超过 400 ms 的最近未采样 Cue，同一 Cue 最多记录一次。Minecraft
鼓点记录实际调用发送时刻，Plasmo 记录实际生成并交给发送器的音频帧，静音画面优先记录浮动菜单
真正提交目标传送包的时刻；计划时刻只作为提交前的短暂兜底。呈现账本允许音频线程与主线程乱序
交付，并按实际时间淘汰旧 Cue，避免掉帧后把一次输入误配到相邻节拍。

每个测量阶段先进入低置信度的自适应期，但不再固定丢弃前 4 拍，也不必等待整段 6.4 秒短句
结束。当前短句达到一半覆盖且内部 MAD 稳定后就立即参与统计；首段使用半权重，下一段中心保持
稳定后取得完整权重。若玩家还没跟上，适应期会自动延长，早期不稳定点击不会污染稳定尾段。

适应完成后也没有固定的 30 次机会或“本轮失败”。画面、Minecraft 鼓点和 Plasmo 鼓点都会在
当前阶段持续生成，所有不同拍点的点击不断加入同一个估计器。算法只保留最近 6 段短句，选择
最新连续稳定段，再以中位数和 MAD 动态排除异常值，并对过滤后的全部点击求核心均值；至少取得
10 个内点后还会检查段间漂移，
以及由稳健标准差推导的 95% 估计半径。只有不确定度降到 25 ms 内且中心没有漂移时才进入下一
阶段。稳定玩家通常约 8-10 秒即可完成一个采样阶段；异常点击与漏拍只会让当前阶段多收集一些
证据，不会清零、重播说明或要求玩家从头开始，先前乱拍也会随滚动窗口自动淘汰。

采样数、目标内点数、MAD、置信半径、丢弃次数、实时 Ping 和五项校准值都只供内部算法与
测试使用，不出现在玩家校准界面或完成提示中。采样时界面只显示“正在跟随节奏”或“正在确认
稳定性”，同时保留当前阶段、操作提示和试听倒计时，避免技术诊断信息干扰玩家跟拍。

测试开始后，该玩家会从所有 MIK 唱片机的普通音频与 NBS 听众中临时排除，已经播放中的
歌曲不会干扰测试，但其他附近玩家仍照常听歌。过滤只作用于唱片机后端，测试自身的阶段提示
音仍会播放。Plasmo 阶段合成一段与 20 ms Opus 帧整齐对齐的 48 kHz 单声道鼓点及静音间隔，
使用不插入结束帧的提供器由同一个发送器无缝循环；玩家需要多久，它就稳定播放多久。鼓点使用
只发送给校准玩家的 Direct Source，并在首个 UDP 音频帧前主动发送声源信息，避免玩家声源的
自我排除规则和首拍初始化竞争，也不会把逐拍创建声源的启动抖动混进测量。
完成、取消、菜单关闭、受伤、传送、死亡、掉线或插件关闭都会关闭校准声源并通过同一租约
恢复听众资格。Plasmo Voice 在创建声源、启动发送器或读取进度时抛出异常也只会安全结束当前玩家
的测试、显示可重试提示并记录服务端日志，不会终止节奏游戏的全局 tick；启动到一半的发送器与
声源同样会逐项清理。

两个声音阶段分别生成 Minecraft/NBS 与 Plasmo Voice/普通音频的判定固定偏移；每个声音估计
各自减去同一个键盘画面估计后，公共的反应与输入耗时会抵消，所得差值成为该通道的动画延后或
预进量。正式开局会根据实际播放后端自动选择对应结果，而不是把两种声音路径平均为一个值。
鼠标画面估计减去键盘画面估计得到 `pointerInputDeltaMillis`；下落式不应用它，环向来袭和
星域点击只把它加到判定偏移，绝不移动动画时钟。判定值限制在 -250 到 +350 ms，动画值限制
在 -350 到 +350 ms，鼠标差值限制在 ±200 ms。五个结果写入玩家持久数据，
重新进服仍然有效；右键校准入口可完整重置，并先取消仍在运行的旧测试，防止旧会话随后把结果
写回。只有五个结果同时存在且全部处于合法范围，玩家才算完成校准；部分写入或损坏数据会要求
重新测试，不会被静默截断后用于判定。旧版
普通音频/NBS 微调键不再读取、迁移或清理。未校准时“开始游戏”仍可点击，但会先打开空间
悬浮确认页，说明测试用途、Minecraft/Plasmo Voice/键盘视觉/鼠标视觉四个阶段、自适应时长和语音要求；玩家
可选择“开始完整测试”或“暂不进行”。确认后会再次验证玩家、唱片机和校准状态，再进入独立
测试场景。确认页沿用悬浮菜单的锚点、空间布局和返回层级，不调用 Minecraft 原生 Dialog API。
服务层在进入玩法选择和正式开局前仍各自复查，因此确认页只是更好的引导，不能被用来
绕过强制校准。重置后必须重新完成整套测试才能再次游玩。

延迟测试入口、玩法选择入口和难度确认后的正式开局都会读取当前服务器 RTT；超过 350 ms 时直接
拒绝进入，并显示当前值与上限，避免在已知无法稳定公平判定的网络条件下生成校准结果或开始计分。
已经进入测试或音游后仍按每秒一次的独立节奏监测原始 RTT：单次超限只警告，不会因一个 Ping
尖峰立刻丢失进度；连续 3 次采样都超过 350 ms 才安全结束当前会话。任意一次恢复到上限内都会
清零连续计数。高延迟退出不生成自然结算，也不会保存尚未完成的校准结果。

正式判定会把这项固定的设备、显示与输入偏移和玩家当前 Minecraft 往返延迟相加。每局仍会
按一秒的独立时间间隔采样实时 Ping，以滚动中位数和平滑处理动态跟随稳定的网络变化；
同一服务器 Ping 读数不会被每 tick 或每次点击重复塞满窗口，单次尖峰也不会直接移动
判定窗口；在连续超限确认期间，内部异常值最多按 500 ms 处理。按键或鼠标输入按合并后的延迟回溯到玩家实际看到
节拍并操作的时间；自动 Miss 使用同一时钟，并额外保留网络抖动与主线程 tick 的安全余量，
避免合法输入仍在传输途中就被判失败。校准过程中只扣除实时网络部分，不重复套用旧校准值。
游戏状态栏会分别显示当前合并判定补偿与动画偏移。

音符运动不套用网络往返补偿，因为画面数据到客户端时已经自然经历下行延迟；它只应用当前
播放通道在四阶段测试中得到的音画偏移。正值会延后动画、负值会预进动画，使判定线与实际听到的声音重合。
三种玩法共享判定和动画时钟。下落式、环向来袭、星域点击和校准场景仍在显示端预进一个服务端 tick，
用于抵消浮动菜单任务先于节奏任务执行所产生的固定一帧迟滞；该预进不会修改拍点、输入判定
或自动 Miss 的时间，并已包含在校准差值的测量中。

提取层只发布播放相对时间、强度、声像、音色倾向和稳定签名，不包含方向键或玩法对象；
播放器只向玩法公开只读节奏轨道。每种玩法都在玩家加入后才选择共享拍点：下落式把它们
投影为四个逻辑轨道并绑定热栏 1/2/3/4，环向来袭投影为水平圆周上的移动方块，星域点击则把
强度、声像和音色特征确定性投影为球形体积中的静止命中核并使用瞄准点击，
因此后续模式也能直接复用同一份提取结果，而不需要重新解码歌曲或修改音频/NBS 提取器。

代码职责同样沿这条边界拆分：`rhythm.analysis` 只生成共享拍点，`rhythm.playback` 只提供参与租约
和只读歌曲时钟，`RhythmGameSession` 统一负责判定与分数，`RhythmSpatialPath`、
`RhythmSpatialArena`、`RhythmSpatialSlider` 分别负责空间布局、可玩体积和轨迹几何，
`RhythmSpatialGameplay` 集中维护单局空间呈现、遮挡复检、Slider 转移与缓存清理。
`RhythmGameService` 只协调 Bukkit 输入、菜单渲染和这些组件，不再直接持有空间玩法内部缓存。

三种玩法使用真实 Java 子包，而不是只在文件名上区分：

```text
rhythm/mode/
├── falling/   # 四轨固定布局与下落几何
├── radial/    # 环向路径生成
└── spatial/   # 3D 路径、场地、配置、Slider 与单局运行态

rhythm/input/  # 环向和 3D 模式共用的网络时间戳与鼠标射线选择
```

`mode` 下严格只有玩家能够选择的三种玩法。共享 pointer 能力不是第四种模式，因此放在
`rhythm.input`；它不依赖任何具体玩法，以后增加新的鼠标玩法时仍可复用，而不会反向依赖
星域点击实现。`rhythm` 根包只保留共享谱面、判定、延迟与 Service 适配层。

四条轨道横向排列并显示底部判定线，只对当前玩家可见；音符从上方向固定目标下落，
越过判定线后继续短暂下沉，使提前、命中和错过更容易辨认。目标会按 Perfect、Great、
Good 和 Miss 改变材质并给出短促声音反馈。入场动画期间不会开始扣分。

“环向来袭”的方块使用绝对世界坐标，以玩家身体为中心从水平 360° 外圈向内飞行，
不再收拢到菜单面板中央。首个方块从玩家当前视线前方进入；相邻节拍的来袭角度最多变化
28°，角速度每拍最多再变化 8°，随机目标维持 3-6 拍后才逐层转向，避免突然跳到背后。
每个方块带有两层向外延伸的轨迹残影，接近判定时会逐步发亮，越过时变红。玩家只需把
准星对准方块并按左键或右键；点击事件按服务器 tick 去重。射线选取使用扣除网络往返和
动画偏移的画面时钟来重建玩家实际看到的方块位置，计分则另用网络延迟与个人固定偏移合并后的
判定时钟，因此校准后可点击几何和画面仍保持一致。命中后方块在原世界位置爆出仅该玩家可见的粒子与旋转闪光。
点击空处不提前吞掉节拍，未命中的方块仍由统一的超时逻辑判为 Miss。游玩期间会拦截
对应的方块、实体交互，避免瞄准操作误挖、放置或攻击真实世界内容。

“星域点击”开局前会从玩家眼睛向多组水平角、俯仰角和深度射线预检；至少需要两个俯仰带和
两个深度层，否则在取得播放参与租约前拒绝开局并提示寻找开阔位置。目标方向受球面转向速度、
加速度和累计水平转向约束，第一颗始终位于入场视线正前方，相邻目标最多跨一个深度层。
目标方向遇到障碍时会先缩短深度，再按固定的小角度序列绕开；仍无法呈现或未获得最小反应提前量
的目标直接忽略，不计 Miss。

每颗目标都有两颗对向接近卫星，当前最早目标补成四点笼；当前到下一目标之间还有四个星轨点，
前四颗用不穿墙的序号标明顺序。命中球半径按距离换算为固定屏幕角，因此远目标不会暗中缩小
判定范围。点击包会认领网络线程记录的不晚于点击的最近 yaw/pitch，再用单调播放时钟分别重建
画面位置和计分时刻；缺少精确视角包时才回退 Bukkit 视角，并只增加 1° 的粗略输入宽容。
射线重叠时先比较归一化准星偏差，再比较时间误差、谱面时间和 id；空点保持中性。

间隔、转角和空间可见性合适的相邻目标会确定性生成三维轨迹链。浅蓝曲线先静态预读，只有成功
点击起点后才生成轨迹头；它最早在起点 Perfect 窗口结束后开始沿球面方向和平滑深度曲线移动，
并在终点 Good 窗口前留出一个服务器 tick 的稳定时间。走过段与待走段使用不同颜色，ActionBar
显示视线是否跟上；跟随状态只作显式引导，不参与隐藏计分。

曲线必须保留两端完整 Good 窗口、至少 220 ms 移动和 50 ms 终点稳定时间；超过 1400 ms、转向
不合理或被遮挡时自动退回普通星轨。遮挡按弧长自适应采样，并在游玩中每 250 ms 节流复检；端点
被忽略、轨迹被遮挡或检查点 Miss 都会清除活动链，不会从半程继续。连续轨迹最多三段，之后插入
普通恢复跳点。所有降级都不改变原检查点位置、判定窗或得分，后续目标仍可独立命中。

三秒准备倒计时会在正前方播放一个不计分的四点笼示范。正式开始后分数、连击、近期判定和
离屏目标的八方向寻回箭头显示在 ActionBar，玩家转到初始面板背后也不会失去关键信息。
静止命中核在世界位置没有变化时不重复发送传送包；世界序号关闭穿墙显示。自然结束后打开独立
结算页，保留不可变成绩快照并显示总分、准确率、最大连击、Perfect/Great/Good/Miss 和平均
Early/Late 偏差。主动退出、受伤或传送只执行安全清理，不误弹自然结算。

基岩版会把玩法与难度选择自动转换为客户端原生表单；实际游戏场景保留空间虚拟实体和
实时玩法输入，不转换为会占用输入的表单。音游模式下，没有玩家进入时唱片机显示“等待玩家”
且不会发声；首位玩家确认玩法与难度、真正进入游戏场景后，整首歌曲缓存和节奏分析完成前
显示“准备中”。最后一名玩家退出、掉线或离开场景时，歌曲时钟和声音立即停止，唱片机回到
“等待玩家”；已完整提取的谱面可供下一局从歌曲起点复用。
每位玩家真正进入玩法后还会从当前播放位置预留约 3 秒缓冲，再显示第一批方块；中途加入者
不会突然面对已经贴近判定线的方块。
游戏空间会按玩家自己的阶段显示中央悬浮层：整曲仍在缓存或分析时显示“正在准备完整谱面”，
声音时钟开始后依次显示 `3 · 2 · 1` 并播放逐级提示音，随后短暂显示“开始”。正式游玩时，
Perfect、Great、Good、Miss 和当前连击会在中央短暂反馈；左上状态区同时保留歌曲时间、
分数、难度、玩法和动态延迟信息。中途加入玩家的倒计时仅对自己生效，不会遮挡或重置其他玩家。
NBS 本身会先完成文件解析和精确谱面提取，两种用途模式都从同一零点开始；中途加入的玩家
会先等待约 3 秒，再显示自己的方块。

玩家停留在玩法或难度选择页时，其他玩家看到的头顶状态仍是普通“菜单中”；真正进入
节奏游戏或延迟校准场景后会立即切换为本地化的“节奏游戏中”，退出游戏、歌曲结束或界面关闭后由
菜单生命周期自动恢复或移除，不会留下失效的 Display。

NBS 声音发射与公开给谱面的播放位置由同一个有界逻辑时钟驱动。服务器长时间卡顿时，两者
会一起丢弃过旧的调度债务，而不会出现声音只追赶一小段、方块却按墙钟跳到几十秒之后的永久
错拍。无限循环 NBS 的已判定拍点、方向缓存和玩家谱面会按滑动时间窗清理，长时间游玩时内存
与得分状态不会再受 32 位计数上限影响。

## 安全和资源边界

- 单个自定义音源脚本最大 2 MiB。
- 最多登记 128 个 URL 音源订阅。
- 自定义音源 HTTP 请求和响应最大 4 MiB，action 返回最大 2 MiB。
- 每个脚本最多 16 个并发 HTTP 请求。
- 单次聚合搜索最多接受 200 首歌曲。
- 单个 NBS 最大 16 MiB、4096 图层、0.01-655.35 tick/s、总计 20 万音符。
- 在线音乐依赖管理员安装的第三方音源及其网络可用性。
