# 账号密码保护

`/password` 或主菜单「个人设置 → 账号安全」管理自己的密码。新人和正式成员自愿设置；设置后每次连接都需要验证。Moderator（管理）与 Custodian（维护者）必须设置密码才能进入世界。

未设置密码的玩家会在[日常随机提示](guidance.md#日常随机提示)中收到设置建议，点击提示填入 `/password`。设置密码后停止展示该提示。

## 登录与身份

密码验证在 Paper 的连接配置阶段完成，验证成功后才进入世界。未验证的连接不能操作世界、执行游戏命令、打开空间菜单或确认网页登录，也不会产生正常入服后的有效游玩记录。关闭表单或两分钟内未完成验证会断开连接。

没有密码的普通玩家直接入服；没有密码的管理或维护者不能自行首次设密，需要由有权限的管理者执行重置。现有管理员、刚获任命的管理员与手动加入管理组的账号遵守同一规则，没有旧账号豁免、默认密码或宽限期。OP 账号同样受到强制保护。

任命照常交付 LuckPerms。身份生效时，如果在线账号没有密码，将被断开连接，之后需要重置密码再登录。密码状态不改变身份、任期或投票结果。辞任或罢免完成后，原密码保留，由本人决定是否移除。

验证状态只属于当前连接，不按 IP 记住登录。密码验证失败有账号、来源与全局限流，重连不能清空失败次数。关闭插件、认证启动失败或不安全的热重载会请求关闭服务器，避免认证停用后遗留的 LuckPerms 权限继续开放；应通过正常重启更新插件。

## 验证失败与冷却

登录、修改或移除密码、管理者重置时验证自己的密码，共用同一个账号失败计数。同一账号同时只允许一个验证任务，排队前即占用名额，取消连接不会提前释放仍在计算的任务。

前 4 次密码错误可以重试；第 5 次错误后等待 30 秒，后续每次错误翻倍，最高 **48 小时**：

| 累计错误次数 | 本次冷却 |
| --- | --- |
| 5～8 | 30 秒、1 分钟、2 分钟、4 分钟 |
| 9～12 | 8 分钟、16 分钟、32 分钟、64 分钟 |
| 13～16 | 128 分钟、256 分钟、512 分钟、1024 分钟 |
| 17 | 2048 分钟（约 34 小时） |
| 18 及以后 | 48 小时 |

冷却期间拒绝验证并显示剩余秒数，重连、换 IP 或改走其他入口不能绕过账号冷却；被拒绝的请求不会延长冷却或消耗全局验证额度。没有永久锁定状态。失败历史在最后一次冷却结束 24 小时后失效；验证成功即清除该账号的历史。

管理员成功重置密码后立即清除目标账号冷却，新密码可以正常验证，旧密码验证任务晚到也不能重新施加冷却。重置不会清除来源 IP 的速率限制。

每个来源 IP 最多突发 20 次提交，此后每 3 秒恢复一个名额；全服最多突发 120 次提交，此后每 0.5 秒恢复一个名额。来源限制独立于账号失败次数，共享网络中一名玩家输错不会直接给其他账号施加长冷却。已处于账号冷却、同账号并发或被来源限流拒绝的提交不会占用全局名额。任务队列和限流状态均有容量上限。

以上计时使用单调时钟，状态仅保存在内存中，正常重启会清空。等待过长或忘记密码时，联系有权限的管理者执行 `/password reset <玩家>`。

## 玩家操作

| 命令 | 行为 |
| --- | --- |
| `/password` | 打开账号安全页 |
| `/password set` | 无密码的普通玩家首次设密 |
| `/password change` | 验证当前密码后修改密码 |
| `/password remove` | 验证当前密码并检查保留要求后移除密码 |

密码通过独立的原生表单输入，不作为命令参数，不进入普通聊天、菜单聊天草稿或社交转发。当前原生文本框不提供密码遮罩，输入会显示在本人屏幕上。

自行设置的密码使用 10～128 个 Unicode 字符，支持空格和粘贴。系统统一采用 NFC 规范化，不去除首尾空格、不截断输入，并拒绝明显弱密码、玩家名和常见弱密码片段。不要复用其他服务的密码。

设置和修改需要重复确认新密码。失败不会先清空旧密码。密码无法查询或找回原文；忘记密码时联系有权限的管理者重置。

## 管理申请

`/gov nominate` 和治理菜单的报名入口共用规则：提交新申请前必须已经设置密码。未设置时，菜单提供「先设置密码再报名」入口；设置后仍需本人确认报名。

管理身份、进行中的管理申请或尚未交付完成的任命都会禁止移除密码。修改、重置始终以新密码替换旧密码，不会清空密码，也不会撤回申请或更改选票。申请撤回、失败或终止后，且不再有管理身份或待交付任命时，可以自行移除密码。

密码移除与创建申请共同协调，投票从进行中转为待交付任命的保留要求由治理数据库一次读取，避免并发操作绕过限制。系统读取失败不会被当作玩家失去资格，也不会因此终止投票。

## 重置密码

`/password reset <玩家名或UUID>` 为已知账号生成并设置新的随机正式密码，同时处理首次补设、忘记密码和更换泄露密码。目标可以离线；也支持 LuckPerms 中已知但从未成功进入世界的账号。输入错误的名字不会创建新账号。

| 目标 | Moderator | Custodian | 控制台 |
| --- | --- | --- | --- |
| 新人、正式成员 | 可以 | 可以 | 可以 |
| 尚未设密的其他 Moderator | 可以 | 可以 | 可以 |
| 已设密的其他 Moderator | 不可以 | 可以 | 可以 |
| Custodian 或 OP | 不可以 | 不可以 | 可以 |

本人使用修改密码；忘记密码则由其他有权限者处理。所有管理者均无法登录时，使用服务器控制台。游戏内执行重置需要确认目标与后果，并输入执行者自己的当前密码。提交时重新核验权限、目标身份和当前凭据，旧表单不能绕过身份变化。

治理「玩家管理」提供相同的重置入口。新密码由密码学安全随机源生成，共 24 个易辨认字符，可直接长期使用；本人可以在登录后自行修改，不存在临时密码、兑换码或强制改密状态。

新凭据保存成功后旧密码失效，目标已有游戏验证会话和连接被撤销。凭据变化也会撤销尚未消费的网页登录确认，HTTP 消费时再次检查其绑定的原凭据和会话是否仍有效，不能利用清理回调的延迟继续登录；外部网站已建立的会话仍由网站自身管理。新密码只交给执行者，由其核实本人后通过可信渠道转交；不会发送给目标尚未证明身份的游戏连接。游戏内执行者在私人结果表单复制密码；控制台执行会输出密码，因此控制台、RCON 和面板的访问与记录应由服主妥善管理。

关闭结果后不能查询或重新显示密码；未收到结果时再次重置即可。并发修改或重置发生冲突时，过期操作失败，需重新打开入口。重置成功后本人走正常登录验证，不自动登录。

## 存储与运行

凭据保存在 `plugins/mik/passwords.db`，使用 Argon2id（19 MiB 内存、2 次迭代、并行度 1），每次更新生成独立的 16 字节随机 salt，保存标准 PHC 编码串。salt 与哈希一同保存，不存明文或可解密密码。每次提交都替换当前凭据；移除再设置也不能让之前开始的旧验证放行新连接或绕过重置。

凭据变更和成功操作审计在一个 SQLite 事务提交。审计保存目标 UUID、执行者、动作和时间，不保存密码、哈希或输入内容。数据库启动时校验结构、完整性和凭据编码；损坏不会被默认空账号数据覆盖。凭据写入发生存储错误时立即停止信任内存缓存、拒绝后续验证并请求停服；即使数据库可能已提交而调用方收到了错误，也不会继续接受旧密码。支持 POSIX 权限的平台将数据库文件设为仅所属用户可读写。

认证服务统一拥有当前凭据与逻辑会话，密码提交时原子更新授权状态：重置立即撤销旧授权，本人修改或移除密码只延续发起操作的同一会话。主线程回调只显示结果、清理失效连接，不能恢复登录授权；延迟的回调不会撤销已验证新密码的连接。耗时哈希在提交锁外计算，提交时核对所依据的凭据仍然有效。账号冷却跟随当前凭据失效，不依赖界面回调手动清除。验证任务结束并释放占用后才发布结果，取消等待不会提前释放仍在计算的任务。

哈希、验证、数据库操作和离线 LuckPerms 查询使用后台线程及有界任务队列。认证功能独占相关连接、表单、等待任务和线程，关闭时统一取消与清理。备份数据库时仍需保护备份文件，因为哈希可以被离线猜测。

此功能依赖可信的 Minecraft UUID 来源。正版验证或代理身份转发、防止绕过代理直连等服务器配置仍由服主维护。Java 与 Geyser 客户端必须能显示原生 Dialog 并提交响应；无法完成验证时不会免密放行，正式部署前应使用实际客户端验证。
