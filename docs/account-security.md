# 账号、身份绑定与登录

`/password` 或主菜单「个人设置 → 账号安全」管理自己的密码。新人和正式成员自愿设置；设置后每次连接都需要验证。Moderator（管理）与 Custodian（维护者）必须设置密码才能进入世界。

未设置密码的玩家会在[日常随机提示](guidance.md#日常随机提示)中收到设置建议，点击提示填入 `/password`。设置密码后停止展示该提示。

## 游戏密码与准入

密码验证在 Paper 的连接配置阶段完成，验证成功后才进入世界。未验证的连接不能操作世界、执行游戏命令、打开空间菜单或确认网页登录，也不会产生正常入服后的有效游玩记录。关闭表单或两分钟内未完成验证会断开连接。

没有密码的普通玩家可跳过验密，仍需通过封禁、维护模式及[绑定准入](#外部身份绑定)。没有密码的管理、维护者与 OP 须由有权限者重置密码后才能进入世界；没有旧账号豁免、默认密码或宽限期。

任命照常交付 LuckPerms。身份生效时，如果在线账号没有密码，将被断开连接，之后需要重置密码再登录。密码状态不改变身份、任期或投票结果。辞任或罢免完成后，原密码保留，由本人决定是否移除。

验证状态只属于当前连接，不按 IP 记住登录。密码验证失败有账号、来源与全局限流，重连不能清空失败次数。关闭插件、认证启动失败或不安全的热重载会请求关闭服务器，避免认证停用后遗留的 LuckPerms 权限继续开放；应通过正常重启更新插件。

## 验证失败与冷却

登录、修改或移除密码、管理者重置时验证自己的密码，共用同一个账号失败计数。同一账号同时只允许一个验证任务，排队前即占用名额，取消连接不会提前释放仍在计算的任务。

前 4 次密码错误可以重试；第 5 次错误后等待 30 秒，后续每次错误翻倍，最高 **48 小时**：

| 累计错误次数 | 本次冷却 |
| --- | --- |
| 5～8 | 30 秒、1 分钟、2 分钟、4 分钟 |
| 9～12 | 8 分钟、16 分钟、32 分钟、64 分钟 |
| 13～16 | 128 分钟、256 分钟、512 分钟、1024 分钟 |
| 17 | 2048 分钟（约 34 小时） |
| 18 及以后 | 48 小时 |

冷却期间拒绝验证并显示剩余秒数，重连、换 IP 或改走其他入口不能绕过账号冷却；被拒绝的请求不会延长冷却或消耗全局验证额度。没有永久锁定状态。失败历史在最后一次冷却结束 24 小时后失效；验证成功即清除该账号的历史。

管理员成功重置密码后立即清除目标账号冷却，新密码可以正常验证，旧密码验证任务晚到也不能重新施加冷却。重置不会清除来源 IP 的速率限制。

每个来源 IP 最多突发 20 次提交，此后每 3 秒恢复一个名额；全服最多突发 120 次提交，此后每 0.5 秒恢复一个名额。来源限制独立于账号失败次数，共享网络中一名玩家输错不会直接给其他账号施加长冷却。已处于账号冷却、同账号并发或被来源限流拒绝的提交不会占用全局名额。任务队列和限流状态均有容量上限。

以上计时使用单调时钟，状态仅保存在内存中，正常重启会清空。等待过长或忘记密码时，联系有权限的管理者执行 `/password reset <玩家>`。

## 玩家操作

| 命令 | 行为 |
| --- | --- |
| `/password` | 打开账号安全页 |
| `/password set` | 无密码的普通玩家首次设密 |
| `/password change` | 验证当前密码后修改密码 |
| `/password remove` | 验证当前密码并检查保留要求后移除密码 |

密码通过独立的原生表单输入，不作为命令参数，不进入普通聊天、菜单聊天草稿或社交转发。当前原生文本框不提供密码遮罩，输入会显示在本人屏幕上。

自行设置的密码使用 10～128 个 Unicode 字符，支持空格和粘贴。系统统一采用 NFC 规范化，不去除首尾空格、不截断输入，并拒绝明显弱密码、玩家名和常见弱密码片段。不要复用其他服务的密码。

设置和修改需要重复确认新密码。失败不会先清空旧密码。密码无法查询或找回原文；忘记密码时联系有权限的管理者重置。

## 管理申请

`/gov nominate` 和治理菜单的申请入口共用规则：提交新申请前必须已经设置密码。申请浮窗提供设置密码入口，返回后保留申请步骤，仍需本人点击「申请管理」提交。

管理身份、进行中的管理申请或尚未交付完成的任命都会禁止移除密码。账号安全页不等待治理；选择移除时才查询能否继续。修改、重置始终以新密码替换旧密码，不会清空密码，也不会撤回申请或更改选票。申请撤回、失败或终止后，且不再有管理身份或待交付任命时，可以自行移除密码。

Paper 先验证当前密码并持久记录移除意图，再由 `mikd` 在治理事务内授予许可。移除期间不能提交新的管理申请；Paper 提交前复核本地凭据修订和保护条件。成功或取消后由 Paper 报告本地最新修订；超时不会解除后台约束，重启后只补送结果，不重新删密。只交换请求标识和最小凭据事实，不发送密码或哈希。治理不可用时不能删密；本地验密不依赖治理通道。

## 重置密码

`/password reset <玩家名或UUID>` 为已知账号生成并设置新的随机正式密码，同时处理首次补设、忘记密码和更换泄露密码。目标可以离线；也支持 LuckPerms 中已知但从未成功进入世界的账号。输入错误的名字不会创建新账号。

| 目标 | Moderator | Custodian | 控制台 |
| --- | --- | --- | --- |
| 新人、正式成员 | 可以 | 可以 | 可以 |
| 尚未设密的其他 Moderator | 可以 | 可以 | 可以 |
| 已设密的其他 Moderator | 不可以 | 可以 | 可以 |
| Custodian 或 OP | 不可以 | 不可以 | 可以 |

本人使用修改密码；忘记密码则由其他有权限者处理。所有管理者均无法登录时，使用服务器控制台。游戏内执行重置需要确认目标与后果，并输入执行者自己的当前密码。提交时重新核验权限、目标身份和当前凭据，旧表单不能绕过身份变化。

治理「玩家管理」提供相同的重置入口。新密码由密码学安全随机源生成，共 24 个易辨认字符，可直接长期使用；本人可以在登录后自行修改，不存在临时密码、兑换码或强制改密状态。

新凭据保存成功后旧密码失效，目标已有游戏验证会话和连接被撤销。凭据变化也会撤销尚未消费的网页登录确认，HTTP 消费时再次检查其绑定的原凭据和会话是否仍有效，不能利用清理回调的延迟继续登录；MikData 在私有接口校验当前角色及凭据更新时间，缓存最长 60 秒，撤销早于凭据变更的网页会话；缓存过期而接口不可用时拒绝认证。新密码只交给执行者，由其核实本人后通过可信渠道转交；不会发送给目标尚未证明身份的游戏连接。游戏内执行者在私人结果表单复制密码；控制台执行会输出密码，因此控制台、RCON 和面板的访问与记录应由服主妥善管理。

关闭结果后不能查询或重新显示密码；未收到结果时再次重置即可。并发修改或重置发生冲突时，过期操作失败，需重新打开入口。重置成功后本人走正常登录验证，不自动登录。

## 存储与运行

凭据保存在 `plugins/mik/passwords.db`，使用 Argon2id（19 MiB 内存、2 次迭代、并行度 1），每次更新生成独立的 16 字节随机 salt，保存标准 PHC 编码串。salt 与哈希一同保存，不存明文或可解密密码。每次提交都替换当前凭据；移除再设置也不能让之前开始的旧验证放行新连接或绕过重置。

凭据变更和成功操作审计在一个 SQLite 事务提交。审计保存目标 UUID、执行者、动作和时间，不保存密码、哈希或输入内容。数据库启动时校验结构、完整性和凭据编码；损坏不会被默认空账号数据覆盖。凭据写入发生存储错误时立即停止信任内存缓存、拒绝后续验证并请求停服；即使数据库可能已提交而调用方收到了错误，也不会继续接受旧密码。支持 POSIX 权限的平台将数据库文件设为仅所属用户可读写。

认证服务统一拥有当前凭据与逻辑会话，密码提交时原子更新授权状态：重置立即撤销旧授权，本人修改或移除密码只延续发起操作的同一会话。主线程回调只显示结果、清理失效连接，不能恢复登录授权；延迟的回调不会撤销已验证新密码的连接。耗时哈希在提交锁外计算，提交时核对所依据的凭据仍然有效。账号冷却跟随当前凭据失效，不依赖界面回调手动清除。验证任务结束并释放占用后才发布结果，取消等待不会提前释放仍在计算的任务。

哈希、验证、数据库操作和离线 LuckPerms 查询使用后台线程及有界任务队列。认证功能独占相关连接、表单、等待任务和线程，关闭时统一取消与清理。备份数据库时仍需保护备份文件，因为哈希可以被离线猜测。

此功能依赖可信的 Minecraft UUID 来源。[正版认证容灾](#正版认证容灾)不改变密码准入规则。正版验证、代理身份转发和禁止绕过代理直连仍由服主配置。Java 与 Geyser 客户端必须能显示原生 Dialog 并提交响应；无法完成验证时不会免密放行。

## 外部身份绑定

`mikd` 管理验证码、绑定、成员证据和撤销记录，默认保存到 `/var/lib/mikd/community.db`。QQ 和 Matrix 适配器直接提交成员证据；Paper 在验密后调用绑定准入，并在主线程执行登录放行或在线撤销，不保存绑定库。原版白名单和 OP 不绕过绑定。外部绑定是入服条件，不等于[正式成员资格](governance.md)。

| 成员证据 | 新连接 | 已在线玩家 |
| --- | --- | --- |
| 有尚未撤销的 QQ 绑定，或 Matrix 绑定确认有效 | 通过绑定检查 | 保留连接 |
| 没有绑定，或没有 QQ 绑定且 Matrix 资格均确认失效 | 拒绝，在平台可用时提供绑定指令 | 最后一条有效绑定被撤销后，由 Paper 执行退出 |
| 没有 QQ 绑定，Matrix 资格暂时无法确认 | 提示现有绑定暂时无法验证；其他可用平台只是备选 | 不因证据未知或后台断连踢出 |

已有 QQ 绑定在入服时不查群成员资格，新绑定仍须在资格群验证。收到配置为入服资格来源的 QQ 群退群事件时，`mikd` 直接撤销对应账号的 QQ 绑定，不再查询其他群；仅仅未出现在群成员名单中不会触发解绑。Matrix 仍须在所有资格来源确认账号不在后才自动撤销。重新进群或进房间不会恢复已撤销的绑定。配置资格来源见[聊天与社交互通](chat.md#社交平台配置)。

- `/bind <平台>`：获取五分钟有效、仅用一次的验证码；同一玩家同平台的新码替换旧码，首次登录也可按拒绝界面提示领取。
- 复制提示中的绑定命令，在启用命令的资格群或房间发送。提示使用对应平台配置的前缀（如 `/bind <验证码>` 或 `!bind <验证码>`）。绑定后重新连接；验证码不会进入共享聊天。
- `/bind list`、`/bind unlink` 查看或删除绑定，`/bind cancel <平台>` 取消未使用的码。外端 `/unbind` 或 `!unbind` 按同一平台的前缀配置使用，要求同一会话、同一账号确认，只能撤销发起时的绑定 ID。
- 管理入口：`/bindadmin lookup <玩家名或 UUID>`、`/bindadmin unlink <绑定 ID> confirm`。

身份键为 `platform + issuer + scope + subject`。QQ 使用 AppID 和 `member_openid`，Matrix 使用 MXID 的服务器名和完整 MXID；两者 `scope` 为空，群／房间不属于身份键。每个外部身份只能绑定一个 Minecraft UUID，同一 UUID 在同一命名空间只能绑定一个账号。昵称不鉴权；仅重绑会生成新的绑定 ID。

Paper 确认已执行的撤销，新连接携带已看到的变更序号，避免被更早的撤销误踢。`mikd` 的只读绑定索引用于跨端提及，不进入 Paper 的服内即时发言路径。

## 正版认证容灾

直连 `online-mode=true` 的 Paper 自动启用。Paper 每次都先请求官方会话验证（`verify`）。验证请求遇到限流（HTTP 429）、服务端错误（5xx）或网络不可用时，才按玩家名和最近一次官方认证的 IP 查找缓存。官方明确拒绝（如无有效会话、HTTP 401/403 或账号限制）不回退。

缓存有效期为 **72 小时**，回退和重启都不续期。IP 不符、缓存过期或时钟早于认证时间时不回退。官方确认改名后移除旧名字记录；回退保留同一正版 UUID、签名皮肤和账号限制，不跳过本服密码、绑定、封禁或维护检查。共享公网 IP 不等于持有正版凭据，重要账号应设置本服密码。

如果是客户端向官方登记会话（`join`）时收到 `Status: 429`，原版客户端会在 Paper 发起验证前断开，服务端缓存无法接管。等限流解除后再连接，不要快速连续重试，也无需关闭正版模式。

离线模式、BungeeCord、Velocity 或 PROXY protocol 环境跳过此功能。Geyser 的正版模式只在进入 Paper 会话认证阶段后适用，无法替代此前的微软或 Xbox 登录；Floodgate 使用自己的握手与身份链路，不写入这份回退缓存。

`plugins/mik/auth-fallback.db` 保存最近 10,000 名认证玩家的 UUID、名字、IP、官方资料和认证时间，不保存客户端令牌。仅在模块启用后成功完成一次官方认证才会建立缓存。损坏或写入失败时停用回退，继续尝试官方认证；修复后正常重启，不以空库覆盖损坏数据。

启动检查 `Authentication fallback enabled`；`Could not enable authentication fallback` 表示未接管认证。实际使用缓存时会记录 `Authentication unavailable; using cached identity`。模块暂时包装 Paper 的会话服务及地址传递，不修改 `server.properties`，停用时恢复；不叠加第三方认证实现。升级 Paper 后应在测试服检查正版登录、回退和停用恢复。

## 网页登录与 Passkey

账号安全页的「网页账号与 Passkey」入口打开 `https://mcmik.top/account/security`。玩家在浏览器正常登录后，可查看和添加 Passkey、撤销指定密钥、注销其他浏览器会话，或退出全部网页会话。退出全部会话也会退出当前浏览器，但保留已注册的 Passkey。添加、撤销 Passkey 和注销其他或全部会话需要最近 5 分钟内的身份验证；可在安全页通过已有 Passkey 或游戏确认完成，成功后轮换当前会话，再继续原操作。注册挑战签发后独立有效 5 分钟。插件不直接调用 Worker 管理接口，也不需要额外的网页服务密钥。

Passkey 由浏览器的系统认证器创建，插件不接触私钥。撤销密钥会阻止其再次登录，设备或密码管理器中的副本由玩家自行删除。已有网页会话不会因此退出，丢失设备时还应注销对应会话。最后一个 Passkey 可以撤销，仍保留游戏验证码登录。

网页登录命令 `/weblogin <验证码>` 会弹出确认，有本服密码时需要重新验证密码。只确认自己在官网发起的身份验证，不代他人输入验证码。Paper 在本地验密，只向 `mikd` 提交账号和绑定到当前游戏连接及凭据的引用，不传密码。`mikd` 保管确认 5 分钟，查询时从原游戏实例检查该引用和封禁状态；退出游戏或更换凭据后旧引用失效。相同验证码不能被其他玩家覆盖，也不会因重复输入延长有效期。每个账号最多保留 4 个确认，全服最多 1024 个。确认在有效期内可重读；MikData 在创建或轮换网站会话的同一事务内一次性消费网站挑战。

命令只向仍在同一已验证游戏会话的玩家反馈结果。游戏内确认成功后回浏览器继续，不会直接创建网站会话或网页聊天授权。明确拒绝时核对浏览器里的验证码；后台不可用时稍后再试。若收不到回执，确认可能已经保存，先查看浏览器再决定是否重试。超时或不可用不是验证码错误；浏览器仍须取得有效确认才会放行。

MikData 通过现有 VPC 服务查询回环接口 `GET /api/auth/accounts/:uuid`，读取当前角色、封禁及凭据更新时间。Paper 从提交后发布的内存状态读取凭据时间，在本地比较登录引用，仅返回核验结果，不把当前引用发回 `mikd`。账号核验独立排队，离线权限查询在后台执行。普通状态读取的策略缓存最长 60 秒；Passkey 认证及敏感写入刷新插件策略。角色失去资格或凭据变化后撤销相关会话；插件不可达时停止需要实时校验的操作，保留尚未失效的网页会话。两端应保持系统时间同步。

网页验证码与 Passkey 登录复用封禁事实。封禁复核会撤销会话，解封保留 Passkey。网站会话和[网页聊天授权](chat.md#网页授权与传输)分别管理；网站登录完成后，聊天还需另行授权连接。
