# 地段

地段采用固定范围：先框选，再创建或保存。没有施工预留、到期配额、施工证据门槛或建造时自动扩张。

## 日常操作

1. `/plot` 打开地段菜单，左侧是自己的地段，中央是当前位置，右侧提供创建与浏览入口。
2. 点击「建立地段」进入范围编辑器，选两个角点，点击创建并填写名称。正式成员可以直接建立地段，不需要先放置建筑方块，也不依赖 Prism。
3. 地段详情提供范围编辑、权限与成员、改名、公告板、到访点和删除。默认范围编辑页只显示选点、边框预览、保存、撤销／重做；组合形状和划分子地段集中在「高级形状编辑」。
4. 删除只移除登记和保护，不删除建筑。母地段有子地段时必须先处理子地段；实际提交时重新检查权限。

新建和重新保存的范围向外对齐 4×4×4 网格，不自动附加保护余量。编辑器显示最终尺寸和角点坐标，保存后保护永久有效；普通建造或 WorldEdit 编辑不会改变边界。选区与地段不设置面积、体积或网格单元数量上限，普通与公共地段使用相同的范围规则，也没有可配置的大小配额。地段必须相连，并且不能与其他地段的有效保护范围重叠。

编辑已有地段会先载入已保存的真实范围。普通页重新选择两个角点即可「替换范围并保存」，不必先进入高级页应用笔刷；只有一个角点时不能提交。准备确认不会提前改动组合草稿。

## 地段公告板

地段自己的公告板最多支持 4096 个 Unicode 字符，允许多行，不再限制行数或单行长度；换行也计入总长度，补充平面字符（例如部分 emoji）按一个字符计算。正文保留换行，统一换行符并去除首尾空白；留空清除公告，其他控制字符仍禁止使用。

主菜单和地段详情只显示简短摘要，点击「查看全文」进入只读分页界面。分页只影响展示，不截断保存的正文；翻页不增加返回历史，公告修改后自动刷新，公告清空或地段删除后退出阅读页。所有玩家都可阅读，编辑仍需「地段设置」管理权限，提交时重新检查权限。

以上规则仅用于地段公告板，不调整独立社区公示的发帖长度、频率或其他限制。

## 范围编辑

进入地段编辑后，用 `//pos1`、`//pos2` 标记当前位置，或用 `//pos1 x,y,z`、`//pos2 x,y,z` 指定坐标。实地选点也可持木斧左键选择点 1、右键选择点 2；只有木斧的选点交互被接管，普通工具和空手仍可正常使用。潜行加交换副手（默认 F）返回编辑面板。菜单收起后边框仍显示，可以自由走动；`/plot edit` 返回当前会话，`/plot edit <地段ID前缀>` 编辑指定可管理地段，`/plot edit stop` 退出。

只在有效地段编辑会话中拦截两条标点命令，面板打开和边框预览状态均可使用。不注册命令，不改写 WorldEdit 的选区；会话外或其他 WorldEdit 命令交给原插件。无效参数会被消费并报告错误，不修改地段草稿，也不继续传给 WorldEdit。

青色是已保存范围，绿色与金色标记角点，紫色是待保存网格边界。不叠画原始框与网格框；已保存范围与待保存边界相同也只画一次。Actionbar 只显示两条命令、完成标记和选区尺寸。轮廓只对当前玩家显示；每 10 tick 绘制，总预算 256 粒子，裁剪 24 格外的边缘并缓存几何。单纯转头不续期；移动跨越方块或主动操作续期，20 分钟无操作结束。换世界、实际死亡、失去权限、目标删除和离线也会停止会话。

草稿按玩家与地段隔离，每人最多保留最近使用的 8 份，撤销和重做合计最多 16 步。表单捕获不可变的选区和草稿版本；提交重新检查权限、重叠、子地段和到访点。确认期间已有地段边界发生变化会拒绝旧确认，成功只清除没有再次修改的同一份草稿。多区域通过加入／扣除自动去重整理，操作见 `docs/plot-subplots.md`。

打开编辑器或新建命名前的预检不会展开整个长方体选区，而是用对齐后的坐标边界检查重叠、子地段和到访点。完整长方体本身相连，组合选区仍检查实际单元的连通性。普通地段的范围确认页也按对齐后的各轴数量计算单元数，不为显示数量分配完整选区；计数支持超过长整数范围。子地段仍按母地段的实际单元校验和计数，保留空洞。保存时构建实际单元集合并重新校验；网格坐标采用分散的哈希，避免连续三维坐标在不可变集合中严重聚集。面积、体积和单元数量仍不设配额，保存数据格式不变。

## 保存与失败处理

保护查询直接读取不可变的区块候选与子地段索引，同一次查询复用一个网格坐标，不再每次创建命中列表和父地段集合。常见分组权限键预生成，避免查询时反复拼接字符串，不改变存储键名。地段目录与按名称排序的子地段列表按地段快照缓存，状态不变时复用不可变列表；公告板、到访点和环境修改不会使目录缓存失效。环境刷新单独跟踪保护范围与时间／天气版本，同一网格单元内且版本未变的玩家跳过重复查询；权限和改名不触发环境重算，传送、重生等强制刷新仍正常执行。

地段采用「逻辑结果立即生效、后台静默落盘」。成员与权限、转交、改名、公告板、环境和到访点先检查最新逻辑状态，通过后立即发布完整内存快照、刷新界面并返回操作结果，不等待 SQLite。轻量设置复用原有空间索引，不扫描地段单元或子地段边界。

创建、修改范围和删除仍由 `mik-plot-prepare` 异步验证并构建完整几何与索引，不能为追求即时反馈而把大量计算搬回主线程。准备完成后检查逻辑版本；期间如发生其他修改，基于最新快照重新准备与校验，避免覆盖新权限或绕过已变更的管理身份。校验通过即发布结果并处理对应草稿，不等待落盘；校验失败则保留旧保护和草稿。旧回调不会清除等待期间修改过的新草稿。

不向玩家显示「保存中」，也不因后台落盘中的事务而提示稍后重试。`mik-plot-storage` 按逻辑受理顺序逐笔事务写入，失败回滚该笔磁盘事务、记录服务器日志并保留队首自动重试，后续写入不越过失败事务。后台失败不弹用户错误、不回退已生效的内存结果。准备线程与存储线程均不访问玩家或世界 API。

单元按数据库主键坐标顺序增删，每批最多绑定 512 行，所有批次仍处于同一个事务，只有全部成功才提交。这个批次大小只控制 JDBC 缓冲开销，不限制地段大小，也不会产生分批生效的保护。成员、权限等数据格式和现有数据库表均不变。

停用模块时停止受理新写入、取消尚未发布的几何准备及界面回调，等待已经向用户返回成功的后台事务排空，不依赖主线程执行界面回调。排空等待最多 30 秒；超时或无法落盘会明确记录服务器错误，且不会在写入仍运行时关闭它使用的连接。正常停服会排空已受理结果，但突发崩溃或持续存储故障仍可能丢失尚未落盘的修改；备份应在正常停服后保存整个 `plots/` 目录。

## 数据目录与公示

地段只使用当前数据模型：固定范围、成员、分组权限、公告板、到访点、环境设置和父子地段关系。不保留施工预留、施工证据、保护余量、旧权限键回退或旧数据库迁移代码。保护和重叠判断都以实际网格单元集合为准，相邻边界不额外扩张。

社区公示不占据地段主菜单，可通过 `/plot board` 查看。自动地段公示只处理登记事件，不解释旧施工预留或取消预留事件。地段自己的公告板与社区公示独立。

地段拥有的数据统一保存在插件数据目录的 `plots/` 子目录：`plots/plots.db` 保存地段，`plots/board.db` 保存社区公示，`plots/board-alerts.yml` 保存通知状态。SQLite 的 WAL 和 SHM 文件也位于同一目录；停服备份时保存整个 `plots/` 目录。

代码不查找、不读取、不搬迁插件根目录的旧文件，也不自动转换旧数据库结构。新目录不存在时直接建立当前数据库。已存在的旧文件不会被自动删除。只读公示 API 与 Social 通知仍使用当前地段数据。
