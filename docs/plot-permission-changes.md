# 地段权限变更设计

## 范围与约束

实现原子成员邀请、按实际能力管理成员、统一变更鉴权、显式默认状态与来源链、敏感变更影响预览。不增加审计、历史记录、撤回、旧版兼容、自定义角色或新的默认层级。所有者的权限恢复入口和服务器／母地段监管能力保持不变。

## 变更模型

所有成员和权限修改通过不可变请求表达：成员加入／角色调整、成员移除、单项权限设置、分类／全部个人或组设置重置。请求先生成不可变计划，包含修改前后地段、母地段及相关子地段快照、配置差异和实际权限差异。计划生成与菜单编辑不写入地段或数据库。

影响计算区分权限组规则与已知玩家成员授权。个人覆盖、成员身份、所有者恢复保障及母地段监管均参与计算；母地段组设置变化还计算对子地段继承的影响。加入和移除成员的预览比较成员授权，不推断非成员状态下的服务器身份。

提交重新核对地段、母地段和相关子地段快照，根据请求重新生成标准计划并验证候选状态，重新检查操作者的当前权限；不信任调用方传入的影响列表。任一相关状态变化则拒绝旧计划并要求重新预览。成功时只发布一次完整内存快照，并沿用独立事务、后台有序落盘。不存在先添加成员再限制权限的中间状态。

## 鉴权规则

- 改成员名单或角色需要管理成员；目标修改前或修改后具备任一管理能力时，还需要管理权限。不检查角色是否名为管理员。
- 设置、重置个人或组权限需要管理权限；所有者组只允许地段所有者、母地段所有者或服务器管理者修改。
- 新增管理授权不能超出操作者当前持有的管理能力；显式写入允许同样视为授权，防止把继承授权固化为越权的本地授权。
- 在可管理对象范围内允许撤销管理授权，不要求操作者自己能使用被撤销的能力。恢复默认、角色改变或邀请产生的新增管理授权接受同样校验。
- 所有者、母地段所有者及服务器管理者可恢复权限。所有者管理权限、服务器身份组管理能力等固定规则仍为只读。
- 面向业务的变更入口必须携带操作者；无鉴权状态写入仅保留在私有实现或存储层。

## 邀请流程

输入目标玩家后进入未提交草案，选择现有管理员／协作者模板并配置个人权限。默认状态显示继承后的实际结果；可逐分类设置或清除草案覆盖。取消、返回或断开不会创建成员。提交前预览角色、权限新增／撤销及影响范围，确认后一次提交身份与完整个人权限。现有成员角色调整保留个人覆盖。

## 权限表与敏感预览

状态显示默认（允许）、默认（禁止）、允许、禁止；来源显示个人设置、当前组、母地段名称和规则默认的具体链路。普通游戏操作保留快速循环切换。管理操作使用显式的默认／允许／禁止选择，避免不能授权的操作者无法越过允许状态执行撤销。

邀请、角色调整、移除和恢复默认均展示影响预览；管理权限变更展示预览后确认。预览列出新增与撤销的操作、实际受影响成员、子地段影响及仅配置改变但有效权限不变的情况。名单采用有上限的摘要并显示剩余数量，不为大型地段生成无限长表单。菜单和命令复用同一计划及提交路径。

## 验证与验收

- 原子邀请在提交前没有成员，在一次提交后同时具有完整覆盖；取消草案没有副作用。
- 相同实际管理能力的成员，不因管理员／协作者标签不同而获得不同的管理保护。
- 授予、撤销、邀请、角色调整、移除、重置都接受统一鉴权；显式允许和恢复默认不能绕过授权上限。
- 个人覆盖和母地段监管参与预览；子地段继承变化被准确列出。
- 确认后发生权限撤销、母地段规则修改或目标成员变化时，旧计划不能提交。
- 所有者恢复入口不可关闭；无授权操作者不能修改所有者组。
- 各语言的默认状态、来源链、预览及选择界面具有完整资源；只读与交互行均通过布局测试。
- 运行专项测试和完整测试集；不增加审计表或审计写入。
