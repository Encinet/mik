# 监狱管理

使用 `/prison` 或主菜单中的「监狱」入口打开工作台。监狱是地段的附加功能：地段所有者或服务器管理者在「地段设置」里开启后，这块地段承担监狱职责。

**封禁就是关押。** 监狱不维护自己的囚犯名单：`BanManager` 里每一条落在监狱地段内的有效封禁，就是该地段的一名囚犯。释放等于解封，延长刑期等于修改封禁到期时间。手动关押留待后续按需加入，避免绕过封禁体系滥用。

## 地段与牢房

- 附加功能的开关状态保存在地段自身的 `addon.prison` 标记里，地段数据仍是唯一事实来源。
- 地块的子地段各算一间牢房；没有子地段时整块地段是一间牢房。
- 囚犯的牢房由玩家 UUID 与监狱地段 UUID 稳定哈希决定，重启、换服或数据迁移后不会改变，因此牢房分配不写入存档。
- 释放点在监狱详情页用「设置释放位置」记录；被解封的玩家重新登录时传送到该点，没有配置则原地留在牢房。
- 封禁不在任何已启用监狱地段内时，监狱不接管该玩家，封禁按原有规则拒绝登录。

## 囚犯与面板

管理人员可在菜单里查看监狱列表与当前囚犯（名称、所在监狱、剩余刑期、封禁原因）；关押与释放请走封禁菜单。永久的封禁（无到期时间）按永久刑期显示。

囚犯所在牢房的外墙上会显示一块只读面板，列出封禁原因、剩余刑期和释放点。面板沿用铁块电梯的墙面放置算法：在地段边缘寻找可用的实心墙面，找不到时退化为悬空面板，并随方块变化、区块卸载和玩家退出失效。

## 准入与保护

- 已关押的**本人直接封禁**玩家在牢房可解析时放行登录，落地即被传送到分配的牢房；地址关联封禁仍正常拒绝登录。
- 关押期间保留物品与经验、限制活动范围和命令，并阻止囚犯破坏或放置方块。
- 关闭附加功能或删除地段时，只要还有囚犯留在里面就会被拒绝；先解封囚犯再操作。

## 配置与数据

启动后在插件数据目录生成 `prison-settings.yml`：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `allow-banned-prisoner-login` | `true` | 允许有效牢房中的本人直接封禁玩家登录 |
| `protect-regions` | `true` | 阻止监狱地段内非管理者破坏和放置方块 |
| `check-interval-ticks` | `40` | 刷新囚犯状态栏与面板的间隔，范围 1–72000 |
| `allowed-commands` | 私聊、帮助、封禁管理指令 | 关押期间允许执行的命令标签 |

`prison-data.yml` **只保存每座监狱的释放点**，没有 `prisoners` 段；地块本身由地段存储维护，囚犯、刑期与原因全部实时取自封禁数据。每次更新使用临时文件原子替换，数据损坏时保留原文件并报告初始化失败。

MIK 不会自动导入独立 `PrisonPlugin` 的 YAML 数据；上线前请在地段中重建监狱及牢房，并备份既有数据。
