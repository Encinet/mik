# 监狱管理

使用 `/prison` 或主菜单中的「监狱」入口打开工作台。监狱是地段的附加功能：地段所有者或服务器管理者在「地段设置」里开启后，这块地段承担监狱职责。

## 地段与牢房

- 附加功能的开关状态保存在地段自身的 `addon.prison` 标记里，地段数据仍是唯一事实来源。
- 地块的子地段各算一间牢房；没有子地段时整块地段是一间牢房。
- 囚犯的牢房由玩家 UUID 与监狱地段 UUID 稳定哈希决定，重启、换服或数据迁移后不会改变，因此牢房分配不写入存档。
- 释放点在监狱详情页用「设置释放位置」记录；释放时优先传送到该点，没有配置则回到关押前的位置。

## 关押与面板

管理人员从菜单选择玩家、监狱和刑期。刑期支持 `2d12h`、`30m`、`permanent`；玩家可离线关押，但需预先有 MIK 玩家记录。菜单也提供当前囚犯的筛选与释放操作。

囚犯所在牢房的外墙上会显示一块只读面板，列出封禁原因、剩余刑期和释放点。面板沿用铁块电梯的墙面放置算法：在地段边缘寻找可用的实心墙面，找不到时退化为悬空面板，并随方块变化、区块卸载和玩家退出失效。

## 封禁与保护

监狱功能读取 MIK `BanManager` 的有效封禁，并自动将有 UUID 的封禁玩家分配到可用牢房。已关押玩家可在牢房可解析时通过**本人直接封禁**的登录检查；地址关联封禁仍正常拒绝登录。刑期结束或封禁撤销时按配置释放。

关押期间保留物品与经验、限制活动范围和命令，并阻止囚犯破坏或放置方块。无监狱或无可用牢房时不会自动分配封禁玩家。

关闭附加功能或删除地段时，只要还有囚犯留在里面就会被拒绝；先释放囚犯再操作。

## 配置与数据

启动后在插件数据目录生成 `prison-settings.yml`：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `automatic-jailing` | `true` | 自动关押有 UUID 的 MIK 有效封禁玩家 |
| `allow-banned-prisoner-login` | `true` | 允许有效牢房中的本人直接封禁玩家登录 |
| `release-on-unban` | `true` | 解封后立即释放自动关押的玩家 |
| `release-when-sentence-ends` | `true` | 到期释放非有效封禁中的囚犯 |
| `protect-regions` | `true` | 阻止监狱地段内非管理者破坏和放置方块 |
| `check-interval-ticks` | `40` | 同步封禁、到期释放和刷新面板的间隔，范围 1–72000 |
| `default-ban-sentence` | `permanent` | 永久封禁玩家的默认监狱刑期 |
| `allowed-commands` | 私聊、帮助、封禁管理指令 | 关押期间允许执行的命令标签 |

`prison-data.yml` 只保存释放点与囚犯记录，地块本身由地段存储维护；每次更新使用临时文件原子替换。数据损坏时保留原文件并报告初始化失败，不会静默覆盖。

MIK 不会自动导入独立 `PrisonPlugin` 的 YAML 数据；上线前请在地段中重建监狱及牢房，并备份既有数据。
