# 监狱管理

使用 `/prison` 或主菜单中的“监狱”入口打开工作台。成员可以创建和管理自己的监狱；版主与服主可以管理全部监狱，并关押或释放玩家。

创建监狱后，在监狱详情页设置备用出生点、释放位置和区域角点，再站在每个牢房位置添加牢房。正常关押会分配牢房；备用出生点仅用于修复缺失的牢房位置。若设置了区域，牢房和备用出生点都必须位于同一世界的两个角点之间。移除牢房前必须先释放对应囚犯。

管理人员从菜单选择玩家、监狱和刑期。刑期支持 `2d12h`、`30m`、`permanent`；玩家可离线关押，但需预先有 MIK 玩家记录。菜单也提供当前囚犯的筛选与释放操作。

## 封禁与保护

监狱功能读取 MIK `BanManager` 的有效封禁，并自动将有 UUID 的封禁玩家分配到可用牢房。已关押玩家可在牢房可解析时通过**本人直接封禁**的登录检查；地址关联封禁仍正常拒绝登录。刑期结束或封禁撤销时按配置释放。关押期间保留物品与经验、限制活动范围和命令，并阻止囚犯破坏或放置方块。

无监狱或无空牢房时不会自动分配封禁玩家。管理人员可在完成监狱和牢房配置后手动关押，或等待后续有效封禁同步。

## 配置与数据

启动后在插件数据目录生成 `prison-settings.yml`：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `automatic-jailing` | `true` | 自动关押有 UUID 的 MIK 有效封禁玩家 |
| `allow-banned-prisoner-login` | `true` | 允许有效牢房中的本人直接封禁玩家登录 |
| `release-on-unban` | `true` | 解封后立即释放自动关押的玩家 |
| `release-when-sentence-ends` | `true` | 到期释放非有效封禁中的囚犯 |
| `allow-player-prisons` | `true` | 允许成员建立自己的监狱，也允许自动分配使用这些监狱 |
| `protect-regions` | `true` | 阻止监狱区域内非管理者破坏和放置方块 |
| `prisoner-radius` | `12` | 未设置区域角点时，以牢房为中心的活动半径 |
| `default-ban-sentence` | `permanent` | 永久封禁玩家的默认监狱刑期 |
| `allowed-commands` | 私聊、帮助、封禁管理指令 | 关押期间允许执行的命令标签 |

监狱与囚犯一起保存在 `prison-data.yml`，每次更新使用临时文件原子替换。损坏的数据不会被静默覆盖，启动时会报告初始化失败。数据使用世界 UUID 保存位置。

MIK 不会自动导入独立 `PrisonPlugin` 的 YAML 数据；上线前请在菜单中重建监狱及牢房，并备份既有数据。
