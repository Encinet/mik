# 地段权限管理

## 成员视图与存储边界

- `PlotRoster` 从不可变 `Plot` 快照生成只读成员投影，统一识别、去重、计数和权限对象映射，不依赖 Bukkit、语言资源或数据库。所有者仍存于 `Plot.owner`，受邀角色仍存于 `Plot.members`，不新增持久化的所有者角色。
- 列表、卡片、详情和权限入口均统计所有者及受邀成员；无受邀成员时人数为 1。列表按所有者、管理员、协作者排列，同身份按玩家名（忽略大小写）、UUID 排序；分页使用实际名单。
- 所有者详情对应所有者组权限，不创建个人覆盖，不提供降级或移除；受邀成员对应个人权限。统一使用「权限」入口，查看不代表有权修改。转让沿用既有流程，新所有者仅出现一次，旧所有者不自动成为受邀成员。
- 母地段所有者单独展示为监管主体，不计入子地段成员人数；服务器管理者也不自动计入。菜单监听本地和母地段快照，点击权限、转让时重新解析身份，写操作仍由 `PlotEdits`／`PlotAccessPlan` 校验最新状态。
- 新增角色先扩展 `Plot.Role`、`PlotAccessPolicy` 的分组及默认权限，投影读取统一规则，菜单只负责展示。监管、待确认邀请、审计保持独立模型，不混入已生效成员名单。界面不增加解释性文案。

## 列表操作

创建子地段使用独立管理权限 `create_subplot`，修改已有范围使用 `manage_area`；两者互不授权，也不把原有范围设置自动复制到新权限。创建权限只适用于母地段，子地段的权限表不显示该项，命令和个人授权也不能写入该项。所有者和地段管理员在母地段默认允许创建；需要限制创建时，单独配置对应组或成员的 `create_subplot`。

从 `/plot` 打开地段详情，选择「权限与成员」。页面仅列出权限对象、成员入口和「地段设置与所有权」，不在同一页铺开全部开关或混入删除按钮。

1. 选择所有者、管理员、协作者、服务器新人或服务器正式成员。不再提供受邀访客角色。
2. 直接进入权限表格。左侧常驻建造与修改、方块交互、储物与物品、实体操作、管理权限五个分类；切换分类不新增返回层级。
3. 右侧按「操作／状态」对齐，每行只有一项操作；默认明确显示「默认（允许）」或「默认（禁止）」，状态下方显示完整来源。普通游戏操作点击循环切换默认 → 允许 → 禁止 → 默认；管理操作打开默认／允许／禁止选择页，直接选择需要的状态。

左上角的对象名称带下拉标记，可切换权限组或进入成员名单，切换组时保留当前分类。个人设置从「成员」→ 成员详情 →「个人权限」进入，复用同一表格。管理员也可设置个人权限；所有者通过所有者组设置权限。列表一次最多六项具体操作，使用纯文字控件，不为每行重复生成物品图标。列宽与行距根据实际文本和字号测量，长名称可以换行，不挤占状态列。

权限表格不再常驻显示切换顺序说明，权限对象、成员列表和成员详情也不提供重复解释角色默认值的帮助页。状态及来源直接在各行显示；成员草案只保留「尚未提交」状态，操作由按钮名称表达。确认页继续说明权限影响、重置范围和不可逆后果。

底部的「恢复默认」只清除当前对象、当前分类的设置；对象选择页的「恢复默认 · 全部操作」清除当前对象的全部操作设置。两者都先预览对象、范围和有效权限影响，确认通过校验后立即更新状态，后台静默落盘。Bedrock 使用原生表单，每个状态按钮保留对应操作名称和来源，隐藏空间表格专用列标题。

「地段设置与所有权」单独承载项目公开状态、所有者、转让和删除。公开状态是项目标记，不会自动开放交互或建造。

## 成员草案与影响预览

添加成员或执行 `/plot invite` 后先进入未提交草案，使用现有管理员／协作者模板，逐分类配置个人设置；默认状态展示该角色、当前组和母地段规则共同计算的结果。切换角色保留个人设置，「清除本分类设置」只清草案当前分类。草案不写入成员名单；返回、取消、断开不会创建成员。

提交先预览角色及完整个人覆盖，确认后一次发布成员身份和全部个人权限，不会短暂赋予未受限制的角色权限。已有成员切换角色保留个人覆盖；移除时同时清除成员身份和个人设置。

邀请、角色调整、移除、管理权限修改以及分类／全部重置共用影响预览。预览区分新增和撤销操作、受影响的已知成员、子地段继承变化；只改变配置而不改变有效权限时明确提示，避免把固化继承误认为没有修改。名单最多显示六个名称及剩余数量。成员加入和移除比较成员授权，不推断玩家移出名单后的服务器身份组权限。

确认捕获地段、母地段和相关子地段快照；相关成员、权限或继承状态发生变化则拒绝旧确认，要求重新预览。无关地段的变化不会阻止提交。菜单和命令共用不可变请求、计划、当前鉴权及原子提交，不增加审计、历史或撤回功能。详细实现与验收见 [权限变更设计](plot-permission-changes.md)。

## 操作分类

| 分类 | 可独立设置的操作 |
| --- | --- |
| 建造与修改（6 项） | 放置方块与普通载具、破坏方块、用桶取放液体与生物、点火、修改方块与施肥、采收浆果、藤蔓与蜂蜜 |
| 方块交互（4 项） | 门与栅栏门、按钮／拉杆／压力板、使用设施与工作站、编辑告示牌 |
| 储物与物品（4 项） | 打开方块容器、打开实体储物、拾取地面物品、丢弃物品 |
| 实体操作（6 项） | 普通实体交互、村民交易、乘坐载具与动物、照料／驯养／拴绳、伤害实体与载具、放置与修改装饰实体 |
| 管理权限（6 项） | 修改地段设置、修改范围与划分子地段、管理成员、管理权限、转让所有权、删除地段 |

共 26 项具体权限，分类互斥，每项只归属一类。分类按操作意图与对象划分，不把「能破坏」「能开箱」「能拾取」捆绑成一个宽泛授权。一次操作同时涉及多个受保护资产时组合检查。完整的操作键、事件及集成入口见 [权限覆盖清单](plot-permission-coverage.md)。

修改地段设置包括名称、公开状态、公告板、到访点及其文字、时间与天气。修改范围与划分子地段包括范围修改、创建子地段及修改子地段范围，仍须通过边界、重叠、到访点及层级校验。管理成员允许添加、调整和移除成员；目标修改前或修改后具备实际管理能力时，还须具备管理权限，不按管理员名称判断。转让和删除各自独立授权，不凭角色直接放行。

带物品库存的熔炉、酿造台等属于容器，不因工作站权限而开放。箱子矿车与马匹库存属于实体储物。马匹空手乘坐、喂食、潜行打开库存分别检查乘坐、照料、实体储物；实际骑乘事件另行校验乘坐权限。插件载具的交互实体和盔甲架座位通过载具标记识别，使用乘坐权限，不误归为装饰操作。

工作站权限包括没有独立库存的设施、工作台、床、重生锚使用和铃铛；堆肥、吃蛋糕、填充重生锚和花盆取放植物属于修改方块，不能仅凭设施使用权限改动。炼药锅用桶／瓶取放液体检查桶权限，洗旗帜、装备及潜影盒检查修改权限，自然补水和灭火不冒充玩家修改。

物品拾取只检查物品所在位置；主动丢弃同时检查玩家与生成物品的位置，避免跨边界丢物绕过限制。拾取与丢弃互相独立，也不与开箱或批量建造绑定。服务器身份组默认禁止这两项，所有者、管理员和协作者默认允许，均可单独配置。玩家死亡和自然生成的掉落不属于主动丢弃；其他生物的自动拾取不使用玩家权限。

驯养、拴绳、解绳、剪羊毛及动物命名归动物照料；拴绳同时检查动物和锚点位置，拴绳结不误归为装饰。非动物命名使用实体交互，不因交易或乘坐授权而放行。向驴、骡等添加箱子使用实体储物权限。桶装生物捕捉组合检查桶与动物照料，释放桶装生物同时要求放置权限。钓竿拉取地面物品仍需拾取权限；拉取普通实体需实体交互，带库存的实体另需实体储物，装饰实体使用装饰权限。

装饰权限包括画、物品展示框、盔甲架和展示实体的放置、操作、拆除与受玩家伤害，展示框装入、旋转和取出物品均受保护。普通实体及原版载具的伤害／移除检查实体伤害，带库存时还检查实体储物，近战、投射物和可归因玩家的伤害共用规则。插件载具的命令及菜单入口也检查对应权限：生成为放置、进入为乘坐、维护为实体交互、移除为实体伤害、采集展示模型为装饰。

实体伤害不改变玩家之间的 PvP 规则。桶、点火、告示牌打开与提交、讲台书放入与取出、采收、施肥及玩家触发的树木生长都有对应事件检查；跨边界施肥检查每个实际变更方块。投射物伤害检查发射玩家。

## 权限优先级与默认值

角色只提供默认值，所有者、管理员和协作者的游戏操作及管理能力使用同一套权限计算，不凭角色绕过限制。服务器管理者和子地段的母地段所有者保留监管能力。其余玩家按以下顺序计算：

1. 当前地段的个人设置，仅对当前已邀请成员有效。
2. 当前地段所属组的具体操作设置。
3. 子地段继承母地段同组规则。
4. 角色默认值。

所有者默认允许全部操作；管理员默认允许游戏操作及设置、范围、成员、权限管理，但默认不能转让或删除；协作者默认允许游戏操作，不具备管理能力。所有者和管理员也可限制放置、破坏、储物等操作。服务器新人和正式成员默认禁止所有操作，可明确授予具体游戏操作，但不向服务器身份组开放管理能力；管理能力必须授予地段成员。

所有者的「管理权限」始终允许且只读，作为恢复入口，防止误设置后失去地段控制；其他操作可以关闭，必要时从权限页恢复默认。所有权归属保持单一，通过转让变更，不使用普通成员组赋予所有权。

修改成员身份需要管理成员；目标修改前或修改后具备任一管理能力时，还需要管理权限，不因管理员／协作者标签不同而采用特殊保护。没有管理能力的管理员和普通协作者具有相同的成员管理保护。

具备管理权限的成员不能给自己或他人授予自己不具备的管理能力；显式写入允许即使暂不改变实际结果，也接受授权上限校验。邀请、角色调整及恢复默认新增的管理授权接受相同检查。在可管理对象范围内，可以撤销自己不具备的管理能力，不必先获得被撤销的权限。所有者组只允许地段所有者、母地段所有者及服务器管理者修改；这些监管主体可恢复权限和授权。每次实际修改均读取最新地段状态重新鉴权，菜单入口、旧快照或此前的角色不能绕过已撤销的权限。

母地段的成员身份、个人授权不自动进入子地段。子地段按自己的成员名单决定所属组，然后继承母地段该组规则。例如母地段协作者若未加入子地段，在子地段按普通服务器玩家判断，而不是继续拥有协作者权限。

个人默认值跟随所属组，子地段组默认值跟随母地段。来源明确显示个人覆盖、所属组及其本地设置／角色默认；继承来源显示母地段名称、同组和其本地设置／角色默认。所有者权限恢复保障单独显示。不可修改的权限为只读；无权授予的管理状态禁用，但可撤销的状态保持可选。设置、成员操作、转让、删除和范围操作按各自能力显示，能打开管理页不等于具备全部管理能力。

移除成员时同步删除其个人设置，重新邀请不会恢复旧授权；转让时清理新旧所有者的个人设置。权限修改先读取最新逻辑状态并检查管理权及目标成员，通过后立即发布内存快照、刷新列表，连续点击基于上一点击的结果计算，不等待数据库，也不显示保存中或因落盘忙碌而拒绝点击。后台按受理顺序使用独立事务落盘；失败仅记录服务器日志，保留已生效的逻辑状态并自动重试，不用旧磁盘结果覆盖新设置。检查操作权限只读不可变快照，不等待数据库或触发地段几何扫描。

## 权限键与编辑器保护

不提供旧版角色或权限规则的兼容与数据迁移。`visitor` 角色及权限组、`interact`／`entity` 大类操作、无组前缀的权限写入均已移除；权限只使用当前组名和具体操作名。分类重置只清除当前对象当前分类的具体操作键；全部重置清除该对象的所有操作键，环境及未知扩展键保持不变。

命令为 `/plot flag <地段ID> <组.操作> <true|false>`，组名为 `owner`、`admin`、`collaborator`、`newcomer`、`member`。游戏操作名对应 `place`、`break`、`bucket`、`ignite`、`modify`、`harvest`、`door`、`switch`、`workstation`、`sign`、`container`、`entity_storage`、`item_pickup`、`item_drop`、`entity_interact`、`trade`、`ride`、`animal`、`entity_damage`、`decoration`。管理操作名为 `manage_settings`、`manage_area`、`create_subplot`、`manage_members`、`manage_permissions`、`transfer`、`delete`。命令遵循与菜单相同的授权、只读约束和管理权限变更确认。`/plot invite` 只接受 `admin` 和 `collaborator`，进入草案而非立即添加成员。

方块放置、破坏分别检查各自权限；破坏带库存的方块还要有容器权限，避免拒绝开箱后仍可拆箱取物。双箱库存检查两侧权限。WorldEdit、Axiom 和受保护的原版修改命令沿用统一查询，其中内部 `build` 查询自动汇总建造分类，以及告示牌和容器权限，不是一项可配置权限；拾取和丢弃不加入批量修改的授权要求。WorldEdit 创建装饰实体单独检查装饰权限，拴绳结检查动物照料，其他实体检查放置权限。Axiom 和原版实体事件共用实体编辑规则：装饰检查装饰，拴绳结检查照料，其他实体创建检查放置，移除检查伤害，编辑器修改检查交互和伤害，修改／移除带库存的实体还需实体储物权限。刷怪蛋、船、矿车与末地水晶的使用检查放置，向末地传送门框放入末影之眼检查修改。

这些规则覆盖已接入的 Bukkit／Paper 事件和编辑器入口，不保证能够约束绕过事件和集成接口直接修改世界的其他插件。火焰烧毁、爆炸方块破坏、液体与活塞跨地段等环境保护保持独立，不混进玩家操作列表。漏斗等自动库存转移与自动拾取禁止跨不同地段、母子地段或地段与外部边界，允许同一地段内部及完全外部的转移；双箱检查两半的实际位置。不具备世界位置的插件虚拟库存无法按地段判断。移动、到访、PvP、自然掉落及自然环境并非新增的成员权限，也不提供审计或旧版兼容。
