# 音乐文件与配置

音乐独占 `plugins/mik/music/`。目录按文件的维护者和生命周期划分，曲库扫描、音源加载和缓存清理分别限定在各自目录内。

```text
plugins/mik/music/
├── settings.yml                 # 管理员编辑的启动参数
├── library/                     # 管理员维护的本地音频和 NBS，可按专辑分子目录
├── sources/
│   ├── local/                   # 管理员维护的 LX JavaScript，可分子目录
│   ├── managed/                 # 导入后验证通过的音源脚本快照
│   │   └── remote-<URL hash>.js
│   └── subscriptions.json       # 程序维护的订阅地址和更新状态
├── data/
│   ├── music.sqlite             # 个人音乐、歌单、设备、同步组及播放检查点
│   └── playback-statistics.json # 有效播放统计，供缓存保留策略使用
├── secrets/
│   └── disc-signing.key          # 实体唱片签名密钥
└── cache/
    ├── audio/                   # 在线音频及配套来源、曲目元数据
    └── lyrics/                  # 歌词响应缓存
```

按实际使用创建文件与缓存目录，不预建空的日志、备份、导入或临时目录。数据库使用 WAL 时，`music.sqlite-wal` 和 `music.sqlite-shm` 也位于 `data/`。文件名保持稳定，格式版本由文件内容或数据库结构维护。

## 管理员入口

| 位置 | 维护方式 | 生效方式 |
| --- | --- | --- |
| `settings.yml` | 编辑运行参数 | 重启服务器 |
| `library/` | 添加、替换或移除本地媒体；相对路径作为本地曲目身份 | `/music reload` |
| `sources/local/` | 放入可信脚本，按相对路径排序加载 | `/music reload` |
| `sources/managed/`、`sources/subscriptions.json` | 由音源导入和更新服务共同维护，保持配套 | `/music sources import <URL>`、`/music sources update` |
| `data/` | 由游戏内操作和存储服务维护 | 歌单编辑与设备操作提交后生效 |

曲库只递归扫描 `library/`；移动其中的文件会改变曲目身份。音源只扫描 `sources/local/` 与订阅表登记的 `sources/managed/` 文件。歌单导入保存曲目元数据和来源信息到数据库，不在本地曲库生成媒体文件，也不持续同步外部歌单。

## 启动参数

首次运行生成带注释的 `settings.yml`，已有文件保持原样。允许省略配置项并使用默认值；未知项、错误类型、无效 YAML 和越界数值会使音乐启动失败，并在日志中给出文件位置。修正后重启，不用空配置覆盖原文件。

| 配置项 | 默认值 | 约束与效果 |
| --- | --- | --- |
| `sources.refresh-interval-minutes` | `360` | 整数，0–10080 分钟；`0` 关闭周期检查，启动加载、手动重载及更新仍可检查订阅 |
| `cache.audio.maximum-file-mib` | `512` | 整数，1–4096 MiB；限制单次下载及可复用音频大小 |
| `cache.audio.maximum-total-mib` | `8192` | 整数，不小于单文件限制，最大 1048576 MiB；新下载按预算预留空间并淘汰可释放音频 |
| `cache.lyrics.maximum-total-mib` | `256` | 整数，4–65536 MiB；写入歌词后按使用时间淘汰旧缓存 |

MiB 为 1024 × 1024 字节。音频最多并行下载 4 首；正在使用的音频不会被容量淘汰，无法腾出所需空间时下载失败。容量预算分别管理音频正文与歌词缓存，音频配套的小型来源和曲目索引会随音频一起清理。调整预算不会立刻遍历删除现有缓存；后续读取、下载或写入执行对应检查。

配置只提供当前使用的运行参数，不允许另行指定曲库、数据库或密钥的外部路径。个人声音设置、歌单排序和设备选择通过游戏界面维护。

## 持久数据与可清理内容

`data/music.sqlite` 保存曲目快照、歌单与顺序、收藏、最近播放、个人设备记录与别名、同步组、播放程序、检查点和导入结果。文件统计与个人最近播放分开：`playback-statistics.json` 用于记录有效播放并辅助缓存保留策略，不是界面的个人历史存档。

`sources/managed/` 保留最后通过验证的脚本。上游暂时不可用或返回无效更新时仍可使用已有快照，因此它随订阅表参与备份。`sources/local/` 由管理员维护，程序不会通过导入和更新覆盖它。

`secrets/disc-signing.key` 用于验证已有实体唱片。丢失后新生成的密钥无法验证此前签发的唱片；损坏的密钥会报错，不会自动重置。支持 POSIX 权限的系统会将密钥文件限制为所有者读写。

`cache/` 可以在停服后删除，之后按使用需要重新获取媒体；删除后，已缓存在线歌曲不再能直接离线播放。音频的 `.audio`、`.source.json` 和 `.track.json` 配套维护，歌词缓存独立清理。缓存服务只管理自己的叶目录，不递归清理整个 `music/`。

临时文件与目标文件放在同一目录，便于原子替换：音频和歌词使用 `.part`，音源验证使用 `.candidate` 与 `.backup`，数据保存使用临时文件。它们由对应服务在操作完成或失败时释放；不要在服务运行时手动清理正在使用的文件。

## 备份与恢复

停服后备份 `settings.yml`、`library/`、`sources/`、`data/` 和 `secrets/`；`cache/` 可选。恢复时保持目录及配套文件一致，尤其是订阅表与脚本快照、数据库与签名密钥。

唱片机的设备身份和声音设置保存在世界方块 PDC，玩家音游校准保存在玩家 PDC，实体唱片保存在物品数据。完整恢复服务器还需要对应的世界与玩家存档；只复制插件目录不能恢复这些状态。运行中的 SQLite 数据库应使用一致性备份机制，不单独复制主数据库文件。

本次布局直接启用新路径，不读取、迁移或删除以前位于 `state/`、`lxmusic/`、插件根 `cache/` 或 `music/` 根目录的旧文件。操作入口见[音乐与音游](music.md)，职责与线程边界见[音乐架构](music-architecture.md)。
