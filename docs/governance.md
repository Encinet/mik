# 成员与治理

治理数据保存在 `plugins/mik/governance.db`，规则时间按 UTC+8（`Asia/Singapore`）计算。

## LuckPerms 边界

LuckPerms 管理命令、Axiom 和其他功能权限。治理只通过其 API 增删 `member`、`moderator` 组并设置主组；权限调整修改组继承，不另建新人命令黑名单。

已有成员首次建档缺少入组时间时，以首次加入服务器时间作为 `member_since`；之后的自动晋升记录实际时间。

## 数据库边界

- 每次连接显式启用 SQLite 外键，并在启动时执行完整性、外键和治理快照一致性检查。
- UUID、枚举、时间范围、投票生命周期、晋升暂停书面字段等由 `CHECK`、外键和唯一索引共同约束。
- 开票后选民快照不可增删改；投票截止或终结后选票不可新增、修改或删除。
- 任命和罢免共享投票生命周期、冻结选民、匿名选票、计票、结算、公告与冷却逻辑。
  数据结构仍可读取和结算既有封禁投票，但不再提供发起封禁投票的命令。
- 达到人数的最后一名联署人、罢免建票、冻结选民与申请关联在同一事务提交，失败整体回滚。
- 通过投票与对应的通用治理动作在同一事务提交。动作队列支持 LuckPerms 任命、LuckPerms 罢免
  和既有封禁投票的 `BanManager` 动作；外部写入失败或服务器中断时，未完成动作会保留并重试。
- 投票结算与“结果已公告”状态分别持久化。结算后、公告前发生重启时，系统会在恢复后补发结果。

## 有效游玩与资格

- 每分钟取一次现有 AFK 模块的 `isActivityEligible` 结果，只累计连续两次取样均有效的在线时段。
- 单次取样最多累计 75 秒，服务器卡顿或暂停不会虚增在线时间。
- 跨 UTC+8 午夜的时段会拆到两个自然日。
- 新人晋升同时检查 3 天、8 小时、至少 2 个自然日、生效封禁和书面晋升暂停。
- 活跃成员按当日及此前 59/29 个自然日计算；累计时长包含所有有效秒数，只有单日达到
  30 分钟时才计为有效参与日。

## 游戏内菜单

主菜单在右侧栏的站外链接下方以独立卡片显示进行中事项，卡片按各自内容确定宽度并左对齐，没有事项时收起：单个投票可直接赞成、反对或弃权，截止前可改票；多个事项最多显示两条，点击标题在浮窗参与，更多事项进入完整列表。联署需确认后提交。提交或浮窗打开期间保留原事项，避免刷新更换操作对象；投票明细和他人选择不在摘要中公开。

投票浮窗与「治理事项」共用完整详情：投票编号、类型与对象、选民及法定人数、起止时间、参与进度、本人选择和提案说明使用同一份内容与样式。正文按实际阅读空间分页，阅读位置随刷新保留，末页显示投票控件。标题与操作区保持辅助位置，不占用正文阅读预算。提交时禁用重复操作，事项结束或已不在当前快照中时，保留浮窗上下文并收起投票操作。

主菜单的「社区治理」或 `/gov` 打开公开管理名录，包含离线管理和维护者。名录按 LuckPerms 服务器静态上下文及有效组继承判断身份，隐藏玩家的在线状态按查看者权限显示。治理只撤销自己维护的直接 `moderator` 授权，继承的管理权限仍展示，但不提供无效任免操作。

名录根据实际字号、FOV 和菜单倍率计算每页行数，表头持续显示，各页列宽一致；姓名、身份和在线状态的长标签可通过提示读取全文。翻页使用已加载快照，只生成当前页的控件，不重新查询数据库；搜索和翻页会收起原成员的详情。

- 点击管理行打开详情浮窗，查看职责、近期记录或发起罢免联署；关闭后恢复原列表。申请、撤回和辞任需确认。
- 「治理事项」查看进行中的投票、联署及已结束记录，可按玩家筛选。提交和刷新保留当前选择；通过但未交付的结果显示「待执行」。
- 主菜单资料中的身份行及治理页底部工具栏的身份按钮共用详情浮窗，显示角色、晋升条件和有效参与记录。管理通过任命产生，身份不按经验值升级。
- 管理与维护者可搜索已记录的在线、离线玩家，支持名称片段和 UUID。回车先展示结果，即使只有一条也须点击进入档案；返回保留搜索与页码。查询不触发网络身份搜索。

事项目录按实际行高确定每页容量，名单与右侧正文分别翻页；更改字号、FOV 或菜单倍率时，保留正在浏览的源位置。同一快照内翻页直接重绘，历史记录跨读取批次时在后台加载，页码仍按当前显示容量计算。等待或读取失败时保留刷新、分类和关闭入口；被替换快照中的旧翻页请求失效。

玩家档案按完整字段阅读，暂停理由与申诉途径保留全文。适用的暂停／恢复、密码管理、刷新和返回入口持续可用；刷新或切换语言后保留当前字段，切换玩家从头开始。快速切换、重复刷新及关闭后的旧查询不会替换当前档案；旧表单回调也不会转到新的玩家目标。输入的期限或必填书面字段无效时，表单保留原值并显示原因。

治理页顶部显示申请状态。「申请管理」可查看尚未满足的具体条件；设置密码后返回同一申请浮窗，仍需本人提交。投票中提供「撤回申请」，已通过而尚未执行任命时显示「申请状态」，避免重复申请。提交后等待读回最新状态再恢复操作。

成员职责、近期记录、申请条件和确认说明按实际阅读空间分页，操作区持续可用。阅读位置绑定当前浮窗来源，刷新保留源段落；切换对象、重新打开或关闭后，旧翻页回调不会更新新浮窗。浮窗标题保持单行，超长标题通过提示保留全文。

符合资格且已设账号密码的成员可申请管理。申请及待交付任命期间不能移除密码，仍可修改或重置；任命照常交付，无密码的管理账号须由有权限者重置后登录。具体权限见[账号安全](account-security.md)。

## 命令

`/governance`、`/gov` 和 `/governance menu` 打开同一空间菜单；管理者输入 `/governance player` 可直接搜索玩家。以下子命令供控制台或熟悉命令的玩家使用：

- `/governance status`：以聊天文字查看自己的晋升或活跃成员资格。
- `/governance player <玩家>`：管理或维护者查看玩家履历、适用的资格条件及暂停信息。
- `/governance player <玩家> pause <期限> <申诉途径> <理由>`：暂停晋升；期限支持 `m`、`h`、`d`，需填写理由与申诉途径。
- `/governance player <玩家> resume <解除理由>`：解除生效中的晋升暂停并保留审计记录。
- `/governance nominate`、`/governance withdraw`：申请管理或撤回申请。
- `/governance list`、`/governance vote <编号> yes|no|abstain`：查看和参与匿名投票。
- `/governance show <编号>`：查看投票快照、当前参与数或最终分类票数；玩家只能看到自己的选择。
- `/governance history`：查看最近 10 次投票的完整汇总结果和终止原因。
- `/governance petitions`：查看正在征集共同发起人的罢免申请，只显示人数而不显示发起人名单。
- `/governance remove <管理>`：以活跃成员身份共同发起罢免；达到所需不同发起人数后自动开票。
- `/governance resign`：管理随时辞任。

任命和罢免投票均为三天，并使用相同的法定参与人数与通过门槛。正式封禁使用封禁模块的固定等级与
现行规则中的处理程序；已有的封禁投票记录仍可查询，待执行动作仍会完成。

开票时会把合资格 UUID 写入不可变选民名册，同时固定选民数和法定参与人数。投票中只公开参与数，
不公开实时赞成、反对或弃权分项；每名玩家可以私下确认自己的当前选择。截止后公布选民总数、参与
数和赞成/反对/弃权汇总，不提供查询他人选择的命令。候选人在截止前失去活跃成员资格或主动撤回时，
任命投票会记录具体原因并自动终止。未达到法定参与人数的投票在三天内不能重新发起。

## 每日管理状态

系统按 UTC+8 午夜检查 LuckPerms 的 `moderator` 组和 Paper 的成功登录记录。超过 180 天未登录者按
离线时间由长到短卸任，但本流程最多卸任到剩余四名；辞任和投票罢免不受此下限约束。`custodian`
组不参与管理任免或离线卸任，仍可依规则行使管理权限。

## 运维注意

“每个自然人的指定账号”需要可信的自然人到账户映射。现有 Minecraft UUID、IP 关联和外部平台绑定
都不足以单独证明两个账号属于同一自然人，因此模块当前冻结并去重的是 UUID。上线治理投票前，应由
身份系统提供该映射；不能使用 IP 自动合并账号，因为共享网络会错误剥夺选举权。
