# 非欧空间拓扑

该模块连接的是两张有面积、有朝向的矩形接缝，不是两个方块坐标。任何独立移动实体的移动线段穿过接缝后，都会在另一张接缝的对应局部位置继续；位置、朝向与速度使用同一个空间变换。每一条启用的路径始终带有严格的逆路径。

配置文件为 `plugins/mik/non-euclidean-spaces.yml`。当前只接受 `version: 3`，旧格式不会被迁移或解释。修改后执行 `/mikspace reload`；配置采用全量校验，任一错误都会保留上一份正在运行的拓扑。

## 接缝区域

一张接缝由两个对角和一个穿越方向定义：

```yaml
surfaces:
  upper-loop:
    world: world
    area:
      corner-a: [-1.0, 72.0, -8.0]
      corner-b: [ 2.0, 75.0, -8.0]
    through: north
```

这里的平面宽 3 格、高 3 格，覆盖 `x=-1..2`、`y=72..75`，并位于 `z=-8`。`corner-a` 和 `corner-b` 是区域的两个对角，不是方块编号，也不是起点与落点。坐标差就是实际边长，因此不再另设含义不明确的 `size`。

- `area.corner-a`、`area.corner-b` 必须位于同一平面，并且是该矩形的两个对角。
- `through` 是实体可穿过接缝的方向，可写 `north`、`south`、`east`、`west`、`up`、`down` 或 `[x, y, z]`。
- `up` 决定接缝局部坐标中的上方，主要用于地面、天花板或倾斜平面。它必须与 `through` 垂直。普通墙面可省略，此时默认采用世界的上方；`through` 为 `up` 或 `down` 时默认以北为局部上方。
- 区域边界使用精确世界坐标。若墙洞从三个方块的左边界延伸到右边界，应写相差 `3.0` 的两个坐标，而不是按方块数量使用相差 `2` 的闭区间。

两个对角与 `through` 不共面、区域某一边长度为零、两个连接区域尺寸不同，都会令整次加载失败。

## 连接区域

```yaml
version: 3
enabled: true

surfaces:
  upper-loop:
    world: world
    area:
      corner-a: [-1.0, 72.0, -8.0]
      corner-b: [ 2.0, 75.0, -8.0]
    through: north
  lower-loop:
    world: world
    area:
      corner-a: [-1.0, 64.0, 8.0]
      corner-b: [ 2.0, 67.0, 8.0]
    through: north

links:
  infinite-stairwell:
    connect: [upper-loop, lower-loop]
    entrances: first
```

`links.*.connect` 必须引用两张不同、同世界、等宽等高的接缝。每张接缝必须且只能属于一个连接，避免同一位置出现不确定目的地。`entrances` 必须显式选择 `first` 或 `both`：

- `first`：启用 `connect[0]` 沿自身 `through` 穿到 `connect[1]` 的路径，并自动启用它的严格逆路径。逆路径是从第二张接缝沿其 `through` 的反方向返回第一张接缝。
- `both`：在 `first` 的基础上，再启用 `connect[1]` 沿自身 `through` 穿到 `connect[0]` 的路径及其严格逆路径。因此两张接缝的正面和背面都可进入，共有四条有向路径。

这里没有 `reversible` 开关：只要启用一条路径，其逆路径就必须存在。否则实体立即回头时无法回到原位置、原朝向和原速度，空间接缝也就不再连续。`entrances` 只决定启用一组还是两组互逆路径。连接也没有固定落点、缩放偏移、保留世界朝向、清空速度、权限分流等模式；这些模式都会破坏同一空间在不同方向、不同玩家眼中的一致性。

正向穿过 `upper-loop` 会从 `lower-loop` 的同一局部位置继续。反向越过 `lower-loop` 的另一面会得到严格的逆变换。实体在区域中的横向和纵向偏移、越过平面后的剩余步长、视角、速度及坠落距离都不会被重置。

水平接缝使用相同规则。两个区域都写 `through: down` 且 `entrances: first` 时，从第一张区域向下穿过会在第二张区域继续向下；从第二张区域下方再向上穿过，会沿严格逆路径回到第一张区域并继续向上。若使用 `entrances: both`，从第二张区域向下以及从第一张区域下方向上也会分别启用。水平区域的两个对角必须具有相同的 Y；可用 `up: north` 固定区域平面内的旋转方向。

`through` 之间是直接对应关系，不会因为第二张接缝是水平面而自动反向。例如第一面写 `through: west`、第二面写 `through: up`，从第一面向西穿过后就会向上出现；若要求“向西进入、向下出现”，第二面必须明确写 `through: down`。若还要保持南北方向，可令第一面使用 `up: up`、第二面使用 `up: west`。这时完整轴映射为 `west → down`、`up → west`、`north → north`，反向穿越是其严格逆变换。

## 建筑约束

服务端可以保证数学变换连续，但画面连续还取决于建筑：

- 两张接缝附近的走廊截面、材质、照明和可见轮廓应当吻合。
- 接缝背面应藏在墙体、转角或玩家无法直接同时观察两侧的位置。
- 两个区域应放在玩家发送视距以内，使客户端在穿越前已经持有两边区块。模块会为区域覆盖的服务端区块添加加载票，但不会用加载界面或普通传送掩盖过远的布局。
- 所有已加载的独立实体都能穿过接缝，包括玩家、生物、矿车、船、掉落物、经验球、箭矢和其他投射物、点燃的 TNT、下落方块及展示实体。龙等复合生物的身体分段随父实体一起处理，不会重复穿越。
- 玩家、生物和载具使用各自的移动事件即时检测；其余实体在每个服务器 tick 结束时，用“上一位置到当前位置”的完整线段检测，而不是只检查终点。因此快速箭矢即使一个 tick 内越过整个平面，也不会因终点已经位于另一侧而漏检。普通插件传送会重置轨迹基线，不会被误认为穿过接缝。
- 穿越移动的是原实体实例，不会重建服务端对象；物品堆、拾取延迟、经验值、投射物发射者与伤害数据、TNT 引信、下落方块数据及展示实体属性都会原样保留。
- 若实体正在乘坐其他实体，只由最外层根实体触发一次穿越；所有嵌套乘客会作为同一棵实体树移动，座位关系不会被拆开。

所有类别都只由最外层根实体触发一次穿越；正在骑乘的玩家或其他乘客不会独立重复触发。根实体统一使用 Paper 的乘客感知同世界重定位，使完整嵌套乘客树在同一次操作中到达出口并保持原有座位关系。随后模块对树中每个成员分别恢复空间变换后的视角、身体朝向、完整三维速度与原坠落距离，保证墙面和水平接缝互转时骑乘状态及动量都不会丢失。目标区块未准备好、目标超出世界边界、世界解析不一致或 `EntitySpaceTraverseEvent` 被取消时，本次越界会被拦下。正常穿越不发送文字、声音、粒子或延迟提示。

普通实体传送包会让其他玩家的客户端在旧坐标与新坐标之间插值。空间穿越完成后，模块会只为当前确实追踪该实体的远端观察者，在同一个协议 bundle 中删除旧模型、按出口状态完整重建整棵骑乘实体树，并在所有模型就绪后恢复乘客与拴绳关系。这个过程不修改服务端 tracker，也不调用玩家或实体的隐藏接口，因此不会改变皮肤、装备、Tab、隐身或其他插件维护的可见性状态；参与穿越的玩家不会收到针对自身模型的重建包。

穿越时会分别保留“出口平面交点”和“本 tick 的目标终点”，并在出口侧重新解析两者之间的连续碰撞。半砖、楼梯等非整方块碰撞形状不会因为目标终点已经位于其另一侧而被跳过；发生碰撞时只截断受阻的运动轴并清除该轴速度。

实体位置是脚底或载具锚点，碰撞箱却始终保持世界竖直。墙面出口会按碰撞箱半宽、向下的水平面出口会按碰撞箱完整高度，沿出口法线清出门体；这段位移属于穿过接缝本身，不会清除转换后的速度。超过该碰撞箱投影后仍未找到空位，才判定出口确实被方块堵塞。墙面出口若只是脚部与半砖或楼梯轻微重叠，还可以在根实体当前原版步高范围内纵向解出；水平出口不会被解回接缝错误的一侧。

接缝映射的原始点可以位于矩形任意边缘，但出口锚点会进一步限制到“整个实体都能放进门洞”的范围。水平面接缝映射到竖直门洞时，如果玩家位置对应到门洞顶部而导致头部超出区域，模块会沿门面自动下移；横向靠边时也会向内收进。入口交点与本 tick 终点使用同一调整量，因此只改变必要的落点，不改变视角、速度或剩余位移。

## 示例

首次启动后，以下完整配置会写入 `plugins/mik/examples/non-euclidean/`：

- `infinite-stairwell.yml`：一段楼梯首尾相接，可无限上行和下行。
- `endless-corridor.yml`：同一段直走廊循环。
- `impossible-corner.yml`：两个朝向不同的区域连接，视角与动量随空间转弯。
- `looping-fall.yml`：井底连接井顶，坠落速度和坠落距离持续保留。

这些文件都是独立的完整配置。使用时根据实际建筑修改世界名和两个区域的对角坐标，再复制为主配置；它们不是自动叠加到主配置中的 include 文件。

## 命令与外部调用

`/mikspace status`、`/mikspace list`、`/mikspace reload` 使用权限 `mik.command.space`。

模块通过 Bukkit `ServicesManager` 发布 `NonEuclideanSpaceService`。外部模块可读取不可变的 `SpaceNetwork`，或用 `register(SpaceLink)` 注册动态连接。`SpaceSurface.betweenCorners(...)` 与 YAML 使用相同的双对角区域模型；`SpaceLinkEntrances.FIRST` 和 `SpaceLinkEntrances.BOTH` 对应配置中的两种入口选择。注册句柄关闭后连接立即移除。所有动态连接与配置连接共用区域唯一性校验、区块预热和 `EntitySpaceTraverseEvent`。事件中的实体始终是独立移动实体或最外层根实体，监听器取消事件即可拦下整棵乘客树。

安装 Skript 后也可用带名称字段的 section 注册运行时连接；完整语法、所有权和卸载清理规则见 [MIK Skript API](skript.md#非欧空间)。
